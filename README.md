# Console Canvas

실제 웹 화면을 소스 없이 복제해 편집하고, 디자인 의도를 이미지와 주석으로 로컬 개발 에이전트에게 전달하는 Chromium 내장 앱입니다.

**0.46: 티켓을 먼저 만들고 그 안에서 편집합니다.** 화면·현재 편집·주석·시안의 확정 목표·구현/검토 기록을 같은 티켓 ID로 이어갑니다. 시안 제안·비교·선택은 기존 에이전트 대화에서 하며 앱에 AI 계정/API 키를 입력하지 않습니다.

## 사용 흐름

1. **＋ 새 티켓**을 누릅니다. 자동 제목과 고정 ID가 생기며 이름 입력 창 없이 시작합니다.
2. 웹사이트를 열어 로그인·메뉴/필터를 준비하고 화면을 가져옵니다. 빈 티켓이면 그 티켓에 연결합니다. 이미 편집 중인 티켓에서 새 화면을 가져오면 별도 티켓으로 분리해 기존 편집을 보존합니다. 샘플·앱 디자인 편집·파일 가져오기도 티켓 안에서 진행합니다.
3. 요소 이동·삭제·복사·정렬, 요소/좌표 주석과 공통 설명으로 의도를 남깁니다. 오른쪽은 현재 요청·주석이며 모든 작업은 자동 저장됩니다.
4. **작업 티켓**에서 해당 프로젝트의 저장 티켓 공개를 허용하고 앱 설정의 스킬/MCP를 연결합니다. 이후 에이전트에게 **‘캔버스 티켓 가져와’**, **‘CC-12 시안 3개 보여줘’**처럼 요청합니다. 닫힌 티켓도 조회할 수 있습니다.
5. 대화에서 선택한 시안 또는 현재 편집 결과를 **같은 티켓의 목표로 확정**합니다. 새 티켓은 생성하지 않습니다. 목표 자체가 바뀌면 새 티켓으로 분리합니다.
6. **‘CC-12 구현해’**라고 지시하면 에이전트가 실제 프로젝트를 반응형으로 수정하고 결과/검증을 기록합니다. 사람이 결과를 승인하면 완료합니다.

헤더의 ID를 눌러 복사할 수 있고 이름으로도 조회할 수 있습니다. 같은 이름이 여러 개면 에이전트가 ID 목록을 보여 선택받습니다. 프로젝트는 티켓 메뉴 → 원본 정보에서 설정합니다. 확정 목표의 프로젝트/이미지/요청은 이후 편집으로 바뀌지 않습니다. 조회·생성·시안 선택·목표 확정은 자동 구현 명령이 아닙니다.

통합 티켓 목록에서 준비 중 작업·검색·상태·이름 변경·휴지통/복구를 관리합니다. 새 티켓으로 복제하면 편집·주석만 독립 복사하고 확정 목표/진행 기록은 승계하지 않습니다. 패널 접기/너비·확대·중첩/다중 선택과 undo/redo를 유지합니다.

## 저장과 전달

IndexedDB v3는 0.45의 현재 문서와 확정 티켓을 보존해 티켓 중심으로 전환합니다. 이전 목표의 이미지·요청·기록을 유지하며, 전환한 작업 공간은 전환 당시 현재 상태일 수 있음을 표시합니다. 일반 웹 로그인·OS 서명·개인 스킬은 초기화하지 않습니다.

**편집 파일 저장**은 현재 티켓의 편집·주석·출처·목표·작업 기록을 담은 `console-canvas-ticket` v3 백업입니다. 0.45의 문서 v2 파일도 읽으며 충돌은 덮어쓰지 않습니다. **전달 이미지**는 화면 위 번호/하이라이트와 하단 요청 카드가 포함된 PNG 한 장입니다. MCP 없는 대화에 첨부할 수 있습니다.

## MCP와 스킬

앱 설정에서 스킬 설치·업데이트와 MCP 등록 명령을 제공합니다. 앱은 실행 중이어야 합니다. 티켓 목록에서 **‘이 프로젝트의 저장된 티켓을 에이전트에 공개’**한 범위만 조회합니다. 공유 철회와 휴지통은 목록·이름 후보·상세·이미지·구독에 반영됩니다.

| 용도 | 도구 |
| --- | --- |
| 최신 안내·진단 | `get_agent_guide`, `list_screens` |
| 티켓 생성·조회 | `create_ticket`, `list_tickets`, `get_ticket` |
| 현재 편집 대상·주석·보조 이력 | `get_screen`, `list_elements`, `list_comments`, `list_history` |
| 복제본 편집 | `apply_edits`, `undo`, `redo` |
| 이미지 맥락·전달 | `get_design_context`, `get_review_image` |
| 같은 티켓의 목표 확정·진행 | `confirm_ticket_goal`, `update_ticket` |

대상은 `ticket_ref`에 ID/표시 ID 또는 정확한 이름을 넣습니다. 편집에는 `expected_edit_revision`, 목표/상태에는 `expected_ticket_revision`, 구현/검토에는 `goal_id`를 구별하며 쓰기에는 고유 `operation_id`를 씁니다. 스킬이 화면과 주석·스크롤 상세를 읽으므로 긴 프롬프트를 반복할 필요가 없습니다. 원본 웹사이트와 저장소를 MCP가 자동 수정하지 않습니다.

## 개발·검증

Node.js22.12 이상·Python3·macOS를 사용합니다. 편집 UI는 React·TypeScript·shadcn, 엔진은 정제된 DOM/CSS를 스크립트 없는 iframe에서 렌더링합니다. Electron이 네이티브 경계이며 MCP 어댑터/브로커는 Python 표준 라이브러리로 동작합니다.

```sh
npm ci
npm run check
npm run test:desktop:offscreen
python3 scripts/build_desktop.py
python3 scripts/install_desktop.py --update
```

공통 UI·타입·포맷·저장/수집·패키지와 Electron/공식 SDK 통합을 구별해 검증합니다. offscreen을 실제 설치 앱 사용으로 표시하지 않습니다. macOS 빌드는 준비된 고정 Apple 개발 서명을 사용하며 ad-hoc으로 자동 전환하지 않습니다.
