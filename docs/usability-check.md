# 2026-10-24 직접 사용 점검

대상: 설치 앱 0.10.0을 복제한 별도 프로필의 QA 앱과, 같은 런타임을 제공하는 Chrome 테스트 세션. 사용자 프로필의 문서에는 테스트 편집을 적용하지 않았다. 원본은 가상 NORTH 콘솔이다.

마우스·키보드로 샘플 열기 → 실제 화면 가져오기 → 영역 선택 → Cmd+C/V → 이동 → 실행 취소/다시 실행 → 주석 작성 → 이름 있는 스냅샷 저장 → 이전/다음 복원 → 원본 비교 → 변경 전달을 사용했다. 네이티브 창 조작이 간헐적으로 끊기는 구간은 같은 편집기를 Chrome에서 재현해 조작 도구 문제와 앱 문제를 구분했다. 브라우저의 편집 파일 저장은 실제 다운로드 파일과 스냅샷 2개를 확인하고 스킬의 review 명령으로 해석했다.

## 발견과 반영

- 선택한 카드 영역과 버튼 안에서 숫자를 끌면 문구 하나만 선택되는 문제: 선택된 상위 요소를 유지해 묶음 전체를 이동한다. Alt는 세부 선택을 유지한다. 수정 후 동일한 실제 드래그로 두 요소 선택이 유지되는 것을 확인했다.
- Cmd+컨테이너 배경 클릭이 영역 선택 대기 상태로 끝나는 문제: 드래그하지 않으면 해당 컨테이너의 추가 선택으로 처리한다.
- 다중 선택의 오른쪽 패널: 정렬·이동을 주석보다 앞에 배치하고, 삭제 버튼에 선택 개수를 표시하며 전체 선택 영역의 크기를 보여 준다.
- 삭제한 복사본의 전달: 기존 요소의 삭제와 구분하고 삭제된 복사본에 연결된 주석을 명시한다. 복사본 참조 원본 정보는 에이전트용 지시문과 compact 주석에도 유지한다. 수정 후 실제 복사·주석·삭제·전달 흐름을 다시 사용해 확인했다.

0.10.1 회귀 검사에는 위 상황 5개를 추가했다. Python 38개, Node 18개, Chromium 147개, 공식 SDK 18개와 실제 포인터의 iframe 경계 이동·Electron 종료/재실행 검증을 통과했다.

설치된 앱을 0.10.1로 교체하고 재실행했다. MCP 공식 SDK로 설치 번들의 버전·11개 도구·가이드·활성 문서와 스냅샷 조회를 확인했다. 앱이 자동 동기화한 스킬 4개 파일도 번들과 일치했다. 업데이트 전후 종료된 프로필의 사본을 읽기 전용으로 조사해 문서 7개와 스냅샷 13개의 원본·편집·주석·전체 메모·타임라인 해시가 모두 같은 것을 확인했다. 마지막으로 설치 앱을 다시 열어 편집기 화면과 패널 너비가 유지되는 것을 확인했다.

## 0.11.0 후속 개선과 버튼 점검

두 후속 후보를 구현했다. 캔버스 도구막대의 **문서**에서 저장된 화면 전체를 이름·주소로 검색하고 전환한다. 현재 작업과 가져온 시각·저장 시각을 표시해 같은 사이트를 여러 번 가져온 문서를 구분한다. 다중 선택은 공통 점선 외곽선과 **N개 이동** 손잡이로 이동하며 한 번에 실행 취소한다. 주석 모드와 내보낸 HTML·이미지에서는 손잡이를 숨긴다.

## 0.12.0 이름·휴지통 직접 점검

별도 프로필의 QA 앱과 같은 편집기를 제공하는 Chrome 세션에서 가상 NORTH만 사용했다. 네이티브 창 조작이 간헐적으로 끊겨 Chrome의 실제 버튼·입력·키보드로 이어서 확인했다. 문서 이름 변경→현재 문서를 휴지통으로 이동→복구→다시 열기, 고객 등록 버튼을 키보드로 이동→스냅샷 저장→이름 변경→현재 버전 삭제→복구를 사용했다. 스냅샷 복구만으로 현재 화면을 바꾸지 않았고, 문서 ID로 다시 연 뒤에도 사용자 지정 문서명·변경 1개·스냅샷 휴지통이 유지됐다. 문서 휴지통과 재열기 후 스냅샷 휴지통 화면을 로컬 증거로 저장했다.

0.12.0의 250개 검사(Python 39·Node 18·Chromium 175·공식 SDK 18)와 별도 Electron의 정상 종료/재실행을 통과했다. 네이티브 검사에는 문서/버전 이름과 문서/스냅샷 휴지통의 보존도 포함된다. 설치 앱을 갱신하고 실제 문서 목록과 스냅샷 패널의 이름 변경·휴지통 버튼을 확인했다. 설치 번들의 실제 MCP 버전·11개 도구·현재 화면/스냅샷 조회와 스킬 4개 파일의 동기화가 일치했다. 사용자 문서에는 이름 변경·삭제 같은 테스트를 하지 않았다. 종료 프로필 사본을 대조해 문서 7개·스냅샷 13개의 캡처·이름/휴지통 메타데이터·편집·주석·메모·전체 타임라인 해시가 모두 같은 것을 확인했다.

최종 시각 점검에서 휴지통 스냅샷 카드 전체가 비활성 버튼의 투명도를 상속해 흐리게 보이는 점을 보정했다. 버전 적용은 계속 비활성화하되 제목·날짜·미리보기는 선명하게 유지한다. 전체 250개 검사와 빌드를 다시 통과하고 최종 설치·재실행 및 설치 CSS/스킬 파일 일치·실제 MCP 연결을 확인했다.


## 0.13.0 메뉴와 버튼 배치 개선

문서명 메뉴에 문서 전환·이름 변경·편집 파일 열기/저장·원본 정보·휴지통을 모았다. 레이어 패널은 검색과 요소 목록에 집중한다. 도구막대는 실행 취소/다시 실행, 선택/주석 모드, 복사/붙여넣기/삭제, 확대 순서다. 상위 요소 선택은 오른쪽 경로 옆으로 옮겼다. 속성은 위치·정렬을 우선하고 주석은 요약과 편집 링크를 제공한다. 입력은 주석 탭 또는 요소 옆 팝업에서 한다.

스냅샷 관리 버튼은 항목의 ⋯로 모으고, 휴지통에는 복구 도구만 둔다. 혼동을 주던 ×는 제거하고 패널 접기 버튼 하나를 사용한다. 전역 스냅샷 버튼은 목록을 열며 패널을 접으면 활성 표시도 해제된다. 삭제 알림에 되돌리기를 추가했고, 문서는 복구/복구하고 열기, 스냅샷은 복구/복구하고 적용을 구분한다. 저장 파일은 문서 메뉴로 옮기고 전달 화면은 요청문과 ZIP에 집중한다.

가상 NORTH를 격리 Chrome 포트 8864에서 직접 사용했다. 문서명 메뉴에서 이름 변경→레이어 검색→버튼 이동→주석 작성→Esc→시안 저장→⋯에서 삭제→되돌리기→다시 삭제→휴지통→복구하고 적용, 문서 삭제→복구하고 열기→다시 삭제→즉시 되돌리기를 확인했다. 1000×720 창에서 패널을 접어도 문서 메뉴가 열리는 것을 확인하고 화면 크기 설정은 원복했다. 다운로드 관찰 도구가 시간 초과로 재연결됐지만, 실제 다운로드된 가상 문서의 편집 파일을 찾아 이름·스냅샷 3개·주석 1개를 확인했다. 사용자 데이터는 테스트에 사용하지 않았다.

직접 사용 중 문서를 닫아도 열린 스냅샷 패널의 저장·탐색 도구가 남는 문제를 발견해, 문서 없음 안내·도구 숨김·개수 초기화를 반영했다. 17개 새 검사를 포함한 전체 267개 검사와 공식 Electron 배포 빌드를 통과했다. 설치 앱 0.13.0을 재실행해 문서명 메뉴·선택/주석·간결한 버전 목록을 실제 화면으로 확인했다. 공식 SDK의 설치 번들 버전·11개 도구·현재 문서/스냅샷 조회와 자동 갱신한 스킬 4개 파일의 일치도 확인했다. 업데이트 전후 종료 프로필 사본의 캡처·문서 이름/휴지통 메타데이터·편집·주석·설명·전체 타임라인 해시가 문서 7개·스냅샷 13개에서 모두 같다.


## 0.13.1 접힌 패널의 세로 바

좌우 패널을 접으면 각 가장자리에 36px 세로 바를 남긴다. 맨 위 44px 영역에 펼치기 화살표가 있고, 레이어/속성 이름을 세로로 표시한다. 펼친 상태의 접기 버튼은 각 패널 상단에 유지한다. 도구막대의 펼치기 버튼은 제거했다. 기존 패널 너비·접기 상태·주석 초안 보존과 스냅샷/주석에서 오른쪽 패널 자동 열기를 유지한다. 접힌 바 너비를 제외한 공간을 캔버스에 돌려주며, 패널 크기 조절의 최대 너비 계산에도 반영한다.

267개 전체 검사를 통과했다. 패널 검사 23개는 세로 바가 실제 가장자리에 있고 캔버스 전체 높이를 차지하는지, 펼치기 버튼이 맨 위에 있는지, 캔버스가 바를 제외한 너비를 얻는지, 키보드 포커스와 재실행 후 너비/접기 상태가 유지되는지 확인한다.

설치 앱을 0.13.1로 교체해 실제 패널 상단 버튼으로 좌우를 접고, 바 맨 위 화살표로 다시 펼쳤다. 기존 250px/310px 너비가 복원됐다. 다시 접어 정상 종료·재실행한 뒤 두 세로 바가 유지되는 것을 확인했다. 업데이트 전후 종료 프로필 사본의 문서 7개·스냅샷 13개 원본·이름/휴지통·편집·주석·설명·전체 타임라인 해시가 동일했다. 설치 스킬 파일 일치와 공식 SDK의 실제 0.13.1 앱 연결·11개 도구·활성 화면/스냅샷 조회도 확인했다.

## 0.14.0 직접 사용

가상 NORTH 브라우저 샘플에서 고객 등록 버튼 클릭, 위 주석 아이콘 클릭, 모달 입력과 저장, 번호 배지 생성, 이름 모달로 A 시안 저장을 확인했다. 설치 앱도 정상 종료·업데이트 후 다시 열고 중앙 스냅샷 드롭다운과 오른쪽 기본 변경 이력을 확인했다. 패널 화살표의 방향과 디자인이 펼침/접힘 상태에서 같은 체계로 유지된다. 선택 없는 상태에 editor-only 주석 아이콘이 노출되는 문제는 CSS important 우선순위를 바로잡아 수정했다.

추가 네이티브 QA 도중 Mac 잠금으로 조작이 막혔고 사용자가 현재 해제할 수 없다고 답했다. 설치 앱을 사용해 새 분기를 만들고 PNG 저장 대화상자까지 마우스로 수행하는 추가 검증은 미완료다. 해당 동작은 별도 프로필의 자동 Chromium/Electron/MCP 검사로 검증했으며 실제 사용자 문서에는 테스트 작업을 만들지 않았다.

## 0.15.0 통합 이력·가로 Git 그래프

오른쪽 속성/주석 탭을 제거하고 속성 전후 값·주석 내용·이동·삭제·복사를 한 타임라인에 모았다. 위치/정렬 입력은 요소 선택 후 도구 모음의 **요소 편집** 모달에서 수행한다. 패널 상단 접기 버튼과 가장자리 펼치기 바는 유지한다.

**스냅샷 목록 · 선택한 이름**은 저장 직후 열리는 가로 Git 그래프다. 선택은 이름과 하단 미리보기만 바꾸고 **이 버전으로 이동**으로 적용한다. 현재 버전과 미리보기는 표시를 구분한다. A→B→C와 A→D는 실제 부모로 연결한다.

이번 최종 검증 시 Mac이 잠겨 사용자가 가능한 자동 검사를 요청했다. 새 설치 앱을 마우스로 직접 사용했다고 보고하지 않는다. 대신 별도 가상 데이터에서 버튼/모달/그래프 이벤트·저장·재열기를 자동 실행하고 실제 Chromium 렌더링 이미지를 검토했다. 이 과정에서 기존 `.snapshot-card` 규칙이 노드의 absolute 위치를 덮어써 계단처럼 보이던 문제를 발견해 수정했다. 데이터의 lane 값만 보던 검사에 실제 카드 좌표 정렬 검사도 추가했다. 상세 통과 결과와 잠금 때문에 대체한 캡처는 [검증 기록](verification.md)에 구분했다.

설치 앱 0.15.0 실행과 스킬 4개 파일 자동 동기화를 확인했다. 설치 전후 사용자 자료는 7개 문서·13개 전체 스냅샷의 모든 보존 지문이 일치한다. 설치 런타임을 프로필 사본에서 열면 기존 364개 요소·3개 활성 스냅샷과 새 이력/목록 UI가 로드된다. 실제 설치 창의 클릭과 활성 화면 MCP 조회는 잠금 상태 때문에 남겨 두었다.

## 0.16 실제 설치 앱 사용과 0.16.1 보정 (2026-10-25)

사용자 문서를 그대로 두고 별도 프로필의 동일 설치 앱에서 X 숫자 입력·주석/번호 재편집/Esc·A→B→C/A→D/미래 C·좌우 세로 바·PNG 실제 파일 저장을 직접 사용했다. 긴 이력과 문서 카드 높이 문제를 발견해 0.16.1로 보정하고 실제 렌더 경계 검사를 추가했다. CUA 한글 키 입력의 제한과 마지막 재잠금 뒤 미완료를 [0.16 실행 결과](release-0.16-verification.md)에 구분했다.

## 0.16.1 잠금 상태의 브라우저 직접 사용 (2026-10-25)

Mac 잠금은 네이티브 창의 조회·입력을 막지만, CUA 인앱 브라우저의 웹 편집기 조작은 가능했다. 설치 앱이 루프백으로 제공하는 실제 0.16.1 런타임을 별도 브라우저 저장소에서 열고 가상 NORTH 문서만 사용했다. 자동 DOM 이벤트 검사와 달리 CUA의 실제 클릭·드래그·키 입력으로 아래 흐름을 수행했다. Electron 창·네이티브 저장 대화상자·macOS IME 검증으로 확대하지 않는다.

- 레이어 검색, 숫자 위치 입력/Tab 확정, 컴포넌트 포인터 이동, 복사/붙여넣기·삭제·실행 취소/다시 실행을 사용했다. 복사 시 버튼·아이콘·텍스트의 3개 요소와 주석이 유지됐다.
- 431자 한글 주석을 작성하고 Esc로 닫은 뒤 캔버스 번호 배지에서 다시 열었다. 긴 이력 본문은 카드 안에 들어가고 다음 항목과 겹치지 않았다. 속성 전후 값·주석·삭제·에이전트 이동은 같은 이력 목록에 표시됐다.
- 이름 있는 A/B/C 저장 직후 그래프 열림, A 선택 이름/미리보기와 C 작업 기준의 분리, 실제 A 적용 후 D 저장, 미래 C·병렬 D 이동을 확인했다. 실제 부모 ID와 화면 좌표 모두 A→B→C 및 A→D를 나타냈다. 임의의 A/C 비교를 닫아도 편집 위치·revision·활성 버전이 바뀌지 않았다.
- B 이름 변경→휴지통→복구에서 자식 C가 유지되고 D 작업 기준이 바뀌지 않았다. 문서 이름 변경·빈 검색 결과·휴지통·복구만 하기·다시 열기를 사용했다. 긴 문서 카드의 날짜는 카드 경계 안에 있고 이름 변경 후 항목 메뉴로 포커스가 돌아왔다.
- QA 화면만 MCP에 연결해 공식 SDK 조회와 이동을 실행했다. 에이전트 이동이 같은 UI 이력에 나타나고 UI 실행 취소로 되돌아갔다. 문서 휴지통에서는 화면이 목록에서 사라지고 복구만으로 다시 공개되지 않았다.
- 전달 이미지 복사 성공 뒤 클립보드의 실제 `image/png` 바이트를 파일로 저장해 열었다. 화면 위 번호 하이라이트·하단 카드·삭제 대상 참고 영역·추가 설명을 확인했다.
- 패널 경계 드래그/방향키로 너비 288/300px을 설정하고 양쪽을 접었다. 저장된 문서 ID로 화면을 다시 열어 접힘·너비·추가 설명·요소 위치·주석 2개·전체 스냅샷 5개·이력이 유지됨을 확인했다. 재연결한 MCP 결과도 요소·주석 요약·전체 스냅샷·이력 수가 동일했다. 화면 세션 ID/revision의 초기화와 실행 취소 수명은 영구 문서 저장과 구분했다.

### 새로 발견한 개선점

1. **전달 모달의 주요 버튼이 처음에는 보이지 않는다.** 1280×720에서 모달 하단은 684px인데 저장 버튼은 788~817px에 놓였다. 내부 미리보기와 모달의 스크롤이 겹친다. 복사·저장은 고정 하단에 유지하는 편이 낫다.
2. **스냅샷 이름 변경 후 그래프가 닫힌다.** 이름 변경 완료 뒤 같은 그래프·선택·스크롤 위치로 돌아가야 연속 관리가 쉽다.
3. **전달 PNG의 긴 문서 제목이 가로로 압축된다.** 제목을 정해진 너비로 축소하는 대신 줄바꿈이나 말줄임을 적용해야 읽기 쉽다.
4. **삭제한 복사본의 참고 이미지가 화면 오른쪽에서 잘린다.** 삭제 전에는 캡처 경계 밖으로 늘어났던 버튼이 삭제 후 크기를 기준으로 렌더링되는 브라우저 출력에서 일부 잘렸다. 삭제 전/후 장면의 크기를 따로 처리하는 검토가 필요하다. 네이티브 PNG에서의 재현은 별도다.

제품 코드는 이번 점검에서 변경하지 않았다. 19개 직접 사용 확인 항목·렌더 경계·MCP 전후 조회와 가상 문서 스크린샷은 Git 제외 `local/manual-0.16.1-locked/`에 남겼다. QA MCP 연결은 해제했으며 실제 사용자 문서·스냅샷에는 테스트 작업을 적용하지 않았다.
