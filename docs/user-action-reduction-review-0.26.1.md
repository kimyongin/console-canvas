# Console Canvas 시나리오별 액션 절감과 UX 보호 검토

기준 버전0.26.1 · 검토일2026-10-30 · 설계 검토안이며 구현 또는 실측 완료가 아니다.

후속 구현·검증은 [0.27.0 구현 기록](action-ux-0.27.md)을 따른다. 기준/설계 기록을 소급하여 실측 결과로 바꾸지 않는다.

121개 목표를 각각 검토했다. 액션 수를 줄이는 것이 사용자가 의도한 결과를 정확히 얻는 것보다 우선하지 않는다. 기본 동선을 짧게 바꿀 수 있는 경우, 기존 기본 동선에 선택적 단축을 더할 경우, 클릭 수를 유지하고 탐색/재시도를 줄일 경우, 현재 동선을 유지할 경우를 나눴다.

기존 [액션 집계](user-action-audit-0.26.1.md)의 목표 ID·시작 상태·현재 기능 동선 수치를 사용한다. 링크 이동·메뉴 펼침·하위 메뉴·초점·스크롤·창 닫기·복귀·OS/외부 조작을 전부 포함해야 한다. 이 문서의 기본 횟수도 시작 조건이 갖춰진 **부분합**이며, 실제 전체는 진입·탐색 N과 외부/OS 비용을 더한다. 미측정 N은0으로 취급하지 않는다.

단축 경로의 명령1회는 사용자가 이미 알고 있는 지정 키보드 명령1회를 뜻한다. 메뉴를 열어 명령을 찾는 경우에는 메뉴/하위 메뉴/항목 클릭을 모두 별도로 더하므로1회 경로로 계산하지 않는다. 현재 지정된 키 조합이 있다는 뜻은 아니며 구현 전에 기존 입력/OS 단축키와 충돌을 검토해야 한다.

## 전체 작업 흐름 재평가

아래 부분합에는 기존 집계의 기준 외부 대화/OS 저장을 포함한다. 실제 전체는 현재에 N, 개선에 N′를 각각 더한다. N′가 줄었다고 가정하지 않으며 메뉴 접근·옵션 켜기·발견·오류 복구가 늘면 모두 추가한다. 실제로 하지 않은 편집·과금 호출·설치의 성공을 주장하지 않는다.

## 모든 시나리오의 개선안과 보호 조건

각 행은 같은 목표와 시작 조건을 유지한다. 현재 숫자는 앱 안의 기능 동선이며 OS/외부 조작이 있으면 현재 수치에 합쳐 읽어야 한다. 예를 들어 G07의 현재2회는 OS 확인을 포함하면3회 이상이다. 유지 판정도 검토를 생략했다는 뜻이 아니라 액션을 줄일 안전한 근거가 없다는 결론이다. 단축키의 발견을 위해 메뉴를 열었다면 그 동작도 실제 횟수에 포함한다.

## 반복 주석과 판정의 구현 보호 계약

- 새 주석 대기열은 사용자가 명시적으로 선택한 ID만 고정한다. 선택에 없던 하위 요소를 자동 추가하지 않는다. 빈 대기열 항목은 실제 주석이나 전달 요청으로 미리 저장하지 않고, 입력한 항목만 기존 자동 저장/이력/undo 계약을 따른다.
- 문서/버전이 바뀌면 이전 대상에 늦은 입력을 보내지 않는다. 닫기/전환은 입력한 초안을 보존하며 기존 단건 주석 아이콘은 계속 같은 방식으로 동작한다.
- 판정 후 다음 이동은 해당 요청의 저장 성공과 미리보기/하이라이트 준비를 확인한 뒤만 가능하다. 저장 오류·이중 클릭·키 반복이 다음 요청을 자동 승인하지 않게 요청 ID와 호출을 묶는다. 마지막 요청 뒤 자동 이미지 전송/창 닫기는 하지 않는다.
- 판정 되돌리기는 검토 안의 작업이며 캔버스 undo와 섞지 않는다. 빠른 경로에서도 반영 확인/추가 수정 필요/미검토의 의미와 이전 판정 복구를 유지한다.

## 반복 사용과 옵션 설정 비용

- 선택적 명령을 배우기 위해 메뉴/설명을 열었다면 첫 사용에는 그 비용을 더한다. 단축키를 알고 시작하는 경로를 처음 쓰는 사용자의 기본 횟수로 보고하지 않는다.
- 자동 다음 이동은 최초 선택1회가 필요하므로10건에서11회다. 옵션이 켜져 있었다는 시작 조건을 확인한 반복 작업에서만10회라고 기록할 수 있다.
- 자동 다운로드 옵션을 켜는 데 최소1회가 든다면 첫 업데이트는1+3=4회 이상이다. 이후에만3회가 가능하며 옵션을 찾기 위한 경유도 추가한다.
- 주석 대기열은 대상 선택을 생략한 것이 아니다. 개별 대상10회 또는 정확한 영역1회와 실제 탐색 N을 모두 포함한다. 한꺼번에 대상 찾기/기억하기가 더 어려우면 기존 단건4회 경로를 계속 쓸 수 있어야 한다.
- 같은 시작/완료 조건에서 처음1회와 반복10회를 따로 비교한다. 현재 사용 빈도 데이터는 없으므로 총 시간/전체 절감률을 확정하지 않는다.

## 권장 진행 순서

1. **신뢰 문제부터 정리:** 기존 편집/이력0 불일치, 복구 완료와 원본 경고 구분, 서버/에이전트 연결 상태. 올바른 상태를 이해하지 못하면 단축도 오조작을 늘린다.
2. **불필요한 왕복 제거:** 자산 복구 누적 A11, 오류 백업 L01, 구현 결과 연결 I02. 데이터/목표를 보존하며 줄일 수 있는 반복 경유다.
3. **판정과 반복 주석:** I03/I04의 기본 직접 판정부터 검증하고 선택적 다음 이동을 별도로 평가. D06의 명시적 선택 대기열도 단건 경로와 비교한다.
4. **일상 탐색과 요청 작성:** 문서 직접 목록 G01/G02/G05, 원본 직접 비교 A08/A09, MCP 요청 작성 J01/J02. 관리 경로/기존 초점 동작을 동시에 회귀 확인한다.
5. **명시적 실행/설정 단축:** 가져오기 실행 메뉴 A03/A04, 설정 카드 K01/K03·업데이트 자동 확인 K05/K06. 원본 수집/네이티브/설치 경계는 별도 통합 확인한다.
6. **숙련자 선택 경로:** 주소·좌표·검색·복제·파일·이미지 명령과 집중 보기. 실제 사용 빈도와 학습 비용을 확인하고 기본 UI를 복잡하게 만들지 않을 때만 추가한다.

공통 편집기 UI는 웹 사용 검증과 영향받은 검사로 확인한다. 수집/IPC·네이티브 파일·업데이트·스킬·로컬 서버 경계에 영향이 있으면 해당 Electron 통합 검사를 추가한다. MCP 계약을 바꾸면 공식 SDK로 확인한다. 사용자 실제 문서에는 테스트 편집을 하지 않는다.
