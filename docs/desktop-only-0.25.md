이전 Chrome 제품화 #28/#33/#35는 미검증 조건을 완료로 바꾸지 않고 not planned로 종료한다. #69의 과거 확장 실패·영상 기록은 남기고 내장 잔여는 #73으로 이관한다. 모든 신규 화면95% 목표 #68도 내장 앱 범위로 계속 추적한다. 과거 버전의 양 경로 시험 결과를 현재 공식 지원으로 읽지 않는다.

## 단일 지원 경로와 자료 보존

- 내장 앱의 **웹사이트 → 이 화면 가져오기 → 편집/주석 → 스냅샷 → 전달 PNG**와 로컬 Python MCP19개 도구는 유지한다. AI 직접 호출과 외부 에이전트도 같은 편집기/문서를 사용한다.
- Chrome 전용 background·manifest·수집/외부 자산·WebMCP 소스를 `archive/chrome-extension/`으로 옮기고 빌드 의존성에서 제외했다. 보관 실험은 당시 트리 기준이며 마지막 완전한 구성은 Git 태그 v0.24.3이다.
- 새 배포는 macOS arm64 DMG/앱 ZIP, `console-canvas-runtime.zip`, `console-canvas-skill.zip`이다. Chrome ZIP과 설치용 manifest/background/WebMCP를 새 runtime/skill에 포함하지 않는다. 빌드는 이전 생성 ZIP/descriptor를 정리하며 과거 GitHub 릴리스는 보존한다.
- helper `prepare`는 체크섬을 검증한 공통 runtime을 추출해 `runtime_directory`를 반환한다. 확장 설치 폴더가 아니다. 스킬의 stdio MCP도 같은 runtime ZIP을 사용한다.
- 앱 시작 시 관리 스킬4개 파일을 동기화한다. 기존 관리 자산 `assets/console-canvas-extension.zip`은 백업 후 정리하고 새 runtime 자산을 사용한다. 개인 추가 파일은 유지하며 교체 오류는 롤백한다. 패키지 제외·체크섬·스킬 이전은 회귀 검사로 확인한다.
- **기존 설치 확장과 문서는 자동 삭제하지 않는다.** 기존 확장에서 각 문서를 **문서 메뉴 → 편집 파일 저장**, 앱에서 **편집 파일 열기**로 이동한다. 파일에 편집·주석·전체 분기·휴지통이 포함된다. 원본 로그인/문서 자동 동기화는 제공하지 않는다. 필요한 문서를 모두 내보내기 전에 확장을 제거하지 않는다.

## 가져오기 상태 UX와 MCP

캔버스 제목 줄의 **가져오기 · 확인 필요 N건**에서 수집 경고·이미지/배경/프레임의 partial/unavailable coverage·프레임 이미지화·외부 자산·구조 변환을 한곳에서 읽는다. 대상이 있는 항목은 **화면에서 확인**으로 해당 요소를 선택·확대한다. 요소 편집 모달 안에 숨겨져 있던 참고 경고를 옮겼다. 직접 사용 중 발견한 경고 종류의 중복 표시도 정리했다.

제한이 없으면 **가져오기 · 화면 비교 전**이다. 원본과의 실제 픽셀 비교 없이95%/100%·완벽 복제 배지를 만들지 않는다. 범위는 문서/뷰포트 크기로 명시하며 원본에 아직 렌더링되지 않은 다른 상태는 포함하지 않는다. **원본 사이트 확인**은 현재 원본 사이트이며 캡처 시점과 달라질 수 있다.

`get_screen.screen.capture_status`는 `visual_comparison: not_measured`, 전체 `issue_count`, 최대200개 `issues`, 잘림 여부 `issues_truncated`를 제공한다. UI와 같은 불변 평가이며 원본 캡처·편집·주석·스냅샷을 수정하지 않는다. 경고0건과 시각 일치 검증을 혼동하지 않는다. 유효하지 않은 오래된 경고 값은 UI 전체를 깨뜨리지 않고 정보 형식 경고로 표시한다.

별도 로컬 문서에서 버튼 열기·닫기·제한 상세·대상 이동/확대·경고 없음·MCP not_measured·원본 무변경을 브라우저로 직접 확인했다. 사용자 문서에는 시험 편집을 적용하지 않는다.

## 내장 수집의 공통 수정

1. **대형 DOM**: Element Plus의 DOM은19,104개였고 display:none 하위/생략 태그를 제외한 순회는6,224개였다. 기존15,000개 한도를 늘리지 않고 렌더링되지 않는 하위만 생략한다. 숨겨진 루트의 식별자는 유지하고 visibility:hidden의 visible 자손은 보존한다. 보이지 않는 다른 UI 상태까지 복제한 것은 아니다.
2. **동적 배치 일관성**: 촬영 전과 직렬화 후의 배치·그림·직접 문구를 제한된 읽기로 비교해 최대2회 재수집한다. 끝까지 바뀌면 dynamic 경고, 감지 한도에 도달하면 범위 제한을 남긴다. 광고용 비시각 속성 갱신만으로 배치 변경을 판정하지 않는다. 원본 DOM/스타일·재생 상태를 바꾸거나 멈추지 않는다. 감지 false는 픽셀 일치/영상 동기화 보장이 아니다.
3. **원래 뷰포트 폭**: 커스텀 스크롤바가 있는 Element Plus에서 큰 문서 사진의 콘텐츠 폭과 캡처 DOM의 폭이6px 달라 줄바꿈/누적 위치가 어긋났다. 스크롤바 공간이 있으면 실제 뷰포트를 유지한 타일을 촬영하고 원래 스크롤을 복원한다. CSS를 바꿔 스크롤바를 숨기지 않는다.
4. **문단 안 custom element**: 일반 div로 바꾸던 custom 아이콘을 스타일을 유지한 span으로 옮겨 HTML 파서가 문단/링크를 분리하지 않게 했다. 원본 태그/selector는 캡처 메타데이터에 유지한다.
5. **내부 스크롤과 이동 기준**: 고정 컨테이너를 재구성한 뒤 캡처 스크롤을 복원하고 실제 배치에서 자식의 이동 기준을 잡는다. 새 회귀에서 자식 이동이 튀는 문제를 발견·수정했다. 코드 재구성은 기본 배치/스크롤이 확정된 뒤 기존 이동·복사·주석/선택을 복원하고 완성된 UI를 갱신한다.

사이트 이름·selector·좌표를 조건으로 한 수정을 추가하지 않는다. 실제 DOM의 숨겨진2만 자손/visible 자손/custom glyph, native6px 스크롤바/원본 무변경/자식 이동·코드 재구성/원위치 복귀를 가상 페이지로 검증한다.

## 실제 페이지 결과와 남은 한계

기존 지표인 RGB 최대 채널 차이16/255 이하 비율이다. RGB8·완전 동일 지표와 실패 기록도 보존한다. 마스크·허용오차 확대는 없다. 각 실행 안에서 같은 뷰포트·기록한 문서 구간을 비교하며 서로 다른 날/상태의 원본을 같은 참조라고 주장하지 않는다.

| 페이지 | 초기 화면 / 문서 구간 | 범위·판정 |
| --- | --- | --- |
| Element Plus Table | 반복1·2 모두 **99.96 / 98.71%** | 1440×1000 / 높이12,000px, 통과 |
| 국립중앙박물관 | 반복1·2 모두 **99.99 / 99.94%** | 1440×1000 / 높이5,395px, 통과 |
| IKEA | 반복1 **88.79 / 92.77%**, 반복2 **88.75 / 92.49%** | 1440×1000 / 높이12,000px, 미달 |

Element Plus의 원본 높이는27,204px이며12,000px만 비교했다. 전체를 촬영하지 못한 capture_limit 경고도 남긴다. 중간 구현의93.44%, custom 마크업 보완 후93.40% 기록을 보존한다. 원본 상태가 다른 새 수집이므로 이를 동일 원본의 단일 전후 값으로 포장하지 않는다. 최종 같은 저장 원본으로 재렌더링한 Element Plus/박물관 결과도 확인한다.

박물관은 이전93.04%와 달리 배치 변경을 감지해1회 재수집한 뒤 통과했다. 최초0.25 실행99.98%와 반복 두 번99.94%를 구별한다. 앞으로 모든 순환 배너를 완벽 재현한다는 뜻이 아니다.

IKEA는 두 번 모두 sourceChangedDuringCapture와 dynamic 경고가 남았다. 재생 영상의 촬영·직렬화·타일 시점 차이가 남아 정지 복제본이 여러 시점과 동시에 일치하지 않는다. 영상 전체를 평탄화해 별도 HTML 오버레이를 중복 표시하거나 원본을 멈추는 방식은 채택하지 않았다. **#73과 #68은 미완료로 유지한다.** 이번 릴리스가 모든 페이지95%를 달성한 버전은 아니다.

## 증빙·검사·배포

실제 사이트 원본/복제/차이·캡처 JSON·좌표·지표·중간 실패는 ignored `local/desktop-only-025/`에만 보관한다. `element-probe.json`, `native/`, `element-inline/`, `element-viewport/`, `repeat1/`, `repeat2/`, `final-replay/`가 근거다. 실제 사이트 자료·프로필·사용자 편집 파일을 공개 저장소에 올리지 않는다.

기존 내장10개 **저장 원본**은 최종 엔진에서도 초기/기록 문서 구간 모두95% 이상이다(`old-regression-final/`). 새로 수집한 페이지 시험과 구별한다. 전체 공통·공식 SDK/정확한 패키지·설치 보존·게시 파일 digest 확인은 아래에 최종 결과를 기록한다.

최종 공통 검사 `final-check.log`는 타입·포맷·runtime/스킬 패키징, Python45·Node41·Chromium508개와 독립 HTML/실제 포인터 검사를 통과했다. source-audit.json은9개 관련 제품 모듈의 기존/신규 시험 도메인 문자열0건을 기록한다. 보관 코드는 제품 의존성에서 제외했다. 스킬 quick_validate·Chrome 제외/해시 무결성·공식 Electron SHA-256·ad-hoc 서명·DMG 체크섬을 확인했다. 정확한 배포 번들의 SDK·설치 결과는 뒤에 기록한다.

패키지 SDK 단계에서 tool-contract.json이 과거 확장 import 그래프에 간접 의존해 빠지는 문제를 발견했다. 내장/Python 정적 의존성을 명시하고 저장소 밖으로 추출한 runtime의 MCP 시작 회귀를 추가했다. 이 실패는 설치 전에 발견했으며 설치 앱 성공으로 처리하지 않았다.

정확한 최종 앱 번들의 격리 프로필에서 공식 SDK22+17개·정상 종료/재실행·sandbox·원본 무변경·편집/주석/분기/휴지통 보존을 통과했다(`packaged-sdk-final.log`). source 토큰/개인 프로필을 공개하지 않는다.

실제 사용자 앱은0.24.3→0.25.0으로 정상 종료·전체 앱/userData/브리지/스킬/확장 백업 후 교체·재실행했다. 전후 편집 파일의 전체 대조는 생성/갱신 시각만 다르며364요소·기존 편집/주석·스냅샷3개·전체 분기/휴지통을 보존했다. 설치 스킬4개 관리 파일 자동 갱신, 이전 extension runtime 자산의 백업/정리, 앱/스킬 ZIP 및 runtime115개 파일의 바이트 일치를 확인했다. 설치 스킬 경유 실제 공식 SDK는guide/server0.25.0과 get_screen의capture_status=not_measured를 읽기 전용으로 확인했다. 실제 설치 앱에서 새 가져오기 정보 모달도 열고 확인했다. 증빙은 ignored `local/deployment-025-backup/`다.

설치된 Chrome 확장93개 파일은 백업과 바이트가 같고 제거·업데이트하지 않았다. 사용자 확장 문서 직접 열람·자동 이전은 하지 않았다. 파일 이동 안내와 공통 JSON 계약을 유지하며 기존 URL 정책 제한을 우회하지 않는다. 수집 방식 변경은 새로 가져올 때 적용하며 기존 저장 HTML을 재작성하거나 과거 편집/스냅샷을 다시 수집하지 않는다. 설치는 백업을 동반한 직접 교체이며 업데이트 버튼의 자기 교체 시험과 구분한다.
