## 범위와 판단

기존121개 목표를 누락 없이 현재 요구사항과 검사 파일에 대조하고, 이후 추가된 PNG 확대·검토 탐색/기록 관리·출처 복귀16개를 더해 **137개**로 정리했다. [행별 매트릭스](scenario-matrix-0.34.md)와 [시작/완료·조건부 횟수·검사 참조 데이터](scenarios-0.34.json)를 함께 관리한다. 세 검사는 ID/행 수/중복·실행 파일/등록된 브라우저 suite·부분 경계16개·왕복 액션 분해를 확인한다.

## 액션과 화면 이동

메뉴/하위 메뉴 펼침·옵션 선택·링크/문서 이동·뒤로/닫기·입력 초점·스크롤을 각각 센다. 드롭다운의 열기+선택은2회다. 자동 도구의 selectOption1회가 사용자1회라는 뜻은 아니다. 아래는 같은 시작/완료와 확인/입력 조건이며 다른 진입·탐색·재시도 q는 실제 수행 수를 추가한다.

137개 목표를 더해 하나의 제품 전체 절감률을 만들지 않는다. H03의 기본 전달/복사4회는 유지되며 **이미 그래프에서 선택한 경우**의 빠른2회와 다른 시작 상태다. C04는 마지막 Y 확정/닫기 비용1을 누락한 과거 모델을 보정해 기본7/단축6으로 기록했다. 필수 확정이 있는 기록 영구 삭제는3회, 복구만 하기는1회를 그대로 유지한다.

## 검증·직접 사용·경계

최종 `npm run check:all`은 종료 코드0으로 통과했다. 타입·포맷·번들/스킬, Python48·Node55·Chromium859+smoke2, 공식 SDK25·현대 SDK17(프로토콜2026-07-28), 실제 표시 기반 격리 Electron nativeScopes5를 확인했다. 수집 원본 무변경·구현 검토 목표 고정/취소·주소 명령과 정상 종료/재실행 뒤 문서 이름·주석·스냅샷/휴지통·패널·sandbox 복원을 검증했다. offscreen 대체 실행은 사용하지 않았다. 고정 가상 화면의 viewport99.687%/region100% 수치를 일반 웹사이트의 정확도로 확대하지 않는다.

잘못된 URL 수집을 거절하는 검사에서 HTTP/HTTPS 주소 오류를 의도대로 stderr에 남겼고 전체 통과와 구별한다.126개 런타임 자산·번들 스킬 유효성/패키징을 확인했다. 로그는 `local/ux-034/check-all.log`다.

새 `ux-followup-034`은 단일 모달·저장 버전/정책/제외·PNG 확대/위치·초점·검토 판정/메모 유지, 하위 Escape/전체 닫기·전역 진입, 그래프 선택/검색/스크롤/보기, 복구만/복구하고 열기·실제 DB 실패, 복귀 저장 실패/재시도·문서 교체,720×600 실제 버튼 hit, 파일/IndexedDB 재열기를 검사한다. 기존 modal-navigation/0.31~0.33 회귀도 포함한다.

새 검사 준비에서 이미 여러 검토가 있는데 ‘2개 이상’만 기다리면 새로운 생성이 끝난 것으로 오인했다. 새 생성 전 개수+1과 해당 선택 ID·저장 완료를 함께 기다리도록 고쳤다. 임시 진단 코드는 제거했다. 이를 실제 제품의 복구만 하기 실패로 보고하지 않는다. 직접 사용에서도 복구만의 선택 유지와 별도 복구하고 열기를 각각 확인했다.
