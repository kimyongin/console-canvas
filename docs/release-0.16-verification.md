# 0.16 전환 실행 결과

기준일 2026-10-25. 최종 소스·설치 앱은 **0.16.1**이다. 편집기 UI의 React·TypeScript·Tailwind·shadcn 소스 전환과 #8~#11 결함 수정을 구현했다. 전체 완료 판정은 실제 창 확인 등의 잔여 항목과 구분한다.

사용자 요청에 따른 후속 [전체 기능 재검사](full-retest-0.16.1.md)에서는 Python 39·Node 24·소스/설치 Chromium 각각 257·설치본 SDK 22개를 다시 통과했다. 표준 검사의 데스크톱 표시 표면 캡처 실패와 offscreen 정상 종료/재실행 성공은 구분했다. 새 가상 문서의 분기·좌표 주석·PNG도 직접 재검사했으며 기존 4개 UX/출력 문제는 미수정이다.

## 설치와 사용자 자료

기존 0.15.0 창의 저장 완료를 확인하고 Cmd+Q로 정상 종료했다. 앱과 전체 프로필을 백업한 뒤, 기존 앱을 다시 열어 **업데이트 확인 → 다운로드 → 업데이트하고 다시 시작**을 실제 클릭했다. 공개 GitHub v0.16.0 ZIP의 GitHub SHA-256·서명 검증 후 앱이 종료·교체·자동 재실행됐다. 새 버전 화면에 v0.16.0과 스킬 자동 갱신 완료가 표시됐다. 수동 실행을 자동 재실행으로 간주하지 않았다.

설치 전후 감사는 사용자 프로필 자체를 시험 Electron으로 열지 않고 사본에서 수행했다. 7개 문서·13개 전체 스냅샷의 캡처, 이름/휴지통, 편집, 요소/좌표 주석, 추가 설명, 전체 타임라인과 updatedAt을 제외한 전체 세션 지문이 동일했다. 실제 설치 앱의 공식 SDK 읽기 전용 조회에서도 364개 요소·3개 활성 스냅샷과 현재 문서를 확인했다.

별도 `CONSOLE_CANVAS_USER_DATA_DIR`·상태 디렉터리·포트로 동일 설치 앱을 실행해 가상 NORTH만 직접 편집했다. 사용자 문서에는 테스트 작업을 적용하지 않았다. 이 과정에서 긴 주석의 이력 카드가 고정 높이 때문에 다음 항목과 겹치는 문제를 발견했다. 문서 목록에도 같은 문제가 있어 내용 높이의 공통 Button 변형으로 수정했다.

0.16.1은 검증한 앱을 서명 확인 후 교체하고 기존 사용자 프로필로 재실행했다. 당시 Mac이 다시 잠겨 이 소규모 수정판은 **검증한 번들 수동 교체**였고, 앞의 0.15→0.16 자동 업데이트와 구분한다. 정상 종료·백업된 사용자 프로필은 건드리지 않았으며, 중단한 프로세스는 별도 QA 프로필뿐이다. 최종 안정 사본의 7문서·13개 전체 스냅샷·전체 세션 지문도 최초 백업과 모두 동일했다.

설치 스킬의 관리 파일 4개는 0.16.1 앱 번들 ZIP과 바이트 단위로 일치하고 자동 동기화 오류는 없다. 0.16.0 갱신에서 이전 관리 파일의 백업도 생성됐다. 원래 설치에는 개인 추가 파일이 없었으며, 개인 파일 보존·미설치 비강제·교체 실패 복구는 별도 Python 격리 회귀 검사로 확인했다.

CUA의 한글 `typeText`는 이 세션에서 마침표만 입력해, 실제 값 조회로 이를 발견하고 붙여넣기로 교정했다. 이를 한글 조합 키보드 입력 성공으로 보고하지 않는다. composition Enter 충돌은 자동 검사로 확인했고, 실제 IME 조합 입력은 잔여다.

0.16.1 표준 전체 검사는 타입·포맷·번들, Python 39·Node 24·Chromium 249·공식 SDK 22개와 실제 표시 표면 캡처·정상 종료/재실행까지 통과했다. 이후 테스트만 보강해 Chromium 257개 전체를 소스와 설치본 각각 재검증했다. 설치본 MCP/재실행의 마지막 재검사는 위의 offscreen 조건이다. 이를 표준 전체 257개가 실제 표시 표면 조건에서 다시 실행됐다고 표현하지 않는다.

## 반응성과 수명

동일 Electron·가상 NORTH·1440px 창·임시 프로필에서 0.15.0과 0.16.1의 명령 묶음을 비교했다. 81버전·241개 이력까지 만들었다. 단일 실행의 동기 명령/다음 태스크 합산으로, 페인트 완료 지연이나 모든 사이트에 대한 SLA 측정이 아니다.

| 명령 묶음 | 0.15.0 | 0.16.1 |
| --- | --- | --- |
| 선택 80회 | 27.4ms | 20.0ms |
| 이동 확정 80회 + 저장 대기 | 204.3ms | 169.0ms |
| 레이어 검색 40회 | 5.4ms | 9.2ms |
| 긴 이력에서 선택 40회 | 13.0ms | 9.4ms |
| 그래프 열기/닫기 6회 | 99.4ms | 182.1ms |

그래프 탐색 비용은 늘었지만 회당 약 30ms다. 선택/이동의 회귀는 없었다. 반복 탐색 후 scene·iframe 객체 동일, 엔진 iframe 1개, 한 번의 편집 revision 증가 1개를 확인했다. 이 점검을 모든 리스너의 힙 누수 증명으로 확대하지 않는다. `scripts/benchmark-ui.cjs`에 재현 경로를 남겼다.

## 남은 확인

- 0.16.1 설치 런타임의 긴 카드·문서/휴지통·비교·PNG 복사·분기 이동·화면 재열기는 잠금 상태에서도 CUA 인앱 브라우저에서 직접 사용했다. 19개 확인 항목과 새로 발견한 4개 UX/출력 문제는 [직접 사용 기록](usability-check.md#0161-잠금-상태의-브라우저-직접-사용-2026-10-25)에 있다. 이것은 별도 브라우저 저장소의 웹 편집기이며 Electron 창을 조작한 증거로 대신하지 않는다.
- 0.16.1 네이티브 창의 마지막 확인·전체 키보드 순회·실제 macOS 한글 조합은 남아 있다.
- 일반 사용자 창의 실제 활성 화면 MCP 조회를 잠금 해제 뒤 다시 확인한다.
- 보조 Chrome 확장의 실제 설치·활성 탭/탭 변경·거부/지원하지 않는 페이지 권한 경계를 확인한다. 번들/독립 HTML/가상 Chromium 통과를 이 결과로 대신하지 않는다.

후속 브라우저 QA 화면에서는 설치 MCP의 공식 SDK로 실제 활성 문서·요소·주석·분기·이력을 조회하고 UI↔MCP 이동/실행 취소를 확인했다. 문서 ID 재열기 전후 요소·주석 요약·전체 스냅샷·이력 수가 동일했다. 위의 일반 사용자 네이티브 창 잔여와는 다른 범위다. 상세 증빙은 Git 제외 `local/manual-0.16.1-locked/`에 있다.

원시 증빙은 Git 제외 `local/upgrade-0.16.0/`의 설치 전/후/최종 지문, 실제 창 스크린샷, `native-handoff.png`, 설치 MCP 조회, 스킬 갱신 기록, 빌드/설치본 자동 검사 로그에 있다. 실제 사용자 프로필·토큰·캡처는 커밋하지 않는다.
