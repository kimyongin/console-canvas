# 앱 버튼을 통한 업데이트 검증

2026-10-24, macOS Apple Silicon에서 공개 v0.6.0 릴리스로 검증했다.

## 방법

기존 사용자 데이터 폴더를 앱 종료 후 그대로 보관하고 별도 테스트 프로필을 연결했다. 같은 프로필 경로를 두 실행에서 사용해 실제 IndexedDB 저장과 다시 열기를 확인했다. 종료 후에는 보관한 원래 폴더를 복원했다.

시작 앱은 v0.6.0 코드의 복사본으로, 업데이트를 제안받기 위해 plist와 package.json 버전만 `0.5.9`로 지정했다. 테스트용 시작 화면·문서 다시 열기와 진단 메뉴·이벤트 기록을 추가했다. `desktop/updater.cjs`, `desktop/preload.cjs`, `editor.js`, `mcp/app_update.py`는 저장소 코드와 바이트 단위로 같았으며 업데이트 후 남은 이전 앱 백업에서도 이를 확인했다. `0.5.9`는 이 검증을 위한 테스트 버전이며 공개 릴리스가 아니다.

앱의 **업데이트 다운로드**, **업데이트하고 다시 시작** 버튼은 컴퓨터 유즈로 실제 클릭했다. 교체 스크립트를 CLI에서 직접 실행하거나 앱을 별도로 실행해 자동 재실행으로 간주하지 않았다. 재시작 버튼 이후 먼저 프로세스와 MCP로 자동 실행을 확인하고, 그 뒤에 화면 도구를 다시 연결했다.

## 결과

| 확인 항목 | 결과 |
| --- | --- |
| 공개 GitHub ZIP 다운로드·SHA-256·앱 서명 무결성 | 통과 |
| 기존 프로세스 종료 → 새 프로세스 자동 시작 | PID 35626 → 36026, 약 0.98초 간격 |
| 앱 버전·실제 교체 상태 | 0.5.9 → 0.6.0, `installed` |
| 편집하던 문서 자동 다시 열기 | 동일 document_id, 새 editor_id로 확인 |
| 최신 버튼 이동량 | X -72, Y 33 유지 |
| 아이콘 삭제·요소별 주석 | 업데이트 전후 동일 |
| 스냅샷 3개의 ID·이름·시간·내용 개수·현재 선택 | 업데이트 전후 동일 |
| 별도 스냅샷으로 저장하지 않은 최신 작업 | 유지 |
| 재실행 뒤 초기 상태·시안 A·시안 B 이동 | 각 위치·삭제·주석 복원 확인 |
| 과거 이동 전 자동 보관한 최신 작업으로 돌아오기 | 통과 |
| 이전 앱 백업 | 0.5.9 앱 보존 확인 |
| 기존 사용자 데이터 복원 | 원래 폴더 inode가 같은 것을 확인 |

검증에 사용한 ZIP의 SHA-256:

```text
b5e5ef727c4fc177c251f3e8aa1d527bca78bf4c1e39273356de90a525ed1949
```

최초 상태, 시안 A(X -120, Y 50), 시안 B(X -40, Y 90)를 저장하고 최신 작업(X -72, Y 33)은 스냅샷으로 저장하지 않은 채 업데이트했다. 복원 검증 중 최신 작업을 보호하는 자동 스냅샷이 추가되어 최종 화면에는 4개가 표시된다.

이 검증은 앱 업데이트의 실제 종료·교체·자동 실행·저장 보존 경로를 확인한다. Apple Developer ID 서명·공증이나 Intel Mac, 권한이 없는 설치 폴더, 실제 사이트 로그인에 대한 검증은 포함하지 않는다.
