# 무료 Apple Development 서명 적용·두 버전 검증 · 0.39

2026-10-31 · #153 · FR-41. 사용자가 무료 개발용 인증서 적용과 자료 보존·서로 다른 버전의 키체인 재승인 검증을 요청했다.

## 준비한 구현

`apple_signing.py`는 실제 Apple 체인·Team ID·공개 leaf 인증서 지문과 사용 가능한 Apple Development 개인 키를 확인한 앱에서만 신원을 선택한다. private key를 내보내지 않고 사용자 전용 폴더에 공개 선택 정보만 기록한다. 이후 기본 앱 빌드는 같은 지문/팀을 사용한다. 신원 부재/팀 변경·손상·빌드별 DR을 거절하며 자체 서명/ad-hoc으로 자동 전환하지 않는다. 선택 이전에는 기존 개발 서명을 유지한다.

독립 Python 회귀7개는 같은 신원 유지/회전 거절·파일 권한/심볼릭 링크·부재 시 서명 전에 중단·Apple 체인 실패·지문/팀 변경·빌드별 DR 거절을 검증한다. 기존 자체 서명 앱은 실제 검사에서 Apple 팀/서명 정보 부재로 거절됐다. 구현/가상 검사만으로 실제 인증서 적용 또는 무재승인 완료라 하지 않는다.

전체 `npm run check` 종료0: Python67·Node81·Chromium923+smoke2, 타입·포맷·번들/스킬 패키징 통과. 실제 Apple 인증서 적용/설치 검증과 구별한다.

## 설치 전 보존

설치0.38.3을 정상 종료한 뒤 앱398개 파일·프로필227개·스킬4개를 SHA-256 대조 백업했다. 저장소 사본에서8문서/14스냅샷/현재 주석2개/편집 대상20개를 확인했다. 그중 원래7문서의 전체 내용 지문은 이전 배포 감사와 같다. 실제 문서에 시험 편집을 하지 않는다. 키체인 항목의 비밀 없이 Safe Storage 한 항목의 접근 메타데이터를 별도로 기록했다.

## 실제 검증 절차와 현재 경계

처음에는 Xcode/Apple Development 신원이 없었다. 공식 App Store에서 현재 macOS26.5.1과 호환되는 Xcode26.6을 설치하고 macOS 기본 구성 요소만 준비했다. 사용자가 Xcode Apple 계정 로그인과 필요한 인증을 직접 완료했다. Personal Team의 수동 인증서 생성 항목은 비활성화돼 있었다. 새 프로젝트 저장 UI도 비활성화여서 /private/tmp의 별도 임시 macOS 프로젝트를 준비해 열었다. 사용자가 무료 인증서 생성/필요한 개발 등록을 승인한 뒤 해당 프로젝트의 Personal Team·Signing Certificate: Development를 선택했다. 실제 Apple Development 개인 키 포함 신원1개가 발급된 것을 확인했다. 임시 프로젝트/개인 계정 정보는 Git에 넣지 않는다. 유료 가입·기존 인증서 폐기·개인 키 내보내기는 하지 않았다.

첫 Apple 서명 버전0.39.0과 두 번째0.39.1을 같은 신원으로 만든다. 각 교체 전에 정상 종료/프로필 보존을 확인하고, 설치 앱에서 보호된 계정 읽기와 실제 모델 조회를 실행한다. 첫 신원 이전의 사용자 허용과 다음 버전의 재승인을 나눈다. 계정 초기화가 지연되는 일반 앱 시작만으로 무재승인을 판정하지 않는다. 재실행 뒤 문서/주석/전체 분기 지문·스킬·SDK도 확인한다.

첫 Apple 앱0.39.0의 strict/deep·Apple 체인/팀/지문·공식 Electron SHA·DMG 검증을 마치고 설치했다. 교체 전후 프로필227개 파일이 같고 런타임129개 해시가 일치했다. 최초 서명 신원 이전에서 사용자가 Safe Storage에 항상 허용을 완료했다. 설치 앱 자신의 진단은 protectedStorage:true·accountCount:1·modelCount:8·ok:true로 실제 계정 복호화/모델 조회를 마쳤다. OS 승인 창 자동 조작은 하지 않았다.

정상 종료 후 사본 감사에서8문서 전체 지문이 같았다. Safe Storage 한 항목의 메타데이터에 해당 Apple 팀 partition이 추가된 것도 비밀 없이 확인했다. 첫 Apple 앱과 프로필226개 파일을 추가 백업하고 같은 고정 신원의0.39.1을 기본 빌드 경로로 만들었다. 두 버전은 Apple 체인·지문·팀·DR이 같고 CDHash는 다르며,0.39.1이0.39.0의 요구사항을 만족한다.0.39.1 서명 빌드는 추가 승인 없이 완료됐다.

## 두 번째 버전 실제 결과

0.39.1 교체 전후 프로필226개 파일과 런타임129개 해시를 대조했다. 추가 사용자 승인 없이 설치 앱 자신의 실제 계정 진단이 ok:true·protectedStorage:true·accountCount:1·modelCount:8로 끝났다. 실행 전후 SecurityAgent가 없었고 Safe Storage partition 목록은 첫 Apple 버전 이후와 동일했다. 새 빌드 해시 승인을 추가하지 않았다.

설치 앱의 편집기·자동 저장·스냅샷 목록·통합 변경 이력을 확인하고 정상 종료했다. 사본 감사에서 전환 전8문서/14스냅샷/주석2개/편집20개 전체 내용 지문이 같다. 그중 원래7문서도 그대로다. 설치 스킬0.39.1의 관리4파일/오류0·실제 SDK0.39.1 조회·암호화 로그인 파일 동일을 확인했다. 정상 종료 후0.39.1을 다시 실행해 추가 승인 없이 같은 보호 계정1개/모델8개를 조회했다. 재실행 후 MCP 조회도 성공하고 설치 앱은1개만 실행 중이다.

이 기기의 같은 Apple Development 신원으로 수행한 두 버전 시험 결과다. Developer ID·공증·다른 기기 배포 또는 실제 AI3후보 생성/비교/적용을 이 결과로 완료 처리하지 않는다. 완성 앱의 직접 교체이며 업데이트 버튼의 자기 교체 시험은 아니다. 실제 프로필·키체인 메타데이터·로그는 Git 제외 local/apple-development-039에 보관한다.
