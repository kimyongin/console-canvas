## 설치와 복구 지점

사용자가 모든 앱을 종료한 뒤 실제 설치 앱과 QA/Electron 실행 여부를 다시 확인했다. 기존 앱·전체 사용자 프로필·브리지 상태·설치 스킬을 별도 로컬 백업에 복사하고 파일 SHA-256을 대조했다. 앱391개·프로필225개·브리지2198개·스킬4개 파일을 보관했다. 브리지 로그는 실행 중 추가될 수 있어 안정성 대조에서 로그만 구분했다. 실제 편집 DB는 종료 상태에서 동일함을 확인했다. 사용자 프로필을 다른 경로로 옮기거나 테스트 편집을 적용하지 않았다.

`scripts/build_desktop.py`로 공식 Electron45.0.0 SHA-256 검증·0.34 번들·ad-hoc 서명·ZIP/DMG를 생성하고 DMG 무결성과 앱 서명을 검증했다. `scripts/install_desktop.py --update`로 기존 `~/Applications/Console Canvas.app`만 교체했다. 교체 직후 전체 사용자 프로필 파일 지문은 백업과 같았다. 설치 런타임의 체크섬125개(공개 자산 목록126개)가 배포 manifest와 일치했다. 이번 배포는 직접 교체이며 업데이트 버튼의 다운로드/자기 교체를 새로 검증한 결과가 아니다.

## 전후 전체 저장소 대조

백업 복사본만 여는 숨긴 Electron 감사 실행기로 같은 origin/partition의 IndexedDB를 읽기 전용 추출했다. 실제 사용자 저장소를 검사기로 열거나 앱 밖에서 수정하지 않았다. 앱을 정상 종료한 뒤 만든 후속 복사본도 같은 방식으로 대조했다.

| 항목 | 전 → 후 |
| --- | ---: |
| 문서 | 7 → 7 |
| 전체 스냅샷 | 13 → 13 |
| 현재 상태의 요소/위치 주석 | 2 → 2 |
| 현재 상태의 편집 대상 | 20 → 20 |
| 문서/스냅샷 휴지통 | 0/0 → 0/0 |

모든 문서의 원본 캡처·편집·주석·추가 설명·전체 timeline(버전 ID/부모/이름/저장 상태 포함) 지문이 같았다. `updatedAt`을 제외한 session 전체도 같아 코드 패치·AI 요청/초안·전달 정책·검토 기록·활동 이력 등 나머지 저장 내용도 보존됐다. 문서 목록 metadata는 마지막 문서의 파생 표시값 `activeSnapshotName` 한 개 추가만 달랐다. 저장 시각 변경과 이 표시값을 콘텐츠 손실로 보고하지 않는다. 마지막 문서 포인터도 동일했다.

## 실제 설치 앱·스킬·MCP

- 정확한 설치 경로의 앱을 실행해 마지막 문서의364개 요소·저장 스냅샷3개·기존 이동/추가 설명2건을 확인했다. 네이티브 About 창은0.34.0(0.34.0)을 표시했다. 편집기 주소창 숨김·한 줄 도구 모음·통합 변경 이력·새 스냅샷 목록 표기가 실제 화면에 반영됐다.
- 스냅샷 목록의 접근성 트리에서 기존3개 버전과 선택/작업 기준 구별·‘이 버전 전달’을 확인했다. 이번 네이티브 조작에서는 목록이 닫히거나 요소 프레임을 얻지 못해 노드 선택→전달→검토→그래프 왕복을 완주하지 못했다. 해당 흐름의 공통/직접 웹 검증은 [0.34 UI 기록](scenario-ux-audit-0.34.md)이며 설치 앱에서 전부 다시 직접 사용했다고 표시하지 않는다.
- 앱 실행 시 설치 스킬 관리4개 파일이 번들과 일치하도록 자동 갱신됐다. `skill-sync-result.json`의 version0.34.0·오류0을 확인했다. 개인 추가 파일은 이번 실제 설치에 없으며 보존 동작은 기존 회귀 검사 근거다.
- 새 공식 MCP SDK 클라이언트로 설치된 스킬 helper → 설치 앱을 읽기 전용 연결했다. 서버/가이드0.34.0·마지막 문서·요소·주석·스냅샷·전체 이력 조회가 성공했다. 앱을 정상 종료하고 다시 실행한 뒤 같은 조회를 다시 통과했다. 이번에 사용자 문서에 MCP 쓰기를 적용하지 않았다.
- 업데이트 전부터 유지된 이 대화의 MCP 어댑터는 이전 인증 정보로401을 반환했다. 새 SDK 연결 성공과 구분하며 기존 클라이언트의 자동 재인증까지 성공했다고 표시하지 않는다. 기존 대화의 MCP 연결은 클라이언트 재연결이 필요하다.
