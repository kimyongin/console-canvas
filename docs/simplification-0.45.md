## 범위와 사용자 지시

기존 작업은 폐기 가능한 테스트 자료라는 명시적 지시로 #161 자료 이전 관문을 취소했다. DB v2가 과거 문서 저장소를 초기화하며 새 문서·티켓부터 저장한다. 일반 웹사이트 로그인 partition·OS/Apple 서명·개인 스킬 파일은 초기화하지 않는다.

수동 스냅샷·분기/Git 그래프/과거 이동, 앱 내부 AI 공급자/로그인/직접 호출, 후보 갤러리/HTML·CSS 생성·적용, 별도 복잡한 구현 재수집/검토의 UI·저장·전용 모듈·IPC·MCP·가이드를 제거했다. 단일 이미지로 화면을 평탄화하지 않았으며 선택/복사/정렬/주석과 수집 품질 비교·자산 복구를 유지했다. 자산 복구 엔진은 관측한 이미지·폰트만 복구하고 임의 HTML/CSS를 받지 않는다.

새 티켓은 이미지·요청·상태를 중심으로 하고 목표와 출처/주석은 불변이다. 구현 지시·구현 이미지/검증·사람 승인 조건을 상태 변경에 요구한다. DB 트랜잭션 CAS/영속 operation receipt로 중복·오래된 쓰기를 거절한다. 화면 변경/재시작으로 editor_id가 달라져도 확정 등록 재시도는 기존 티켓을 반환한다.

문서 복제는 새 ID의 독립 현재 작업이며 기존 티켓은 복제하지 않는다. 편집 파일 v2는 문서와 해당 문서 티켓의 백업이다. 충돌·잘못된 이미지 import는 원자 거절한다. DB를 읽지 못하면 긴급 백업은 현재 메모리 화면을 내보내고 티켓 미포함 경고를 파일과 화면에 명시한다.

## 설치 앱 확인

`~/Applications/Console Canvas.app`을0.44.0→0.45.0→0.45.1→0.45.2로 정상 종료 후 원자 교체했다. 같은 Apple Development 인증서·Team ID를 유지했고 공식 Electron SHA-256·strict/deep 서명·DMG 검증을 통과했다. 최종 설치 런타임110파일 지문 불일치0, 설치 앱1개를 확인했다.

실제 앱에서 NORTH 수집과 앱 디자인 복제본이 열리고 새 요청·주석 패널·목표 확정/작업 티켓 버튼을 확인했다. 설치 앱 번들의 새 공식 SDK 연결에서15도구·가이드를 읽고, 복제본에 이동12px/주석→현재 이미지 목표 등록→작업/증빙/검토·대기 복귀3기록을 저장했다. 정상 종료·0.45.1/0.45.2 업데이트·재실행 뒤 문서 ID·주석·이동·목표 이미지 SHA-256과 기록3개가 동일함을 확인했다. 승인은 QA 역할의 격리 검사에서만 사용했다.

관리 스킬은 앱 시작 시0.45.2로 자동 갱신됐고 오류0, 앱 번들 가이드와 설치 SKILL.md 동일, 설치 런타임 ZIP 지문 동일이다. OS/브라우저 로그인이나 개인 스킬 파일을 초기화하지 않았다. 보호 저장소를 사용하는 AI 기능을 제거했으며 이 작업 중 추가 키체인 승인을 요구하지 않았다. 이것을 남아 있는 계정 기능의 암호화 적격 검증으로 확대하지 않는다.

공통 UI는 설치 앱이 제공하는 편집기를 브라우저에서도 직접 클릭해 선택·주석·목표 등록·고정 이미지·목록/뒤로와 주석 자동 채움을 확인했다. 네이티브 AX의 일부 웹 버튼 클릭은 즉시 상태 반영을 확인하기 어려워 모든 네이티브 버튼의 성공을 주장하지 않는다. 설치 화면의 새 명칭과 주석 표시, 실제 네이티브 메뉴/수집·MCP 및 재실행을 별도로 확인했다. offscreen 통합과 이 직접 사용 결과를 구별한다.

Codex의 기존 console-canvas 등록을 설치 앱의 mcp/server.py·같은 로컬 state-dir/8849로 갱신했다. 기존 대화에 오래 붙어 있던 stdio MCP 세션은 토큰/도구 목록을 캐시하므로 업데이트 후 재연결이 필요할 수 있다. 실제 설치본의 새 SDK 연결에서는0.45.2 가이드와15도구가 정상 동작했다.

## 액션과 검토 범위

개발 대화에서 시안 요청·선택·티켓 등록·구현 지시·결과 검토를 이어가며 앱 왕복/링크 이동을 필수로 두지 않는다. 앱에서 현재 목표를 직접 등록할 때는 ‘목표 확정→요청 입력→등록’3개 액션(기존 주석이 있으면 자동 채움으로2개), 티켓 상세는 ‘작업 티켓→항목 선택’2개다. 메뉴 펼치기/링크 이동도 각각1개로 센다. 출처의 프로젝트 설정은 문서별 초기 연결이며 티켓마다 반복하지 않는다. 저장과 진행 확인을 줄이려고 자동 구현/자동 완료를 도입하지 않았다.

이미지 제안 생성 기능은 외부 에이전트 기능이다. 이번 검사는 선택된 fixture 이미지/현재 결과 등록을 사용하며 실제 공급자 추론이나 사람이 이 프로젝트 구현을 승인했다는 주장이 아니다. 검토 완료는 테스트 역할의 승인 기록으로 검사했다. 원본 재현 일반화 #68/#73, 공개 배포 적격 #152는 별도다.

Electron/MCP 전체 통합은0.45.1에서 완료했다.0.45.2는 표시 보완으로 최종 공통 검사와 실제 설치 서버의 SDK/자료 지문·재실행 검사를 추가했다.

최종0.45.2는 부모 삭제 아래 자식 이동이 현재 요청 목록에 중복 표시되지 않도록 엔진/전달 이미지의 현재 변경 기준을 재사용한다. 단일 목표·댓글 보존과31개 티켓 검사를 포함한다.
