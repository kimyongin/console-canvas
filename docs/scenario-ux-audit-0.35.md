## 범위와 기준

기존137개 ID/목표와0.34의 최종 액션 모델을 유지하고 작업 맥락3개를 추가해 **140개**를 대조했다. [전체 행별 매트릭스](scenario-matrix-0.35.md)·[기계 검증 데이터](scenarios-0.35.json).124개는 관련 제어환경 검사,16개는 실제 OS 대화상자·외부 메시지·계정/유료 추론·사용자 업데이트까지 포함한 부분 경계다.140개를 사람이 각각 완주하거나 모든 조건의 시간/오류율을 측정했다는 뜻은 아니다.

메뉴/하위 메뉴 펼침·옵션 선택·링크/문서 이동·닫기/복귀·입력 초점·스크롤을 각각 센다. 네이티브 드롭다운은 열기+선택2회다. 자동 초점에는 사람의 별도 클릭을 더하지 않는다. 기본은 표준 데스크톱 진입이며 작은 창에서 필요한 ‘추가 편집 도구’ 메뉴와 각 흐름의 추가 탐색/스크롤/재시도 q는 실제 수만큼 더한다. 미측정 q를0으로 숨기거나 겹치는 목표를 합쳐 전체 제품 절감률을 만들지 않는다.

## 직접 재현한 문제와 구현

별도 localhost54252의 가상 NORTH만 사용했다. 내보내기 버튼 선택→주석→‘검토 A’ 저장→검색 ‘검토’→비교→닫기를 사용해 그래프 검색어가 사라지는 것을 확인했다. 문서 메뉴에서 ‘NORTH’ 검색 후 전체 목록으로 넘어가면 검색이 빈 값으로 열리는 것도 재현했다.

AI에서는 ‘버튼들의 간격’ MCP 요청을 보관한 뒤 새 요청 폼에 미제출 ‘검색 영역을 두 줄로’ 문장을 적고 접었다. 원래 요청의 ‘같은 기준으로 추가 생성’을 누르면 숨긴 문장으로 새 요청이 보관됐다. 새 초안의 API 경로/개수까지 추가 생성에 사용되는 구조여서 사용자의 실제 실행 의도를 확인하기 어려웠다. 유료 API를 호출하거나 외부 대화로 보내지 않았다.

## 검증과 한계

최종 `npm run check:all` 종료 코드0:타입·포맷·번들/스킬, Python52·Node55·Chromium899+smoke2, 공식 SDK25+현대 SDK17(2026-07-28), 실제 표시 기반 격리 Electron nativeScopes5가 통과했다. 정상 종료/재실행 뒤 문서 이름·주석·스냅샷/휴지통·문서 휴지통·패널·sandbox 보존, 원본 무변경·고정 검토 목표/취소·주소 명령도 통과했다. 잘못된 URL의 의도한 거절은 stderr에 남기고 전체 검사는 정상 종료했다. offscreen 대체 실행은 하지 않았다. 최종 로그는 `local/ux-035/check-all-final.log`다.

직전 전체 검사에서는 아래 문서 전환 경합 때문에 종료 코드1이었다. 실패 로그 `check-all-before-document-transition-fix.log`를 별도로 보존하고 수정 뒤 관련151개·최종 전체 검사를 다시 통과했다. 초기 통과 기록으로 마지막 실패를 덮어쓰지 않는다.

신규 `ux-followup-035`40개는 검색/확대/초점·비교/이름 변경 취소/성공·0건·A→B/A→D 보존·문서/선택 삭제·느린80ms IndexedDB 쓰기/실패·이름 창 중 문서 전환·저장 중 입력한 주석 보존, 빠른20개/전체23개·검색 이어가기/수정·일반/휴지통 기본값, 독립 AI 문장/개수/경로·API 설정/미등록·자동 초점·연결/재열기·원래/후보 기준·중복/실패·720×600 실제 hit·파일/IndexedDB 왕복을 검사한다. Python은0.34와0.35 ID/표/참조·부분 경계·액션 분해 및 기존137개 목표/최종 비용 보존을 함께 검사한다.

전체 검사에서는 실제 문서 전환 경합도 발견했다. 비교 창을 닫고 새 캡처 저장을 기다리는 동안 이전 세대의 복귀 콜백이 그래프를 다시 열었다. 새 캡처 저장이 성공한 뒤 세대를 먼저 무효화하고 이전 모달을 닫도록 순서를 고쳤다. 실패하면 기존 문서/비교를 유지한다. 저장을 기다리는 동안 주석/설명/편집이 바뀌면 이전 문서를 다시 flush한 뒤 전환해 늦은 입력을 보존한다. 실제 IndexedDB 쓰기를80ms 지연한 조건·쓰기 실패·이름 창 중 전환·지연 중 주석 입력까지 회귀 검사했다.

새 검사 준비에서 비동기 목록/요청 생성 직후 DOM 반영 전에 확인한 경우가 있었다. 휴지통 범위·선택 요청 ID·입력 초점까지 기다리도록 고쳤다. 이름 변경 뒤 결과의 부모 설명에 새 이름이 나오는 것은 정상이며 해당 ID가 검색 결과에서 제외되는지를 검사한다. 이 준비/단언 오류를 제품의 데이터 손실로 보고하지 않는다.

수정 빌드를 같은 저장 문서로 다시 열어 비교 후 검색 ‘검토’/100% 유지·이름 변경 취소 후 같은 검색·문서 빠른 검색→전체 목록의 ‘NORTH’ 유지·자동 초점을 직접 확인했다. AI에서 미제출 API 초안(문장/7개)을 보존하면서 기존 MCP 요청의 독립 문장/2개로 새 요청을 보관했고, 새 초안이 그대로인 것을 확인했다. 접힌 추가 설정 요약·펼침 자동 초점·AI 창 재열기 초안도 직접 사용했다. 720px 직접 사용(브라우저 내부 높이500px)에서 추가 설정을 펼친 뒤 생성 버튼이 화면 아래로 밀리는 것을 확인해 하단 고정 행으로 고쳤다. 버튼 하단438px·실제 hit를 다시 확인했고720×600 자동 검사도 통과했다. 최종 추가 생성 화면은 `ai-followup-final.png`다. 화면/로그는 Git 제외 `local/ux-035/`다.

사용자 설치 앱0.34·개인 스킬과 실제 자료를 바꾸지 않았다. MCP 명령/저장 형식·수집·네이티브 IPC는 유지한다. 실제 유료 추론·외부 메시지·OS 입력/업데이트·설치 스킬 배포는 이번 공통 UI 검증으로 완료하지 않는다. 설치 상태는 [0.34 배포](deployment-0.34.md)와 구별한다.
