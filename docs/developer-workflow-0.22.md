# 0.22 · 디자인 의도 전달부터 구현 결과 확인까지

사용자 승인으로 실제 사용성 검토를 #52~#58로 분리해 구현했다. 목적은 사용자가 자유 배치와 짧은 선택으로 디자인 의도를 표현하고, 개발 에이전트에게 PNG 한 장으로 전달한 뒤 실제 구현 결과를 확인하는 것이다.

## 사용자 흐름

1. 개발 화면을 가져와 요소를 이동·삭제한다. 주석에서 배치 제안과 좁은 화면의 줄바꿈/세로 쌓기/구조 유지를 선택한다. 제안은 선택 전에는 주석/화면을 바꾸지 않으며 자유 수정할 수 있다.
2. `변경 내용 전달`에서 배치 참고/확정 시안과 전달 버전을 고른다. 한 PNG에 경로·기준 너비/높이·가져온 시각·버전·그림 해석 기준·번호 카드·반응형과 기존 동작 유지 지침을 포함한다.
3. 에이전트는 지정한 원본 소스 프로젝트에 의도를 구현한다. Console Canvas의 MCP가 원본 소스를 자동 변경하는 것은 아니다.
4. 수정된 웹 화면을 기존 가져오기 기능으로 별도 수집한다. 목표 문서의 `구현 결과 확인`에서 결과를 선택하고 나란히 비교한다. 새 결과가 목록에 없으면 `목록 새로고침`을 누른다.
5. 요청별 미검토/반영 확인/추가 수정과 메모를 기록한다. 다른 결과를 선택하면 이전 검토를 보존한 새 검토가 생긴다. 남은 요청만 원래 번호·메모와 함께 PNG 한 장으로 다시 전달한다.

## 구현과 보존

- #52/#53: `design-intent.js`는 주변 영역·남은 형제 기반 문장과 반응형 선택을 제안한다. 승인 문장은 기존 annotations에 들어가 주석·MCP·이력·undo·스냅샷과 공유한다. API 키 없이 동작하며 CSS를 자동 수정하지 않는다.
- #54/#55: `handoff-image.js`가 모드·맥락을 그린다. 긴 메타데이터와 footer도 실제 줄 수로 높이를 잡는다. 쿼리/fragment를 제외한 origin/경로를 출력한다. 일반 전달/후속 요청 모두 단일 PNG다.
- #56: `implementationReviews`는 문서별 검토 기록이다. 목표 point·요청·별도 결과 캡처와 point·상태/메모를 포함한다. 원본 결과 문서가 없어도 파일로 복원할 수 있다. 검토 20개·직렬화 20,000,000자·검토당 1,000요청 한도를 넘으면 기존 데이터를 지우지 않는다.
- 전달 모드는 문서별 `handoffSettings`에 저장한다. 검토는 캔버스 undo/스냅샷과 독립적이며 목표/결과를 고정해 현재 장면을 덮어쓰지 않는다. 다른 결과의 판정은 자동 승계하지 않는다. 내장 결과 입력 검증은 문서 전환 전 수행한다.
- #57: 선택 도구는 캔버스 여백을 우선하고 손잡이/방향키/Home으로 이동/복원한다. 삭제 전 참고 렌더가 선택 콜백을 발생시켜 주석 모달을 닫던 문제도 수정했다.
- MCP 도구 19개 계약은 유지한다. 승인된 의도는 일반 주석, 전달 모드는 선택적 화면 metadata다. 렌더 중 전달 모드가 바뀌면 이미지 조회를 충돌로 거절하며 WebMCP 비동기 이미지/맥락 캐시는 전달 모드·요청 리비전도 확인한다.

## 검증 범위

가상 NORTH 콘솔에서 실제 브라우저로 이동→문장 제안 선택→삭제 대상의 같은 너비/모바일 쌓기 선택→단일 PNG→부분 반영 웹 화면 재수집→비교→누락 요청 메모를 확인했다. 테스트 자료와 별도 프로필/포트만 사용했고 실제 사용자 문서는 수정하지 않았다.

자동 워크스루는 실제 DOM 구조/CSS를 수정한 별도 웹 소스를 다시 캡처한다. 이는 외부 AI가 이미지만 보고 개발한 독립 실험이 아니며, 일반 사용자 프로젝트의 시간 단축·재질문 감소를 측정한 결과가 아니다. 실제 API/OAuth·에이전트 자동 실행·설치 앱 배포는 기존 #42/#44/#27 범위에 유지한다.
