## 실제 사용과 액션

- 1280px에서 원본 ID/선택자 검색, 검색0건, 지우기1회와 Escape1회 복귀. ID를 검색하면 버튼과 같은 원본 locator를 가진 내부 문구/아이콘도 개별 요소로 일치할 수 있어 수를1로 고정하지 않는다. 조회만으로 선택하거나 이동하지 않는다.
- 깨끗한 A의 ‘현재 버전’, 요소 방향키 이동 뒤 A 복원 가능, B 저장→A로 이동→D 저장, B↔D 왕복. 실제 그래프 연결선은 A→B와 A→D이며 B와 D가 같은 줄의 선형 부모로 바뀌지 않았다. 과거/미래 버전과 편집 위치를 유지했다.
- 이름을 구별한 두 가상 캡처에서 결과 미리보기→검색→선택, 검색 불일치→지우기, 닫기/Escape·최종 초점 복귀. 결과 이름/시각/1360px와 고정 목표 표시 확인. 검색 없는 기존 드롭다운의 짧은 경로는 유지한다.
- 720×600에서도 결과 팝오버는 x72~648, 높이242로 화면 안에 있으며 문서 가로 넘침이 없었다. 전달 창의 완료된 이미지·버전 선택/후속 버튼과 실제 PNG 저장을 사용했다. 저장된 PNG는1440×1862,285683바이트이며 PNG/IEND를 확인했다. 뷰포트는 원래대로 복원했다.

실패/지연은 실제 가상 브라우저의 Canvas 출력 실패·완료 지연과 파일 저장 응답 지연으로 재현했다. 사용자 캡처·OS에 실패를 주입하지 않았다. 사람이 오류 복구에 쓰는 실제 시간이나 다수 사용자 선호를 측정한 것은 아니다. 불필요한 자동 선택/적용을 추가해 액션 수를 줄이지 않았다.

## 검증

최종 `npm run check` 종료 코드0: 타입·포맷·번들/스킬, Python45·Node52·Chromium632 + smoke2. 신규 `tests/ux-followup-029`27개가 원본 검색·초점/복귀·0건·현재/dirty 버전·자동 보관·영 이동/좌표 주석/CSS 확대·이미지 실패/재시도·지연/버전 전환/닫기·오래된 저장 완료를 확인한다. 기존 분기/주석/휴지통·파일/저장 복원·개발 전달 회귀도 통과했다.

기존 developer-workflow의 즉시 후속 클릭은 이미지 재생성 완료를 기다리도록, trash의 숨겨진 그래프 조작은 실제 열린 그래프·활성 버튼을 기다리도록 수정했다. 초기 검사에서 이 두 옛 가정은 실패했고 최종 전체 실행에서 통과했다. 조건을 삭제하거나 실패를 성공으로 처리하지 않았다. 스킬 quick_validate 및 새 AC102~105의 중복 없음도 확인했다.

가상 화면/로컬 로그는 Git 제외 `local/ux-029/`에 있다. `final-result-picker.png`, `result-search-720.png`, `snapshot-branches.png`, `check-final.log`가 주 증빙이다. 사용자 파일/실제 캡처는 커밋하지 않았다.

공통 UI 변경에 따라 웹 검증으로 완료했다. Electron 수집/IPC·OS 클립보드/저장 대화상자·설치 업데이트/재시작·실제 IME/스크린리더·외부 에이전트 전송/유료 추론을 새로 검증한 것은 아니다. 설치 배포 #27과 기존 실제 계정/외부 통합 미완료 조건은 별도다.
