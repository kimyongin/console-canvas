# 가져오기 품질·내부 선택 개선 티켓

요구사항 확정: 2026-10-29 · 구현 기준: 0.23.0 · 이 문서는 후속 계획이며 구현/배포 완료 선언이 아니다.

사용자는 외부 페이지를 소스 없이 가져와 원본과 같은 모습의 요소를 편집하고 싶다. 현재 네이버에서 발견한 iframe·이미지·내부 선택 문제를 해결한 뒤, 여러 카테고리의 유명 사이트 10개에서 실제 원본과 복제 이미지를 비교한다.

## 확정한 기본 동작

1. 일반 가져오기 버튼으로 각 iframe 내부의 DOM 수집을 먼저 시도한다. 메인 페이지에서 `contentDocument`를 읽는 것만으로 끝내지 않는다.
2. 수집에 성공하면 프레임 경로와 원본 식별자를 유지하면서 개별 요소로 합친다. 다른 출처라는 이유만으로 시도 없이 이미지로 처리하지 않는다.
3. 실제로 실패한 프레임만 이미지 폴백으로 처리한다. 프레임 하나의 실패가 나머지 수집을 막지 않는다. 실제 권한/접근 거부·프레임 변경·한도 등의 이유를 구분한다.
4. 이미지 데이터는 문서에 포함한다. 데이터를 읽을 수 없는 이미지는 원본 화면의 픽셀로 보완하며 링크만 남겨 성공으로 표시하지 않는다.
5. 긴 iframe과 화면 밖 영역을 일부 캡처로 늘려 채우지 않는다. 누락 영역을 해결하고, 전체 수집이 불가능한 조건은 명확히 남긴다. 사용자가 영역을 맞춰 다시 가져오는 것을 기본 해법으로 삼지 않는다.

브라우저에서 `shopsquare.naver.com`에 접속할 수 있다는 사실을 사이트 접근 불가로 설명하지 않는다. 현재 프레임별 수집 누락과 실제 확장 실행 권한을 구분해 확인한다. 별도 옵션으로 수집 방식을 고르게 하는 요구가 아니다.

## 주요 수용 조건

- **#64:** 동일/다른 출처·중첩·중복 URL·권한 허용/거부·프레임 이동/제거를 검사한다. 내부 스크롤·테두리·배율·고정 요소·고유 ID·원본 프레임 경로를 유지하고, 네이버 쇼핑 영역의 실제 수집 시도와 성공/실패 근거를 남긴다.
- **#66:** 일반 이미지·CSS 배경/스프라이트·SVG 이미지 참조를 조사한다. object-fit·자르기·위치·크기를 보존하고 텍스트/자식을 중복 렌더하거나 전체 UI를 이미지로 평탄화하지 않는다. 네트워크 차단/원래 URL 만료 후 재열기·스냅샷 복원·전달 PNG에서도 이미지 유지 여부를 검사한다.
- **#65:** 메인 뷰포트 아래로 이어지는 프레임의 렌더링된 내용을 실제 캡처로 포함한다. 프레임 내부 스크롤 밖의 미렌더링/가상 콘텐츠와 구분한다. 일부를 전체로 늘리거나 누락을 감추지 않는다. 캡처 한도·취소·실패와 필요한 원래 브라우저 상태 복원을 검사한다.
- **#62:** 클릭은 내부 요소를 선택하고 드래그는 기존 선택을 이동한다. 클릭만으로 편집/undo/리비전을 만들지 않는다. 별도 이동한 자식·겹침·다중 선택·수정키·취소·주석/영역 선택을 회귀 검사하고 실제 네이버 복제본에서 확인한다.
- **#63:** 같은 뷰포트·배율·스크롤·관심 영역의 원본/복제/차이 이미지와 수치·육안 평가·수정 전후 결과를 남긴다. 정적 화면의 차이 없는 복제가 목표다. 임의 허용 오차나 원본 이미지를 복제본 대신 표시하는 방법으로 동일 판정을 만들지 않는다.

실제 URL·리다이렉트·시각·브라우저/OS·로그인 여부·뷰포트·배율·스크롤과 검사한 영역을 기록한다. 초기 화면뿐 아니라 하단과 긴 페이지, iframe·주요 이미지도 확인한다. 시간에 따라 바뀐 광고/시세/영상은 근거와 함께 분류하고 복제 결함과 구별한다. 접속 실패·제한/인증 화면은 정상 본문 성공으로 세지 않는다. 대상을 바꾸면 이유를 기록한다.

각 사이트에서 선택·이동·삭제·주석·저장/재열기를 확인한다. 미해결 결함은 티켓과 제약을 남기고 검증 완료로 표시하지 않는다. 실제 웹사이트 이미지·캡처·사용자 자료는 Git에 커밋하지 않고 로컬 증빙으로 관리한다.

## 기존 작업과 보존 기준

- [#61](https://github.com/kimyongin/console-canvas/issues/61)은 직접 읽을 수 있는 iframe DOM 및 현재 뷰포트 부분 이미지 폴백의 완료 기록이다. 모든 다른 출처 iframe과 긴 iframe 전체 캡처의 완료를 뜻하지 않는다.
- [#33](https://github.com/kimyongin/console-canvas/issues/33)은 일반 Chrome의 COOP/COEP·리소스·권한·WebMCP 통합을 계속 추적한다. 이번 티켓의 결과를 재사용하되 남은 조건을 자동 완료하지 않는다. 사용자 설치 앱 배포는 #27에서 별도 관리한다.
- 문서·요소/좌표 주석·추가 설명·변경 이력·스냅샷 전체 분기와 휴지통을 보존한다. 실제 사용자 문서에 시험 편집을 하지 않는다.
- 원본 DOM/업무 동작과 보안 격리를 유지하고 수집 스크립트를 복제본에서 실행하지 않는다. 변경 경로에 맞는 공통/Chrome/Electron/MCP 검증을 구분하며 PRD·README·관련 스킬을 최종 구현에 맞춘다.

## 이번 문서 정리의 검사 상태

2026-10-29 `npm run check`는 타입·포맷·빌드·Python 43·Node 33 이후 Chromium iframe suite에서 실패했다. opaque 프레임의 녹색 내용 대신 흰색(255,255,255)이 캡처되었다. 현재 원인은 미확인이며 #65에서 빈/미페인트 캡처와 렌더 준비·표시 표면 조건을 재현한다. 이전 420개 및 선택 suite 38개 통과 기록과 구별한다. 이번 실행을 전체 통과나 실제 사이트 검증 완료로 표시하지 않는다. 원본/복제 비교 준비와 필수 검사만 수행했으며, 이번 요청에서는 기능 코드 수정과 사이트 방문을 재개하지 않았다.
