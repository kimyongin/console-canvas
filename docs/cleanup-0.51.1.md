# 남은 티켓·브랜치 정리 · 0.51.1

2026-11-01. 5회차 개선 뒤 누락된 검증과 문서의 현재 상태를 정리했다. 과거 유실 로그를 복원했다고 주장하지 않는다.

## 동일 조건 25사례 재측정

기준은 0.47.0(3fa274c), 비교는 0.51.1이다. 서로 다른 루프백 origin의 빈 브라우저 저장소를 사용했다. 같은 수정 전 수집 파일·대상·요소 주석·공통 조건·목표 요청으로 **파일 가져오기 → 티켓 이름/프로젝트 지정 → 대상 검색/선택 → 주석 → 목표 확정 → 캔버스 복귀**를 UI에서 각각25번 수행했다. 첫 사례는 시작 화면, 나머지는 티켓 메뉴의 파일 열기에서 시작한다. 테스트 파일의 독립 ID만 준비했으며 DB에 티켓을 주입하지 않았다.

원본 화면은 이미 수집된 동일 파일이 시작 조건이다. 이번399를 원본 사이트 준비·최초 MCP 연결·시안 선택·프로젝트 구현·사람 승인까지의 전체 횟수라고 해석하지 않는다. 실제 메뉴·파일 선택·입력·클릭은 각1회이며 결과 화면 전환을 중복 더하지 않는다. 자동 AX/사진 조회·SDK 호출은 사람 행동 수에 넣지 않는다. 이번25개는 주석으로 개선 의도를 준비하는 경로다. 수동 이동·삭제·복사 등의 기존 직접 사용과 자동 회귀는 별도 증거다.

## 독립 에이전트와 MCP

- 이전 대화 맥락을 받지 않은 별도 에이전트가 앱 제공 가이드부터 읽고 I3 목록을 2+2+1로 조회했다. 번호를 canonical ID에 고정하고 목표·주석·실제 이미지 블록을 읽었다. 모든 작업이 review여서 재실행 대신 검토를 안내했으며 승인/상태를 쓰지 않았다.
- I1~I5 각 범위의25개 ID와 명시 부분20개 ID를 별도로 대조했다. 다른 프로젝트의 ID는5개 범위 모두 ticket_not_found로 거절했다. 최종 revision·goal_id·상태가 같았다.
- 첫 not_connected와 UI 연결 복원 후 성공을 모두 보존한다. 앱 실행·프로젝트 공개/연결과 인증 실패를 구분했다. 실제 사람의 새 이미지 시안 선택이나 승인을 대신 실행하지 않았다.
- #186: 기존 stdio는 시작 때 토큰을 고정해 앱 업데이트 후401을 반환했다. 새 어댑터는 같은 connection.json·같은 주소의 갱신 코드만 인증된 health 확인 뒤1회 재시도한다. 다른 주소/포트·빈/같은 코드·403·통신 단절은 재전달하지 않는다. operation_id와 인자를 유지한다. 일반 명령은 갱신 잠금으로 직렬화하지 않는다.
- Python 경계 회귀와 실제 공식 SDK의 토큰 회전 검사가 통과했다. 명령은 한 번만 전달됐다. 이미 실행 중인0.51.0 어댑터에는 새 코드가 없으므로 최초1회 MCP 재시작이 필요하며 이후 업데이트 복구와 구분한다. 등록 명령/권한은 바꾸지 않았다.

## 공통·통합·설치

`npm run check`: Python49·Node42 및 전체 공통 Chromium suite 통과. `npm run test:desktop:offscreen`: 공식 SDK16·최신 SDK6(protocol2026-07-28), 이미지 입력8·범위5, 저장/정상 종료/재실행·목표/주석/작업 기록·격리 통과.

기존 앱을 정상 종료하고 앱·프로필·스킬을 백업했다. 같은 Apple Development 신원으로0.51.1 빌드/strict 서명·DMG 무결성을 검증하고 설치·재실행했다. 앱 본체 프로세스1개, 마지막 티켓 복원, source/runtime/가이드/번들 스킬/개인 스킬 바이트 일치, 설치 경로 공식 SDK0.51.1을 확인했다. 기존 사용자 CC-5의 전체 티켓 SHA-256이 전후 같고 주석·목표·이미지3개가 유지됐다. 원래25개 구현 검토 자료와 새 측정 자료는 별도 브라우저 저장소다.

네이티브 AX/사진 조회는 가능했으나 본문 버튼 클릭은 무반응, 좌표 클릭은 noWindowsAvailable이었다. 메뉴를 통한 정상 종료는 됐다. 이 환경에서 실제 OS 포인터/IME·보안/파일 대화상자 검사를 통과했다고 쓰지 않는다.
