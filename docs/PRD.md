# Console Canvas PRD

확정 방향: 2026-11-01 · **티켓 우선 편집 전환: 계획/미구현** · 상위 [#169](https://github.com/kimyongin/console-canvas/issues/169)

설치 앱·실제 MCP·번들 스킬은 현재 **0.45.2**다. 그 버전의 사후 목표 티켓 등록을 아래 요구사항의 구현 완료로 해석하지 않는다. 실행 순서와 상태는 [티켓 추적표](ticket-review.md), 상세 계약은 [티켓 우선 MCP·스킬](ticket-first-mcp-skill.md)에 둔다. 이전 CC-FR/AC와 완료 증빙은 [0.45 PRD](PRD-0.45-history.md)·[0.45 티켓](ticket-review-0.45-history.md)·[0.45 검증](simplification-0.45.md)에 보존한다. 이번 문서의 CC-FR/AC는 아래 전환을 기준으로 다시 정의했다.

## 1. 배경과 제품 목적

원하는 웹 디자인을 말로 설명하기 어려워 에이전트의 구현이 기대와 달라지고 재설명·수정이 반복됐다. 실제 화면을 편집하고 주석을 달거나, 이미지 시안을 보고 선택하면 의도를 구체적으로 공유할 수 있다.

0.45는 편집 문서와 나중에 등록하는 확정 목표 티켓을 분리했다. 이 때문에 사용자가 화면 이름·주석 위치·이미지 조회 방법·후속 요청을 길게 다시 설명해야 했다. 편집에서 시안과 구현까지 같은 작업을 식별하는 단위가 필요하다.

**제품 원칙: 티켓을 먼저 만들고 그 안에서 편집한다. 에이전트와는 그 티켓의 ID나 이름으로 대화한다.**

- 티켓 하나는 하나의 개선 목적이다. 실제 원본 복제 화면·현재 편집·관련 주석·공통 설명을 기본 묶음으로 보관한다.
- 같은 티켓에 사람이 선택한 이미지, 확정 구현 목표, 구현/검토 기록이 이어진다. 별도의 전달 요청이나 사후 등록 티켓을 만들지 않는다.
- 사용자는 ‘캔버스 티켓 가져와’, ‘1번 시안 3개’, ‘CC-12 구현해’ 정도로 요청한다. 화면/주석/필요 스크롤 이미지 조회는 스킬과 MCP가 맡는다.
- 이미지 시안 생성·비교·선택과 결과 검토는 기존 개발 에이전트 대화에서 한다. 캔버스 왕복을 필수로 만들지 않는다.
- 픽셀 편집은 의도를 나타낸다. 실제 소스는 원본 컴포넌트와 반응형 규칙에 맞게 구현한다.

## 2. 역할·범위·핵심 용어

| 역할 | 책임 |
| --- | --- |
| 프로젝트 | 실제 수정할 로컬 저장소와 실행 중인 원본 웹 |
| 캔버스 | 티켓 생성·관리, 복제 화면과 편집·주석·이미지 맥락, 확정 목표·상태·증빙 보관 |
| 사람 | 티켓에서 의도 구체화, 시안 선택·목표 확정, 구현 지시와 결과 승인 |
| 로컬 에이전트 | 티켓 ID/이름으로 맥락 조회, 대화에서 시안 제안, 같은 티켓의 목표 확정·소스 구현·검증·기록 갱신 |

| 용어 | 의미 |
| --- | --- |
| 티켓 | 생성부터 편집·시안·구현·검토를 묶는 기본 작업 단위. 이름은 변경 가능, ID는 영속 |
| 편집 작업 공간 | 티켓 소유의 원본 복제·현재 편집·주석·추가 설명·선택 범위. 내부 문서 자산이지 별도 제품 목록이 아님 |
| 확정 목표 | 같은 티켓에서 사람이 확정한 이미지·합의 요청·출처/관련 주석. 확정 뒤 불변 |
| 프로젝트 연결 | 티켓이 구현될 저장소의 식별 정보. 로컬 파일 접근 권한이나 MCP 공유 권한 자체는 아님 |

첫 구현은 티켓당 주 편집 화면 하나를 기본으로 한다. 여러 화면 묶음 빌더·담당자/마감/스프린트·버전 트리는 추가하지 않는다. 같은 원본에 대한 서로 다른 작업은 독립 티켓으로 만든다.

### 유지·통합·제거

- 유지: Chromium 독립 앱, 원본 재현 품질, 중첩/다중 선택·이동·삭제·복사·정렬·요소/좌표 주석, 자동 저장·undo/redo, 패널/레이어/확대, 휴지통·복구·파일 백업, MCP 직접 편집, 앱 제공 스킬·설치/업데이트.
- 통합: 문서 목록·편집 화면·확정 티켓을 **통합 티켓 목록과 티켓 작업 공간**으로 정리한다. 캡처/세션 저장 자산은 유지하되 티켓에 귀속한다.
- 대체: ‘편집 후 새 티켓 등록’과 `register_ticket`의 사후 생성 의미를 ‘처음 티켓 생성’과 ‘같은 티켓 목표 확정’으로 나눈다. 뒤에서 별도 전달 등록을 요구하지 않는다.
- 계속 제외: 수동 스냅샷/분기/Git 그래프, 앱 내부 ChatGPT/OAuth/API 키·직접 AI 호출·후보 갤러리/HTML 후보 적용, 별도 복잡한 구현 검토 화면, Chrome 확장. 숨김 메뉴/호환 경로로 재도입하지 않는다.

웹 가져오기에 원본 소스는 필요 없다. 실제 구현은 해당 저장소에 접근하는 에이전트가 수행한다. 캔버스의 생성·조회·목표 확정이나 연결/구독은 자동 구현 명령이 아니다.

## 3. 기본 시나리오

### 티켓 생성부터 직접 편집하기

새 티켓(자동 제목/고정 ID) → 웹사이트 열기·가져오기 → 같은 티켓에서 편집·주석·자동 저장 → 현재 결과를 구현 목표로 확정 → 같은 ID의 구현 지시 → 결과 기록·검토·사람 승인.

원본 웹사이트에서 먼저 가져오기를 시작하는 경로도 편집기 진입 전에 티켓을 만들고 그 티켓에 캡처를 연결한다. 빈 티켓·가져오기 실패는 복구 가능한 준비 중 상태로 남긴다. 다른 티켓의 편집 상태를 재활용해 오염시키지 않는다.

### 이미지 시안을 탐색하기

티켓에서 대상·주석 준비 → ‘CC-12 시안 3개 보여줘’ → 에이전트가 현재 편집·주석·필요 스크롤 상세 조회 → 같은 대화에서 시안 제안/비교/수정/선택 → 선택 이미지를 **같은 CC-12의 목표로 확정** → 별도의 구현 지시·검토.

선택하지 않은 후보를 앱에 모두 보관하거나 이미지에서 편집 가능한 HTML을 자동 생성하지 않는다. 이미지 생성 도구가 없으면 한계를 알리고 현재 편집 목표 경로를 제시한다.

### 대상을 모르거나 편집기를 닫은 경우

‘캔버스 티켓 가져와’ → 현재 저장소와 연결된 허용 프로젝트의 저장 목록 → ‘1번 시안 3개’ 또는 ‘CC-12 보여줘’ → 저장된 편집·주석을 읽고 다음 작업 수행. 열린 편집기 탭을 찾거나 화면 이름/주석을 다시 설명하게 하지 않는다. 같은 이름이 여럿이면 ID·출처·요약을 보여 선택받는다.

### 구현과 검토 이어가기

‘CC-12 구현해’ → 확정 목표와 실제 프로젝트 확인 → 구현 지시 기록·착수 → 반응형 소스 수정·검증 → 구현 이미지·검사 결과로 검토 요청 → 같은 대화에서 승인/수정 의견 → 같은 티켓 상태 갱신. 대상 선택만으로 구현을 시작하지 않는다.

## 4. 기능 요구사항

### CC-FR-01. 실제 화면 가져오기

- 읽기 전용 원본 수집·스크립트 없는 복제본 격리, 이미지/폰트 내장·접근 가능한 iframe DOM 우선 수집을 유지한다. 캡처는 티켓에 귀속한다.
- 전체/현재 화면/영역 가져오기와 원본 비교·자산 재시도를 유지한다. 미로딩·가상화·접힌 내용, 이미지 대체 iframe·부분 수집·누락을 구별한다.
- 전체·대상·주변·관련 스크롤 상세를 이미지로 읽고 viewport/content/offset/coverage·생략 범위를 알린다. 모든 요소를 단일 이미지로 평탄화하지 않는다.
- 기존 #68/#73 원본 재현 잔여를 전환 완료로 해결 처리하지 않는다.

### CC-FR-02. 티켓 안의 편집·주석

- 모든 변경은 티켓을 소유자로 갖는다. 티켓 없는 문서 편집 경로를 남기지 않는다. 티켓 전환은 저장 flush를 기다리고 실패 시 작업 유실 없이 재시도한다.
- 현재 티켓 전체 편집·요소/좌표 주석·추가 설명을 기본 전달 묶음으로 사용한다. 선택 영역은 시안 맥락을 좁히는 선택 기능이며 주석마다 별도 등록을 요구하지 않는다.
- 기본 선택/중첩/다중 선택·이동·삭제·복사·정렬·편집·undo/redo를 유지한다. 현재 오른쪽 패널은 요청·주석을 모아 보여 준다.
- 같은 원본이라도 다른 티켓의 mutable 편집 상태는 공유하지 않는다. 작업 복제는 새 ID의 준비 중 티켓으로 만들고 편집/주석·출처만 독립 복사하며 확정 목표·구현/검토 기록은 승계하지 않는다.
- 기존 편집이 있는 티켓에 새 캡처를 넣어 편집을 조용히 지우지 않는다. 새 티켓으로 가져오기를 기본 대안으로 제공한다.

### CC-FR-03. 처음부터 만드는 티켓과 목표 확정

- 이미지·주석·확정 목표 없이 준비 중 티켓을 생성할 수 있다. 자동 제목을 제안하고 이름 입력 모달을 강제하지 않는다. 생성부터 영속 canonical ID와 짧은 표시 ID를 부여한다.
- 이름 변경·저장/재실행 뒤 ID를 유지한다. 이름은 중복 가능하며 조회 시 모호성을 처리한다. 프로젝트별 티켓 연결을 명확히 한다.
- 새 티켓은 현재 선택한 프로젝트를 기본으로 사용하며 매번 프로젝트 선택 모달을 요구하지 않는다. 연결되지 않았어도 준비 중 편집은 가능하고, 프로젝트 미연결을 표시한다. 에이전트 조회 범위는 명시적으로 허용한 연결을 따르며 실제 구현 전 저장소를 확인한다. 확정된 목표의 출처/프로젝트는 이후 이름 변경이나 기본 프로젝트 변경으로 조용히 바꾸지 않는다.
- 통합 목록/검색/상태 필터에 준비 중 티켓도 포함한다. ID·이름·프로젝트·출처·상태·주석 수·최근 변경 요약과 대상 작업 공간을 제공한다. 별도 문서/전달 요청 목록을 두지 않는다.
- 목표 확정은 새 티켓 등록이 아니다. 현재 편집 결과+관련 주석 또는 사람이 선택한 이미지와 합의 요청을 같은 ID에 원자적으로 고정한다. `goal_id`·확정 근거 편집 revision·출처/주석을 보관하고 draft에서 queued로 전환한다.
- 현재 편집과 확정 목표를 구별한다. 목표가 없으면 정상 준비 중 상태로 설명하고, 차이가 있으면 ‘확정 목표와 다른 현재 편집’임을 표시한다. 이후 편집·이름 변경·undo·재실행·백업이 목표를 덮어쓰지 않는다.
- 확정 이후 목표 자체 변경은 새 티켓으로 분리한다. 같은 목표 구현 미달은 같은 티켓에 수정 요청한다. 목표 버전/분기 UI를 만들지 않는다.
- 티켓 생성/캡처/목표 확정 실패·재시도는 중복 생성·부분 저장·성공 오표시를 만들지 않는다.

### CC-FR-04. 상태·구현·검토

| 상태 | 의미와 전이 근거 |
| --- | --- |
| 준비 중(draft) | 티켓 생성 후 의도 구체화. 화면이 없거나 시안을 탐색 중이어도 정상. 구현 목표 미확정 |
| 구현 대기(queued) | 같은 티켓의 목표 확정. 같은 목표 수정 요청도 이 상태로 복귀 |
| 작업 중(working) | 사람이 이 티켓의 구현을 지시한 근거를 기록하고 착수 |
| 검토 대기(review) | 고정 목표에 대한 구현 이미지·변경 내용·검증 결과를 기록 |
| 완료(done) | 사람이 실제 결과/조건을 확인해 승인한 기록이 있음 |
| 확인 필요(blocked) | 요구 충돌·진행 장애를 사유와 함께 기록. 목표 확정 여부/직전 상태를 보존 |

- 준비 중에는 구현을 시작하지 않는다. 목표 없이 구현 요청을 받으면 확정할 대상을 안내하며 임의로 선택하지 않는다. blocked 해소도 확정 목표/기존 지시 유무에 맞는 상태로 복귀한다.
- 목록 조회·대상 선택·생성·시안 선택·목표 확정은 구현 승인과 구별한다. 코드/테스트 완료를 사람 승인으로 추정하지 않는다.
- 결과 증빙은 해당 `goal_id`를 참조한다. 현재 편집 이미지·고정 목표·실제 구현 이미지를 구별해 같은 대화에서 검토한다. 픽셀 일치만으로 구현 합격을 자동 판정하지 않는다.

### CC-FR-05. 티켓 ID/이름 중심 MCP

- [MCP·스킬 계약](ticket-first-mcp-skill.md)의 티켓 생성/목록/해석/현재 편집 조회/이미지 맥락/편집/목표 확정/상태 기록을 제공한다. 사후 등록 의미의 `register_ticket`을 생성/확정으로 대체한다.
- ID 또는 프로젝트 안의 이름만으로 현재 편집·주석·관련 스크롤 상세·목표/기록과 다음 행동을 조회한다. 매번 screen_id·열린 탭 선택을 사용자에게 요구하지 않는다.
- 앱 실행 중 저장된 닫힌 티켓도 조회한다. 명시적으로 허용한 프로젝트/티켓 범위만 공개하며 목록·이름 후보·상세·이미지·resource/구독에 같은 범위를 적용한다. 권한 철회/휴지통은 즉시 반영한다.
- 원본 네트워크/스크립트를 실행하지 않고 저장 복제본을 격리 렌더한다. 열린 작업과 닫힌 작업에 동일 저장 큐·CAS를 적용한다. 앱 종료/권한 오류를 실제 데이터 없음으로 표시하지 않는다.
- 이름 중복·짧은 ID 충돌은 후보 선택을 요청하고 최신 티켓을 추정하지 않는다. 현재 저장소 연결이 명확하면 프로젝트를 자동 좁히고, 불명확할 때만 확인한다. 목록은 pagination하며 선택 전 이미지 전체를 반환하지 않는다.
- 편집 revision·티켓/상태 revision·불변 goal_id를 구별한다. 이미지/주석은 같은 revision을 기준으로 반환하고 각 image role·coverage·제약을 명시한다. 쓰기 CAS·고유 operation_id·원자 저장·실패/중복 계약을 유지한다.
- 캡처 문구는 자료이며 지시가 아니다. 실제 원본 웹·로컬 저장소를 MCP가 자동 수정하지 않는다. 토큰·로그인 프로필·무관한 로컬 파일은 공개하지 않는다.

### CC-FR-06. 짧은 명령을 이어주는 스킬

- ‘캔버스 티켓 가져와/편집 가져와’로 목록, 이름/ID로 직접 조회, 직전 목록 번호+행동으로 다음 작업을 처리한다. ID·이름·상태·짧은 내용을 함께 보여 준다.
- 이름은 한 번 해석한 뒤 고정 ID로 유지한다. 번호는 표시 당시 ID에 묶고 재정렬·이름 변경·대화 모호성으로 다른 작업을 고르지 않는다. 최신 revision/권한은 쓰기 전 재조회한다.
- 화면·주석·스크롤 상세 조회 방법을 사용자에게 반복 설명시키지 않는다. 이미 등록된 의도와 조건을 읽고 부족한 결정만 질문한다. 명시적 ID+행동에는 별도 목록/선택 절차를 강제하지 않는다.
- 시안 생성/비교는 대화에서 하고 선택안만 같은 티켓 목표로 확정한다. 현재 결과 직접 확정도 지원한다. 구현 지시·검토 승인·이미지 생성 미지원·앱/권한/저장소 미연결을 구별한다.
- 실제 도구 구현 뒤 원본 SKILL.md·앱 get_agent_guide·ZIP·설치 관리 파일을 같은 계약으로 갱신한다. 새 미구현 도구를 설치 스킬에서 제공한다고 주장하지 않고 개인 파일을 보존한다.

### CC-FR-07. 저장·전환·백업·복구

- 이전의 테스트 자료 초기화 면제는 0.45 전환에 한정한다. 현재 0.45에서 생성한 자료를 다시 삭제할 승인은 없다. 새 전환은 백업·검증된 매핑·재시도/실패 롤백을 제공한다.
- 기존 편집 문서는 독립 준비 중 티켓으로, 기존 확정 티켓은 기존 ID/불변 목표/기록을 유지한 티켓으로 전환한다. 이미 지나간 정확한 편집 상태를 보장할 수 없으면 읽기 가능한 목표 이미지·출처를 보존하고 재가져오기 제한을 명시한다. 현재 편집을 과거 확정 시점이라고 꾸미지 않는다.
- 캡처 자산의 중복을 줄여도 티켓별 mutable 상태를 공유하지 않는다. ID 충돌/중복 전환/저장 실패·불완전 백업은 기존 자료를 덮어쓰지 않는다.
- 티켓 단위 파일 백업/가져오기에 편집·주석·출처·목표·진행/검토 기록을 포함한다. 이름 변경·휴지통·복구·앱 재실행·업데이트에도 ID/자료를 유지한다. 공유 복구는 허용 정책을 명시하고 자동 권한 확대를 하지 않는다.
- 일반 웹 로그인·OS 서명·개인 스킬·설정·연결 비밀을 초기화하거나 티켓 파일/이미지에 포함하지 않는다.

### CC-FR-08. 범위 간소화·일관성

- 제거한 스냅샷/분기·앱 AI 인증/직접 호출·후보·복잡한 별도 검토·Chrome 확장을 재도입하지 않는다. 내부 undo와 불변 목표는 유지한다.
- 모든 편집 진입(새 티켓/웹사이트 직접 가져오기/샘플/앱 디자인 편집/파일 열기)에 티켓 소유권을 적용한다. 코드·숨은 메뉴·MCP·가이드에 티켓 없는 편집/사후 생성의 제품 계약을 남기지 않는다.

### CC-FR-09. 사용 가이드·액션·검증/배포

- README·구현 구조·개념/사용 HTML·실제 캡처·MCP/스킬을 같은 흐름과 용어로 갱신한다. 구현 전 계획과 0.45 설치 사용법을 구별한다.
- 시나리오별 시작/완료 조건을 같게 두고 사용자 액션을 전후 비교한다. 클릭·메뉴 펼치기·링크 이동·앱/대화 왕복·재입력·재확인을 포함한다. 텍스트 입력의 키 수와 요청 제출 횟수는 따로 기록한다.
- 목표: 초기 연결 이후 일반 조회 ‘목록 요청 1회 + 번호와 다음 행동 요청 1회’, 직접 ID/이름+행동은 요청 1회. 원본/프로젝트/이름이 모호한 경우의 필요한 선택은 유지한다. 단축을 위해 오선택·자동 구현·무승인 완료를 만들지 않는다.
- 단계당 목적은 하나로 두고 티켓 등록/목표 확정과 문서/티켓 목록 왕복을 없앤다. 모달을 기본 겹치지 않으며 필요한 보호 확인만 둔다.
- 변경별 웹/통합/SDK 검증 후 고정 Apple 개발 서명으로 설치 앱·관리 스킬을 갱신하고 정상 재실행한다. 설치 갱신은 실제 구현 티켓 이후의 별도 배포 작업이다.
