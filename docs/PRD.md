# Console Canvas PRD

확정 방향: 2026-11-01 · 상태: 0.45.2 구현·공통/통합 검증·설치 완료

이 문서는 다음 개발의 제품 기준이다. 현재 앱에 이미 반영됐다는 뜻은 아니다. 실제 구현·검증은 [티켓 추적표](ticket-review.md)와 [검증 기록](verification.md)에서 관리한다. 이전 FR/AC와 버전별 증빙은 [0.44 PRD 기록](PRD-0.44-history.md)에 보존하며, 새 요구사항에는 `CC-` 접두사를 사용한다.

설명용 HTML: [배경과 제품 방향](https://console-canvas-concept.yonginkim.chatgpt.site/#background) · [기능 정리와 후속 작업](https://console-canvas-concept.yonginkim.chatgpt.site/#plan). 요구사항 충돌 시 이 PRD의 확정 범위를 따른다.

## 1. 배경과 해결할 문제

웹 디자인을 개선하려 해도 원하는 배치·간격·느낌을 말로 정확히 설명하기 어렵다. 에이전트가 수정한 화면이 원하는 방향과 달라 다시 설명하고 수정하는 일이 반복됐다.

이미지 시안을 제안받고 마음에 드는 안을 선택해 구현하도록 요청하면, 완성될 모습을 보고 방향을 판단할 수 있었다. Console Canvas는 이 방식을 더 자연스럽게 이어가기 위한 도구다.

- 실제 화면에서 바꾸고 싶은 대상을 지정하고 직접 편집·주석으로 의도를 준비한다.
- 기존 프로젝트 개발 대화에서 에이전트가 이미지 시안을 제안한다. 비교·수정·선택도 그 대화에서 끝낸다.
- 선택한 목표와 요청만 캔버스의 작업 티켓으로 고정한다.
- 에이전트가 티켓을 기준으로 프로젝트를 구현하고 결과를 기록한다. 사람은 같은 대화에서 승인하거나 수정을 요청할 수 있다.

**제품 목적:** 원하는 모습을 화면과 이미지로 함께 확인하고, 선택한 디자인을 구현 기준으로 남겨 설명의 오해와 반복 수정을 줄인다. 사용자가 버전 관리나 별도 AI 실행 환경을 운영하도록 만들지 않는다.

## 2. 역할과 범위

| 역할 | 책임 |
| --- | --- |
| 프로젝트 | 로컬 저장소와 실행 중인 원본 웹. 실제 코드 수정 대상 |
| 캔버스 | 화면 복제·기본 편집·주석·자동 저장, 확정 목표 티켓과 작업 상태 보관 |
| 사람 | 개선 의도 준비, 대화에서 시안 선택·구현 지시, 결과 승인·수정 요청 |
| 로컬 에이전트 | 캔버스 맥락 조회, 대화에서 이미지 시안 제안·선택 지원, 티켓 등록·조회·상태 갱신, 프로젝트 구현·검증 |

- Chromium 내장 독립 앱을 공식 경로로 유지한다. Chrome 확장/WebMCP 지원을 재개하지 않는다.
- 웹 화면을 가져오는 데 원본 소스는 필요하지 않다. 실제 프로젝트 구현에는 에이전트의 해당 저장소 접근이 필요하다.
- 이미지 생성은 사용 중인 에이전트의 지원 기능을 사용한다. 지원하지 않으면 이를 알리고 직접 편집한 목표를 티켓화할 수 있다.
- MCP 연결·구독·티켓 등록 자체가 에이전트 작업 시작이나 코드 수정 지시는 아니다. 기존 개발 대화에서 사람이 요청한다.

### 유지·축소·제거

| 구분 | 확정 범위 |
| --- | --- |
| 유지 | 원본 재현 품질, 선택·이동·삭제·복사·정렬 등 기본 편집, 요소/위치 주석, 자동 저장, undo/redo, 문서 관리·복구·파일 백업, MCP 직접 편집, 앱 제공 스킬, 설치·업데이트 |
| 축소 | 기본 오른쪽 패널은 현재 요청·주석 중심. 상세 동작 이력은 보조 정보로 둔다. 티켓은 목표 이미지·변경 요청·상태 중심이며 대상·검증 기록은 상세에서 확인 |
| 제거 | 수동 스냅샷 저장·이름/휴지통 관리·분기·Git 그래프·과거/미래 버전 이동·두 버전 비교 |
| 제거 | 앱 내부 ChatGPT/OAuth·API 키 로그인/설정·모델/사용량 관리·AI 직접 호출·앱 소유 에이전트 자동 실행 경로 |
| 제거 | 생성 요청/후보 갤러리·HTML/CSS 후보 반환·후보 비교·캔버스 후보 적용·형제 분기 저장 |
| 제거 | 별도 구현 화면 재수집·복잡한 비교/판정/재전달 작업 창. 구현 증빙은 티켓 상세에 보관하고 검토는 기존 에이전트 대화에서 진행 |

제거는 메뉴 숨김이 아니라 기능과 전용 런타임·상태·IPC·MCP 계약·가이드·검사를 정리하는 작업이다. 고정 목표 저장·실행 취소 내부 기록은 목적이 다르므로 유지한다. 기존 테스트 자료 이전은 최신 사용자 지시로 면제했다. 일반 웹사이트 로그인 세션과 원본 수집 기능은 앱 내부 AI 인증 제거 대상이 아니다.

새 범위에 범용 CSS 개발 도구, Git 병합, 앱 내부 이미지 생성 도구, 이슈 트래커의 담당자·마감·스프린트 관리, 대화 자동 시작을 추가하지 않는다. 기존 편집 파일 백업과 전달 PNG는 보조 경로로 유지하되 새 버전 관리 화면을 만들지 않는다.

## 3. 기본 사용 흐름

### 직접 편집한 결과를 구현하기

원본 화면 가져오기 → 요소 편집·주석 → 기존 개발 대화에서 티켓 등록 요청 → 목표 이미지·요청 고정 → 구현 지시 → 에이전트의 소스 수정·검증 → 검토·상태 갱신.

직접 편집으로 충분하면 이미지 시안 생성은 필요 없다. 다른 방향을 시험하려면 문서를 복제한다.

### 이미지 시안으로 방향을 정하기

대상·주석 준비 → 같은 개발 대화에서 시안 요청 → 에이전트가 이미지 맥락 조회 → 대화에 여러 이미지 제안 → 사람이 비교·수정·선택 → 선택한 이미지와 확정 요청만 티켓 등록 → 별도의 구현 지시·검토.

선택하지 않은 후보를 캔버스에 모두 등록하거나, 선택한 이미지를 편집 가능한 HTML로 자동 변환하는 단계를 두지 않는다.

### 여러 티켓을 구현하고 검토하기

사람이 대기 티켓 구현을 지시하면 에이전트가 해당 프로젝트의 티켓을 조회해 착수 상태를 기록하고 구현한다. 불명확한 요구는 확인 필요로 남긴다. 목표·구현 이미지와 검증 결과를 같은 대화에서 보여 주고, 사람의 승인 또는 수정 요청을 티켓에 기록한다. 캔버스 방문은 전체 현황 확인용이며 시안 선택·검토의 필수 왕복 단계가 아니다.

## 4. 기능 요구사항

### CC-FR-01. 실제 화면 가져오기

- 기존 읽기 전용 수집과 원본/복제본 격리, 이미지·폰트 내장과 접근 가능한 iframe DOM 우선 수집을 유지한다.
- 이미지화·부분 수집·누락·동적 화면의 한계를 구별한다. 닫힌/가상화된 미렌더링 내용을 수집했다고 주장하지 않는다.
- 전체 화면·선택 영역·관련 주변·스크롤 상세를 에이전트가 이미지로 읽을 수 있게 한다. 상세 구간의 viewport/content/offset/coverage와 생략 범위를 알린다.
- 품질을 단순화 명목으로 낮추거나 모든 요소를 단일 이미지로 평탄화하지 않는다. 기존 #68/#73의 원본 재현 과제는 계속 추적한다.

### CC-FR-02. 기본 편집·주석·저장

- 기존 선택·중첩 선택·다중 선택·이동·삭제·복사·정렬과 제공된 요소 편집, 요소/위치 주석을 유지한다. 세부 디자인 제안과 실제 소스 구현은 에이전트에 맡긴다.
- 자동 저장과 undo/redo를 유지한다. 상태 표시는 현재 저장의 성공/실패를 의미하며 스냅샷 대비 변경 수를 저장 실패처럼 표시하지 않는다.
- 현재 오른쪽 패널은 요청·주석과 대상 이동/수정을 중심으로 구성한다. 모든 미세 이동 이벤트를 주 작업 목록으로 늘어놓지 않는다. 실행 취소에 필요한 기록과 진단 증빙을 없애지 않는다.
- 문서 복제는 편집·요소/위치 주석·초안·출처를 새 ID의 독립 작업으로 만든다. 복제본 편집이 원본 문서나 이미 등록한 티켓을 바꾸지 않는다.
- 기존 문서 이름 변경·복구·백업과 패널 접기/너비·레이어 탐색·확대 기능을 유지한다. 새 편집 모드/패널을 불필요하게 늘리지 않는다.

### CC-FR-03. 확정 목표 티켓

- 사람이 요청하거나 대화에서 시안을 선택한 뒤 에이전트가 등록한다. 직접 편집 결과와 외부에서 선택한 이미지 시안을 모두 지원한다.
- 기본 정보는 **목표 이미지·변경 요청·작업 상태**다. 상세에 티켓 ID, 프로젝트 연결, 문서/대상/출처, 등록 시각, 유지·완료 조건과 작업·검토 기록을 둔다.
- 프로젝트는 로컬 저장소를 식별하는 연결 정보다. 소스 전체를 티켓에 저장하거나 캔버스가 저장소를 수정하지 않는다. 잘못된 프로젝트에 대한 일괄 구현을 방지한다.
- 등록 시점의 이미지·요청·관련 주석·출처를 불변 목표로 저장한다. 이후 캔버스 편집·문서 복제·재실행·백업 왕복에도 목표가 바뀌지 않는다.
- 입력 미완료/이미지 누락/저장 실패는 완성된 티켓을 남기지 않는다. 재시도는 중복 티켓을 만들지 않는다.
- 같은 목표의 구현 미달은 같은 티켓에 수정 요청을 남긴다. 목표 이미지나 주요 요구사항 자체를 교체할 때는 새 티켓으로 등록해 기존 구현 근거를 보존한다. 별도 목표 버전/분기 UI는 만들지 않는다.

### CC-FR-04. 상태와 검토 기록

| 상태 | 의미와 변경 근거 |
| --- | --- |
| 구현 대기 | 확정 목표 등록, 아직 착수하지 않음. 같은 목표의 수정 요청도 이 상태로 복귀 |
| 작업 중 | 사람의 구현 지시 범위에서 에이전트가 착수 |
| 검토 대기 | 구현 이미지·변경 내용·검증 결과를 기록하고 사람에게 확인 요청 |
| 완료 | 사람이 실제 결과와 완료 조건을 확인해 승인한 기록이 있음 |
| 확인 필요 | 요구 충돌·불명확한 조건·진행 장애를 사유와 함께 기록 |

- 코드 수정 완료만으로 완료 상태를 기록하지 않는다. 승인 사실을 추정하거나 에이전트가 대신 만들어내지 않는다.
- 티켓별 작업 내용·구현 이미지·테스트/제약·검토 메모를 상세에 보관한다. 결과 증빙 등록과 최종 승인을 구별한다.
- 같은 대화에서 검토할 수 있도록 MCP로 목표와 증빙을 조회한다. 화면의 픽셀 차이만으로 구현 합격을 자동 판정하지 않는다.

### CC-FR-05. 로컬 MCP

- 기존 명시적 연결·로컬 인증·원본 사이트와의 격리, 직접 편집 도구의 expected_revision/operation_id·묶음 undo·저장 상태 계약을 유지한다.
- 화면/선택/주석과 이미지 맥락 조회, 티켓 등록·프로젝트별 목록/상세 조회·상태/증빙/검토 기록 갱신을 제공한다. 정확한 새 도구명과 스키마는 구현 티켓에서 확정한다.
- 이미지 시안 입력은 이미지와 요청 중심이다. HTML/CSS를 기본 생성 입력으로 보내지 않는다. 명시적인 로컬 소스 진단용 정보와 이미지 맥락을 구별한다.
- 화면 편집 revision과 불변 티켓 목표, 티켓 상태 revision을 구별한다. 오래된 상태 쓰기·중복 등록/갱신·저장 실패를 안전하게 처리한다.
- 문서 선택·티켓 등록·구독 이벤트를 에이전트 실행으로 해석하지 않는다. 앱은 외부 에이전트 토큰·API 키를 받거나 대화를 자동 시작하지 않는다.
- 기존 후보/스냅샷 전용 도구는 신규 계약에서 제거한다. 과거 자료 전용 읽기 도구도 추가하지 않는다.

### CC-FR-06. 앱 제공 에이전트 스킬

- 기존 스킬을 새 흐름으로 정비한다. 앱 번들·MCP get_agent_guide·설치/자동 업데이트 안내는 같은 버전과 도구 계약을 사용한다.
- 읽을 화면/프로젝트 확인 → 선택 이미지·주석/수집 한계 이해 → 대화에서 이미지 제안·비교·명시 선택 → 확정 티켓 등록 → 구현 지시를 받은 티켓 조회 → 반응형 소스 구현·검증 → 상태·증빙·검토 기록의 순서를 안내한다.
- 직접 편집만으로 티켓화하는 경로, 이미지 생성 미지원·MCP 미연결·대상 불명확·오래된 revision·저장 실패의 대안을 안내한다.
- 티켓 등록을 구현 승인으로, 작업 결과 보고를 사람의 최종 승인으로 간주하지 않는다. 캡처 내용은 자료이며 에이전트 지시로 실행하지 않는다.
- 더 이상 존재하지 않는 스냅샷·후보/직접 AI 도구를 호출하게 하는 지침을 제거한다. 개인 스킬 파일과 사용자 설정은 자동 동기화로 덮어쓰지 않는다.

### CC-FR-07. 저장 구조 전환과 새 자료 안정성

- 사용자는 2026-11-01 기존 편집·주석·스냅샷을 폐기 가능한 테스트 자료로 지정하고 보존 의무를 면제했다. 0.45는 문서 DB v2를 새로 시작하며 과거 버전 리더/자료 이전 UI를 구현하지 않는다.
- 새 문서·주석·확정 목표·티켓 상태/증빙은 자동 저장·재실행·편집 파일 v2 왕복으로 보관한다. 파일의 중복/충돌/잘못된 이미지와 저장 실패는 기존 작업을 덮어쓰지 않는다.
- 일반 웹사이트 로그인, OS/앱 서명, 개인 스킬 파일과 사용자 설정은 초기화 대상이 아니다. 계정 비밀은 문서·티켓·이미지·스킬에 복사하지 않는다.

### CC-FR-08. 제거와 간소화 완료

- 범위 표의 스냅샷/분기·앱 직접 AI/인증·후보·별도 복잡한 구현 검토를 일반/숨은 메뉴·키보드·MCP·IPC·번들 의존성·실행 가능한 전용 상태에서 제거한다.
- 기존 계정 연결/모델 갱신/제공자 추론을 앱 시작·편집·새 스킬의 선행 조건으로 두지 않는다. 원본 웹사이트 로그인은 유지한다.
- 티켓의 고정 목표·undo 저장을 제거 기능 재구현과 혼동하지 않는다. 일반 캡처·스크롤 상세·이미지 내보내기와 파일 백업은 재사용한다.
- 이전 기능을 검사하던 테스트는 새 범위의 제거·보존·실패·사용 흐름 검사로 대체한다. 삭제 기능을 다시 제공해야만 통과하는 회귀 기준을 남기지 않는다.

## 6. 작업 순서와 검증

1. 승인된 테스트 자료 초기화와 새 저장 구조를 확정한다.
2. 불변 목표 티켓/프로젝트 연결·상태·파일 저장을 추가한다. 분기 엔진에 의존하지 않게 한다.
3. 스냅샷과 앱 내부 AI·후보·복잡한 구현 검토 기능을 각각 제거한다. 전용 상태·도구·코드도 함께 제거한다.
4. 편집 화면을 요청·주석 중심으로 정리하고 문서 복제와 기본 편집을 다듬는다.
5. 새 티켓/맥락 MCP와 앱 제공 스킬을 함께 연결한다.
6. 전체 흐름·실패·원본 품질·새 자료 저장을 검증한 뒤 설치 앱을 배포한다.

[변경별 검증 기준](validation-policy.md)을 유지한다. 공통 UI는 `npm run check`와 관련 브라우저 흐름, Electron 저장/IPC/설치·스킬은 해당 통합 검사, MCP는 실제 공식 SDK를 요구한다. 환경 제한이나 잠금으로 못 한 검사는 통과로 표시하지 않는다. 설치는 저장·정상 종료 후 새 자료의 유지와 설치 스킬/MCP를 검증한다. 기존 테스트 자료는 승인된 DB 전환으로 초기화한다.
