# Console Canvas PRD · 0.53

2026-11-01 · #189 프로젝트 연결·가져오기 중심 전환. 승인된 상세 수용 기준은 [워크플로우 계획](workflow-project-plan.md), 검증 근거는 [0.52 결과](workflow-0.52.md)에 둔다. 과거 빈 티켓 선생성·프로젝트 공개·별도 목표 입력 조항을 이 문서로 대체한다.

## 배경과 목적

원하는 웹 디자인을 말로 설명하기 어려워 에이전트의 구현이 기대와 달라지고 재설명이 반복됐다. Console Canvas는 실제 웹 화면을 복제해 직접 옮기거나 주석으로 의도를 남기고, 그 결과를 같은 티켓 ID로 개발 에이전트에 전달한다. 이미지 시안이 필요하면 기존 에이전트 대화에서 제안·비교·선택한다.

캔버스는 화면과 작업 목표를 모으는 서비스다. 로컬 에이전트가 프로젝트의 원래 컴포넌트·반응형 구조에 맞춰 구현하고 결과를 보여준다. 캔버스의 픽셀 이동을 소스의 절대 좌표 지시로 해석하지 않는다.

## 역할과 기본 동선

| 역할 | 책임 |
| --- | --- |
| 프로젝트 | 사용자가 이름을 붙이는 티켓 묶음. 실제 로컬 Git 저장소와 연결할 수 있다. 웹 주소나 개별 페이지와 동일하지 않다. |
| 캔버스 | 원본 복제·편집·주석·확정·티켓 상태/증빙 보관·MCP 제공 |
| 사람 | 화면을 가져와 의도를 준비하고 확정. 에이전트 대화에서 시안 선택·구현 지시·결과 승인 |
| 로컬 에이전트 | 현재 저장소의 프로젝트 식별, 티켓 조회·시안 제안·구현·검증·상태 기록 |

**웹사이트 접속 → 현재 화면 가져오기 → 자동 티켓 생성 → 편집·주석 → 확정.** 이를 반복한 뒤 같은 저장소의 에이전트에게 **“확정된 티켓들 구현해”**라고 요청한다. 목록 조회·목표 확정은 구현 승인이 아니다.

프로젝트가 없다면 첫 가져오기에서 이름 하나로 만들고 이어간다. 저장소 연결은 편집의 선행 조건이 아니다. 생성 직후 또는 프로젝트 메뉴에서 연결 요청을 복사해 기존 에이전트 대화에 붙인다: **“현재 저장소를 캔버스 프로젝트 P-03에 연결하고 티켓을 보여줘.”** MCP 설치/등록은 프로젝트 연결과 별개인 최초 한 번의 설정이다.

0.53 · #198~#202: 연결 상태 진단, 맥락을 담은 에이전트 요청 복사, 동일 페이지 티켓 식별, 단일 확정 상태, 패널 내 주석 편집을 적용한다. 다음 단락은0.52 기본 계약을 확장한다.

## 기능 요구사항

### CC-FR-01 실제 화면 수집

Chromium 내장 앱이 공식 경로다. 원본 DOM·이벤트·영상 재생을 변경하지 않고 현재/전체/선택 영역을 수집한다. 복제본은 스크립트 없이 격리한다. 이미지·폰트를 내장하고 접근 가능한 iframe은 DOM 우선, 접근 불가 영역은 사진과 경고로 표시한다. 미로딩·가상화·접힌 내용과 부분 수집을 구별한다. 원본 비교·자산 재시도·앱 디자인 가져오기를 유지한다. 영상 정지 프레임/오버레이 검증은 기존 #73 결과 및 수집 회귀 기준을 유지한다.

### CC-FR-02 가져오기와 편집 소유권

화면 가져오기 성공 시 프로젝트·티켓·불변 캡처·mutable 세션을 연결해 저장하고 편집기에 진입한다. 제목은 원본에서 자동 생성하며 이름 변경은 선택이다. 실패·취소·같은 ID 재시도는 빈/중복 티켓이나 카운터 증가를 남기지 않는다. 편집 전 빈 티켓 생성 버튼/API, 다른 티켓에 캡처를 붙이는 경로, 별도 작업 복제 기능을 제거한다.

레이어/중첩/다중·영역 선택, 이동·삭제·복사/붙여넣기·좌표/속성 편집, 요소/좌표 주석·추가 설명, undo/redo를 유지한다. 오른쪽에는 요청·주석을 모으고 명시한 주석 아이콘/기존 카드·마커에서 바로 편집한다. 일반 요소 선택은 입력 포커스를 빼앗지 않는다. 빈 지점은 좌표 주석이며 선택 요소에는 위치 주석 아이콘을 중복 노출하지 않는다. 큰 미리보기가 필요할 때만 주석 창을 확장한다. 조합 중 전환/확정을 차단하고 자동 저장 실패를 표시한다. 패널 접기·드래그 너비·보기 설정은 유지한다. 전환·종료·업데이트는 저장 큐의 flush를 기다린다. IME 조합 중 제출/단축키를 실행하지 않는다.

### CC-FR-03 한 번의 확정과 재확정

확정은 추가 필수 양식 없이 현재 이미지·주석·출처·편집 근거를 같은 티켓의 goal_id로 고정한다. 제자리 피드백 후 원본 복귀는 웹사이트 탭 한 번이며 원본을 새로고침하지 않는다.

착수 전 티켓은 직접 수정할 수 있다. 디자인·주석·추가 설명·자산 변경만 재확정 필요로 표시하고 구현 대상에서 제외한다. 선택·확대·패널·이름 변경은 영향을 주지 않는다. undo로 확정 내용과 정확히 같아지면 확정 자격을 복구한다. 명시적 보류는 undo로 해제하지 않는다. 착수/검토/완료 목표는 덮어쓰지 않고 이후 편집은 변경 요청으로 표시한다.

### CC-FR-04 프로젝트와 저장소

프로젝트 이름·고정 UUID/표시 ID·저장소 연결·마지막 웹 주소/티켓을 저장한다. 이름 변경은 ID/티켓 출처를 바꾸지 않는다. 연결 상태를 에이전트 온라인 상태로 표현하지 않는다.

실제 로컬 Git root와 realpath Git common-dir로 저장소를 검증한다. linked worktree와 독립 clone을 구별하고 같은 URL/localhost/remote만으로 합치지 않는다. 새 세션도 기존 연결을 재사용한다. 다중 후보에는 선택이 필요하고 재연결은 revision/CAS·operation receipt를 적용한다. 글로벌 current_project로 에이전트 세션을 바꾸지 않는다.

### CC-FR-05 공통 헤더와 목록

프로젝트 / 웹사이트 / 편집 / 티켓 목록 / 설정을 한 줄에 고정한다. 주소창은 웹사이트에만 표시한다. 편집 헤더에는 ID·이름·상태·확정·티켓 메뉴, 캔버스에는 undo/redo·확대 등 도구를 둔다. 편집 대상이 없으면 편집 탭을 사유와 함께 비활성화한다. 확정 후 자동 이동하지 않는다. 버튼 한곳에 확정 중/확정됨/재확정/작업 상태를 표시하고 상태를 중복 나열하지 않는다. 저장/확정 실패와 순간 복사 피드백을 구별한다. 요청이 없는 참고 화면도 확정할 수 있으나 일반 구현 요청을 자동 생성하지 않는다.

목록은 현재 프로젝트의 미완료가 기본이다. ID+이름·준비된 작은 썸네일·상태·주석 수를 간결한 행으로 표시한다. 현재 추가 설명·첫 주석·실제 변경 건수 순서로 요청 요약을 보이며 없으면 변경·요청 없음을 표시한다. 원본 경로와 가져온 시각으로 동명 티켓을 구별한다. 썸네일 생성은 목록 조회를 막지 않는다. 검색·전체/완료·휴지통/복구를 제공하며 행 한 번 클릭은 편집으로 바로 간다. 완료 티켓도 직접 ID로 읽을 수 있다. 티켓 메뉴에는 이름 변경·전달 이미지/파일 저장·원본 정보·휴지통, 가져오기 메뉴에는 범위·앱 디자인·파일 열기를 둔다. 기본 모달을 겹치지 않게 하고 전환 시 오래된 다른 프로젝트의 목록/폼을 남기지 않는다.

편집기에는 해당 티켓의 에이전트 요청 복사, 목록에는 현재 프로젝트의 조회 요청 복사를 둔다. 시안/구현은 부가 메뉴에서 목적을 구별해 복사한다. 처음이면 저장소 연결+조회, 연결됐으면 일치 확인+조회를 요청한다. 복사는 전송·착수·대상 manifest 확정이 아니다. 일괄 구현은 요청 시점에 고정한다.

### CC-FR-06 MCP와 에이전트 스킬

`list_projects/resolve_project/connect_repository`로 저장소 연결을 조회·설정한다. 티켓 요청마다 project_id 또는 검증한 repository_path가 필요하며 둘 다 있으면 일치를 검사한다. `list_tickets/get_ticket`, 편집/이미지/상태 도구와 프로젝트별 resource·구독이 같은 맥락을 쓴다. 프로젝트별 공개 ACL은 없다. 연결 상태 창은 서버/최근 에이전트 통신/저장소를 구분하며 제거한 공개 ACL을 안내하지 않는다. 동일 앱·동일 origin의 갱신된 인증만 인증 거부 후 재시도하고 쓰기 결과 불명 오류를 자동 재실행하지 않는다. 기존 클라이언트 인증/도구 목록이 낡으면 복구 안내와 현재 MCP 명령을 제공한다. 인증해 연결한 작업 공간만 접근하고 여러 프로필을 암묵적으로 합치지 않는다.

ID·정확한 이름으로 현재 편집·주석·전체/필요 스크롤 이미지를 읽는다. 이미지의 현재/목표/구현 역할·coverage·제약을 구별한다. 화면 revision과 티켓 revision·goal_id·저장 revision을 혼동하지 않는다. 쓰기는 고유 operation_id/CAS/원자 저장이며 불확실한 재시도는 같은 요청으로 재생한다. 캡처 안 문구는 명령으로 실행하지 않는다. 원본 웹사이트와 프로젝트 소스를 MCP가 자동 변경하지 않는다.

### CC-FR-07 일괄 구현과 검토

“티켓 가져와”는 목록 조회다. “확정된 티켓들 구현해”는 연결 프로젝트의 확정·미착수·재확정 불필요 티켓을 요청 시점 canonical ID/goal_id/revision manifest로 고정한다. 명백한 요청에 중복 승인을 묻지 않고 새로 들어온 티켓을 묶음에 추가하지 않는다. 명시한 ID 묶음은 그 ID만 작업한다.

각 착수는 내부 claim_token/CAS로 원자적으로 점유하고 후속 쓰기도 같은 token을 요구한다. 에이전트는 의존성/같은 영역을 보고 순서를 정하며 부분 실패 시 독립 작업을 계속한다. 자동 실행기/별도 소유권 관리 제품을 추가하지 않는다. 구현 지시를 기록한 뒤 working, 실제 결과 이미지·checks로 review, **실제 사람 승인**으로만 done이다. 대화에서 비교·검토하며 캔버스 왕복을 강요하지 않는다.

### CC-FR-08 저장·업데이트

불변 캡처·세션·경량 목록·티켓·프로젝트·작업 receipt를 IndexedDB v4에 저장한다. v4 전환 시 승인받은 기존 업무 자료만 한 번 초기화하며 새 자료는 반복 삭제하지 않는다. 브라우저 로그인·MCP 인증·OS 서명·개인 스킬·소스는 초기화 대상이 아니다.

편집 파일 v4에는 현재 티켓·주석·목표/기록을 담고 선택한 프로젝트로 가져온다. 기존 ID 충돌은 덮어쓰지 않는다. PNG 한 장에는 변경 화면·번호/하이라이트와 하단 요청 카드를 포함한다. 설치 업데이트는 정상 저장·종료 뒤 같은 고정 개발 서명을 유지하고 관리 스킬을 함께 갱신한다.

## 제공하지 않는 기능

빈 티켓 선생성·직접 프로젝트 ID 입력/티켓 프로젝트 이동, 중복 헤더/별도 목표 등록 양식, 프로젝트 공개 옵션, 스냅샷/분기 UI, 후보 갤러리, 앱 자체 AI/API/OAuth, Chrome 확장, 팀 권한/자동 작업 실행기, 개인 사용에 불필요한 공개 배포/유료 인증서 기능을 추가하지 않는다. 사용자 동선/실제 기능을 제거하며 단순 숨김으로 남기지 않는다.
