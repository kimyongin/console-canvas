# 남은 품질·OS 검증 · 0.51.3

2026-11-01. #7·#73 후속. 개인 사용 범위와 기존 고정 Apple Development 서명을 유지한다. 이번 실행에서 새로 확인한 결과와 실제 OS 미검증을 구분한다.

## 조합 입력 수정

조합 문자열이 입력될 때 주석의 자동 저장 타이머가 동작하고, Esc/단축키가 편집창을 닫을 수 있는 결함을 발견했다. 주석은 compositionstart에서 대기 저장을 취소하고 compositionend 이후 확정 문자를 저장한다. 공통 대화상자는 조합 상태·isComposing·legacy229를 확인하며 조합 중 Esc/Enter가 앱의 닫기/제출 명령으로 전파되지 않게 한다. 목록 이름 변경·검색·속성·전역 단축키도 같은 판정을 사용한다.

Chromium 회귀는 조합 중 Esc·Cmd+Enter·229·조합 플래그 없는 Esc, 750ms 동안 미확정 문자열의 기존 주석 덮어쓰기 방지, 확정 후 자동 저장, 일반 Esc의 정상 닫기를 검사한다. panels는 34개 통과다. 합성 CompositionEvent 검사를 실제 OS IME 성공으로 표시하지 않는다.

## 실제 파일 권한 오류

새 임시 폴더에 기존 내보내기 파일을 만들고 폴더를 0500으로 제한했다. 제품 파일 저장 함수를 실행하면 실제 파일 시스템이 EACCES를 반환한다. 기존 파일의 바이트와 폴더의 파일 목록이 유지되고 임시 파일이 남지 않았다. 권한을 0700으로 복구하고 같은 요청을 재시도하면 원자 교체가 성공했다. 이 검사는 OS 오류를 모킹하지 않지만 파일 선택 대화상자의 경로 반환만 대체한다. 실제 OS 대화상자 안에서 거절·복구한 결과와는 구별한다.

## 영상 프레임과 사진의 시점 맞추기

원본 VIDEO에서 사진 전후의 실제 디코딩 프레임을 짧게 읽고, 실제 촬영된 사진의 해당 영상 구역과 비교해 가장 가까운 원시 프레임을 복제본에 쓴다. 전체 문서 사진에는 현재 화면 바깥의 영상도 포함한다. 일부만 보이는 영상은 보이는 교집합을 비교하며 object-fit/object-position을 반영한다. 후보 비교는 64×64이며 아래 최종 수치는 모든 비교 픽셀의 RGB16 검사다.

- 영상 하나당 최대 8개 후보, 하나당 4MP·전체 후보 예산 40MP. 촬영 전 150ms·후 65ms의 유한 수집이며 콜백·디코딩 비트맵·선택 프레임은 종료/실패 경로에서 해제한다.
- 원본 pause/play/currentTime/DOM/스타일/업무 이벤트를 변경하지 않는다. 오버레이 텍스트·버튼·그라데이션을 영상에 굽지 않고 HTML 편집 대상으로 유지한다. 전체 페이지 평탄화·도메인별 분기·검사 마스크·허용오차 확대를 쓰지 않았다.
- 캔버스 읽기 불가·한도·지원하지 않는 변형/복잡한 object-position 등은 기존 원시 프레임 수집으로 폴백한다. 모든 영상의 완전 동일·오프라인/DRM 지원을 보장하지 않는다. 영상은 실시간 재생 대신 정지 이미지이며 기존 경고를 유지한다.
- captureReport.videoFrameMatching의 captures/matched는 촬영·선택 작업 횟수다. 고유 영상 수나 화면 일치율로 해석하지 않는다.

### 실패 실험과 원인

CDP LayerTree는 VIDEO에 연결된 레이어에서도 `Layer does not draw content`/`Layer does not produce picture`를 반환했다. 영상 GPU 텍스처를 Skia picture처럼 직접 추출하는 경로는 채택하지 않았다. 초기 후보 선택은 현재 뷰포트 안의 영상만 읽어 초기79.435/문서91.347%였다. 부분 노출을 처리한 뒤 초기99.733/문서93.521%였으나, 화면 아래 다른 영상은 여전히 다른 시점이었다. 촬영 범위 전체의 영상을 수집하도록 수정한 뒤 아래 결과를 얻었다. 실패 사진/코드/원시 로그도 ignored local/remaining-0513에 보존한다.

## 설치·원래 작업 복귀

정상 종료 후 보관한 전체 앱·사용자 프로필·개인 스킬 백업을 유지한 채 최종0.51.3을 같은 고정 Apple Development 신원으로 빌드했다. 공식 Electron SHA-256, strict 코드 서명과 DMG 체크섬을 확인하고 설치 앱을 교체했다. 공개 배포·공증이나 새 인증서 발급은 하지 않았다.

원래 사용자 프로필/포트8849로 재실행했고 AX에서 마지막 CC-6 화면과 자동 저장 상태를 확인했다. 설치 앱의 실제 MCP 경로를 공식 SDK로 연결해0.51.3과 기존 CC-5의 전체 티켓 SHA-256 동일·고정 목표/주석/이미지3개 유지를 확인했다. 소스/설치 앱의 수집기·편집 번들·manifest·package·라이선스, 앱 agent-guide와 자동 갱신된 개인 스킬·런타임 ZIP도 바이트가 같았다. 앱 본체 프로세스는1개다. 이 복귀/연결 확인을 실제 OS IME·저장창 실패 검증 완료로 확대하지 않는다.

스킬 공식 quick_validate는 처음에 시스템 Python의 yaml 의존성 부재로 실행되지 않았다. ignored local/의 전용 가상환경에 검증기 의존성만 설치한 뒤 통과했다. 앱 런타임 의존성은 추가하지 않았다. 최종 스킬 안내를 넣은 뒤 패키징 검사2개도 다시 통과했다.
