# 선택 영역의 AI 시안 생성·비교·선택 계획

> 2026-11-01: 이 문서는 이전/0.44 구현·조사의 근거입니다. 새 제품 범위와 제거·이전 계획은 [현재 PRD](PRD.md)·[티켓 추적표](ticket-review.md)를 따릅니다. 아래 FR/AC는 [0.44 PRD 기록](PRD-0.44-history.md)의 식별자이며 신규 범위로 다시 구현하지 않습니다.

**0.21 MVP와 후속 계획이다.** 공통 HTML/CSS 패치·✨ 요청·후보 비교/선택·형제 분기·API 키 어댑터·19개 MCP 도구와 최신 stdio 발견/구독을 구현했다. 실제 계정 추론·ChatGPT OAuth·모델 이미지 재검토/반복 보정·기존 대화 자동 시작은 남아 있다. [구현/검증 범위](ai-variants-0.21.md)를 따른다. 사용자 설치 앱·스킬·자료는 별도 배포 범위다.

## 목표와 확정한 사용자 경험

**편집 경로 보완:** 사용자 직접 편집·AI 직접 호출(현재 코드/프롬프트→수정 코드/패치)·외부 로컬 에이전트 MCP를 제공한다. API 키/ChatGPT 로그인은 AI 직접 호출의 인증 선택이다. 공통 저장/패치/후보 엔진을 사용하며 상세 계약·자격/제한은 [세 경로·인증 계획](editing-paths-plan.md)을 따른다.

사용자는 세부 디자인 속성을 직접 조절하는 대신 요소나 영역을 선택해 에이전트에게 개선을 맡긴다. 에이전트는 복제본의 실제 HTML·CSS를 수정하고 화면을 확인해 여러 시안을 만든다. **사용자가 후보 중 하나를 선택해야 현재 작업에 적용한다.** 앞서 검토한 클릭 즉시 단일 안을 적용하는 흐름은 기본 방식으로 채택하지 않는다.

여기서 **샘플링**은 같은 기준에서 서로 다른 UI 후보를 생성하는 제품 동작이다. MCP 프로토콜의 Sampling 기능과 별개이며, 최신 규격에서 deprecated인 Sampling은 신규 핵심 경로에서 제외한다. 실행 방식은 별도 조사한다. 처음에는 세 후보로 검증하되 세 개를 제품의 고정 한도로 정하지 않는다.

1. 실제 웹 화면을 소스 없이 가져온다. 복제본은 스크립트가 실행되지 않는 iframe의 HTML·CSS로 표시한다.
2. 요소·여러 요소·영역을 선택하면 기존 작업 도구 옆에 **✨ 시안 만들기**가 나타난다. 요청 범위와 배치에 필요한 주변 구조를 확인할 수 있다.
3. 설명 없이 생성할 수 있으며 주석/선택적 자유 텍스트가 있으면 그 의도를 우선한다. 예: “검색 조건을 한 줄로 정리하고 검색 버튼을 오른쪽에 배치해 주세요.”
4. AI 직접 호출을 고르면 API로 실행하고, 외부 에이전트를 고르면 지원하는 연결로 실행한다. 외부 에이전트 자동 연결 미지원이면 같은 자리에서 요청 문장을 복사해 에이전트 채팅에 한 번 붙여넣는다. 이후 조회·편집·후보 반환은 MCP로 처리한다.
5. 에이전트는 같은 기준에서 간격/밀도/시각적 위계/배치가 의미 있게 다른 후보를 만들고, 후보마다 실제 렌더 이미지를 확인·보정한다. 업무 필드와 의미는 요청 없이 임의로 제거하지 않는다.
6. 갤러리에서 기준 화면과 후보별 이름·개선 방향·차이 요약·실제 미리보기를 본다. 확대/같은 배율 비교와 준비된 후보의 선택을 제공한다.
7. **이 시안 적용**을 누르면 현재 작업을 보호한 뒤 선택한 후보를 한 undo 단계로 적용한다. 다른 후보는 보존하며 선택한 안에서 추가 편집/재생성할 수 있다.
8. 확정한 결과의 개발 전달은 기존처럼 번호 하이라이트와 하단 요청 카드가 있는 **PNG 한 장**을 사용한다. 후보 비교 화면·내부 요청 제어와 최종 전달을 구별한다.

## 자동 실행이 안 될 때의 대안

| 경로 | 사용자가 하는 일 | 조건과 한계 | 우선순위 |
| --- | --- | --- | --- |
| 요청 복사·붙여넣기 + MCP | ✨ → 요청 복사 → 에이전트 채팅에 붙여넣기 | 기존 MCP 연결/공개가 필요하다. 에이전트는 요청 ID로 기준·주석·HTML/CSS를 읽고 같은 갤러리에 후보를 반환한다. 복잡한 프롬프트·코드 복사는 요구하지 않는다. | 필수 MVP 대안 |
| 먼저 대기하도록 요청 | 한 번 “캔버스의 시안 요청을 기다려 처리해 줘”라고 요청한 뒤 ✨ | 대기형 도구/구독/주기적 조회의 실제 클라이언트 지원·시간 제한·재연결이 검증돼야 한다. 종료된 대화를 깨우는 수단으로 설명하지 않는다. | 선택적 실험 |
| 에이전트 앱의 작업 시작 API | 지원하는 연결을 최초 설정한 뒤 ✨ | 공식 외부 API/인증·대상 세션·취소 지원을 확인한다. 현재 채팅에 자동 삽입할 수 있다고 추정하지 않는다. | 자동화 후보 |
| 캔버스 소유 CLI·SDK 실행 | 에이전트 실행 경로와 인증을 설정한 뒤 ✨ | 별도 세션/프로세스·추가 설치/인증·모델 사용 조건을 명시한다. 이미 열린 데스크톱 대화의 재사용을 보장하지 않는다. | 앞 경로가 안 될 때 선택 |
| API와 MCP 모두 사용하지 않음 | 기존 PNG를 첨부해 여러 시안 이미지를 요청·수동 비교 | 이미지 비교는 가능하지만 HTML·CSS 후보가 자동으로 캔버스에 돌아오는 흐름은 제공하지 못한다. 편집 가능한 후보 생성 완료로 표시하지 않는다. | 제한된 대안 |

수동 요청 문장 예시는 다음과 같다. 실제 ID/문구는 구현 계약에서 확정한다.

> 콘솔 캔버스 요청 R…를 조회해 같은 기준의 시안 3개를 만들고 후보로 등록해 줘. 현재 작업에는 적용하지 마.

이 문장은 연결된 작업의 제어 정보다. 토큰·원본 HTML·로그인 정보·긴 CSS를 넣지 않으며 사용자에게 별도 텍스트 파일을 첨부하도록 요구하지 않는다. AI 실행에는 사용자가 선택한 에이전트의 접근/사용 조건이 적용된다. 기본 수동 편집·이미지 전달에 AI 계정을 필수화하지 않는다.

## 조사 관문과 초기 근거

**최신 조사 기준:** 공식 latest가 가리키는 **2026-07-28**을 사용한다. Sampling은 deprecated이므로 신규 핵심 경로에 채택하지 않는다. 구독은 `subscriptions/listen`, 서버 요청은 MRTR 기준으로 확인한다. 아래 2025년 문헌 인용은 과거 호환 참고로만 남긴다. [최신 조사와 설치본 실험](agent-trigger-research.md)을 따른다.

첫 실험은 **버튼 요청 생성 → 알림/수동 전달 → 실제 에이전트의 요청 조회 → 기존 MCP 주석 쓰기**다. 이때 알림 도착, 요청 조회, 모델의 새 작업 시작, 편집 결과를 각각 기록한다. 다음 실험에서 같은 기준의 HTML·CSS 후보 세 개를 만들고 이미지 확인·비교·선택 적용·undo·스냅샷 복원까지 검증한다.

| 조사 질문 | 실제 확인할 것 |
| --- | --- |
| MCP 푸시가 가능한가? | 협상 버전·capabilities·구독/알림·연결 수명과 실제 수신. 로컬 MCP와 확장 WebMCP→공식 Chrome MCP를 나눠 확인 |
| 알림으로 작업이 시작되는가? | 클라이언트 이벤트 처리, idle/작업 중/연결 종료에서 모델 실행·실패/취소. 알림만 표시되면 자동 실행 미지원으로 기록 |
| Sampling을 쓸 수 있는가? | 클라이언트의 지원과 협상 프로토콜의 요청 맥락 제약. 여러 후보 생성이라는 제품 샘플링과 구별 |
| 외부 시작/재개 경로가 있는가? | 실제 공식 API/CLI/SDK, 계정·세션·권한·상시 실행 조건. 앱 내부 도구와 외부 제품 API를 구분 |
| 연결이 없을 때도 사용 가능한가? | 짧은 요청 한 번 전달 → 요청 ID 조회 → 여러 후보 반환 → 사용자 선택. 자동 연결 성공의 선행 조건으로 두지 않음 |

2026-10-26의 초기 문헌 조사에서 확인한 범위는 다음과 같다. **실제 에이전트 실행이나 계정 접근을 검증한 결과가 아니다.**

- 공식 MCP SDK 문서는 서버→클라이언트 변경 알림을 설명한다. 구독/전달 방식은 프로토콜 버전에 따라 다르므로 알림을 지원한다는 사실만으로 AI 새 작업 시작을 단정하지 않는다. [공식 알림 문서](https://github.com/modelcontextprotocol/typescript-sdk/blob/main/docs/servers/notifications.md)
- 2025-11-25 Sampling 문서는 클라이언트 모델 생성을 요청하는 기능과 capability 선언을 설명한다. 적용 버전·클라이언트 지원과 요청 수명 제약을 조사해야 한다. [해당 버전 규격](https://modelcontextprotocol.io/specification/2025-11-25/client/sampling)
- 공식 OpenAI 문서에는 Codex app-server의 `thread/resume`, `turn/start`, 진행 이벤트와 `turn/interrupt`가 있다. 이 근거는 제어 가능한 app-server 통합의 후보를 제시한다. 현재 열린 Codex 데스크톱 채팅에 임의의 외부 앱이 메시지를 넣을 수 있다는 증거는 아니다. [OpenAI Docs: App Server](https://learn.chatgpt.com/docs/app-server)
- 공식 OpenAI 안내는 CLI exec·SDK·app-server의 용도를 구별한다. 어떤 경로를 써도 모델 접근과 관리 서비스의 조건은 별개다. [OpenAI Docs: Codex as a platform](https://developers.openai.com/blog/codex-as-a-platform)

첫 조사 티켓은 알림·자동 실행이 불가하다는 결과로도 완료할 수 있다. 실패/미지원 증빙, 수동 경로 재현, 실행 경로 결정이 있어야 하며 기능 구현 티켓은 별도로 완료한다. 개인 대화에 메시지를 보내거나 사용자 문서를 시험 편집하지 않는다.

## 편집·시안·저장 계약

- **같은 기준:** 요청 시 주석 초안·추가 설명을 반영한 기준 상태를 고정한다. 미저장 편집도 포함한다. 필요하면 기준 앵커를 보관하되 현재 활성 버전/미리보기/선택/revision/undo와 현재 가지의 편집 이력 위치를 바꾸지 않는다.
- **독립 후보:** A에서 요청했다면 A→후보1, A→후보2, A→후보3이다. 후보1→2→3으로 누적하거나 생성 순서대로 부모를 연결하지 않는다. 후보의 패치·요약·상태·이력은 후보 가지에 귀속한다.
- **편집 범위:** 문구·크기·색상·폰트·테두리·배경·간격·flex/grid·요소 추가/삭제/재배치를 지원할 공통 패치를 설계한다. 임의 스크립트 실행으로 구현하지 않는다. 선택한 대상과 배치를 담당하는 필요한 부모 범위를 조회·수정하며 변경 범위를 요약한다.
- **일관된 참조:** 원본 캡처는 유지하고 신규 노드/교체/재배치의 안정 ID·원본 locator·복사 참조·부모 관계·주석 연결을 정의한다. 기존 자유 이동 오프셋과 CSS 레이아웃 변경의 충돌을 명시한다.
- **모델과 화면:** DOM만 일시적으로 수정해 끝내지 않는다. 패치를 자동 저장·스냅샷·undo·영구 이력·편집 파일과 연결하며 과거/미래/병렬/휴지통을 보존한다. 현재/저장 버전/후보 이미지에서 같은 결과를 렌더한다.
- **선택 적용:** 미리보기는 읽기 동작이다. 사용자가 고른 후보만 현재 작업을 보호한 뒤 적용하고 한 단계로 취소할 수 있어야 한다. 적용 이후 새 편집의 부모는 실제 선택한 후보이며 다른 후보로 다시 이동할 수 있다.
- **충돌/실패:** 기준 이후 사람이 편집하면 오래된 후보로 자동 덮어쓰지 않는다. 차이를 보여주고 기존 작업을 보호한 명시적 이동이나 최신 기준 재생성을 제공한다. 후보별 원자 적용·중복 방지·취소/늦은 결과·quota 오류를 처리한다. 일부 후보가 실패해도 완성된 후보는 남는다.
- **노출 범위:** 문서 공개/해제와 요청 취소를 준수한다. 생성 요청/후보의 보존과 공개 상태를 구별한다. 자동 업로드·원본 사이트/소스 수정·로그인/전체 프로필 이전을 추가하지 않는다.
