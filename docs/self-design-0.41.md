# Console Canvas 자기 디자인 편집 · 0.41

2026-10-31 · #155 / FR-42·AC-140~141.

상단 **앱 디자인 편집**을 누르거나 앱 메뉴의 같은 항목을 선택한다. 현재 앱의 웹 헤더와 편집기/웹사이트/설정 화면을 새 문서로 가져와 기존 직접 편집·주석·AI·MCP·분기 스냅샷·전달 기능으로 디자인한다. 상단 버튼1액션, 앱 메뉴는 펼치기+항목 선택2액션이며 주소 입력·다른 창/앱 실행이 필요 없다. 모달을 연 상태에서도 native 앱 메뉴로 시작할 수 있다. 기존 문서 메뉴에서 원래 작업을 다시 열 수 있다. 실제 앱 소스/설치본에 시안을 반영하는 것은 개발 후속 작업이다.

## 구현

main이 소유한 셸과 보이는 WebContentsView를 기존 DOM 수집기로 읽고 좌표·클립·ID를 합친다. 사진만 붙이는 기능이 아니며 내부 캔버스도 기존 프레임 수집 경로로 DOM을 유지한다. selector는 원본 것을 보존하고 DOM의 ID/ARIA/로컬 SVG 참조와 편집 ID는 충돌을 피한다. `source.application`과 자체 출처 URL, locator의 `app_surface`로 가져온 버전/화면과 표면을 구별한다. OS 제목 표시줄은 웹 UI에 포함하지 않는다.

일반 사이트의 HTTP/HTTPS 제약은 그대로다. 셸 캡처만 정확한 앱 소유 shell.html 경로를 허용하며 웹사이트·캡처 프레임에 새 preload를 노출하지 않는다. 모달은 네이티브 최상위 표시·계산 스타일·backdrop을 읽어 일반 요소로 재현한다. 원본 UI에서 showModal이나 버튼을 실행하지 않는다.

새 문서를 저장하고 여는 기존 흐름은 이전 주석 초안·추가 설명 저장을 기다린다. 새 receipt 응답은 편집기 mainFrame에서만 받으며 실제 새 문서 열기가 끝난 뒤 성공으로 표시한다. 중복 요청/검토 가져오기 중/화면·창 크기 변경/수집 실패를 구분한다. 성공·실패 메시지와 버튼 재활성화를 유지한다.

큰 자기 복제본에서 발견한 data URL 길이 제한은 PNG 렌더용 격리 세션의 단일 메모리 문서로 해결했다. JavaScript/Node/프레임/연결은 차단하고 CSP를 응답 헤더에도 고정한다. 큰 HTML이 URL/오류 메시지에 들어가지 않는다. 합성 사진은 Blob의 ImageBitmap으로 읽어 원본 셸 리소스 목록을 늘리지 않고 해제한다. 자산 치환도 이미 내장된 data URL을 정규식에 다시 넣지 않는다.

html 바로 아래의 편집 포털도 수집해 내부 캔버스의 고정 레이어를 빠뜨리지 않는다. 문서 전환은 이전 MCP long-poll을 중단하고 새 메타데이터로 다시 연결한다. 비활성 편집 화면에서 Image.decode가 사진 렌더를 기다려 재실행 준비를 막는 문제는 화면 표시와 독립적인 ImageBitmap 디코딩으로 수정했다. 테스트 창의 촬영도 stayHidden/stayAwake를 명시해 검사 때문에 별도 앱 창을 노출하지 않는다.

## 실제 설치 앱·MCP·보존 완료

정상 종료한0.40 앱399개·전체 프로필227개·설치 스킬4개 파일을 지문 대조 백업했다. 공식 Electron45 SHA·같은 고정 Apple Development 신원·strict/deep·DMG 무결성을 확인하고0.41.0을 설치했다. 교체 직후 프로필227개 파일이 같고 빌드/설치 앱401개·런타임131개 해시가 일치했다. 스킬4관리파일 자동 동기화와 실제 SDK/가이드0.41.0도 확인했다. 개인 키/키체인 ACL을 바꾸지 않았다.

실제 상단 버튼으로 현재 편집기를 가져와801요소의 새 자기 편집 문서를 열었다. 레이어에서 원본 snapshot-dropdown 버튼을 선택하자 메뉴 실행 대신 요소 도구 모음이 나타났다. 공식 MCP로 새 문서만 가드해 그 버튼 이동·주석·스냅샷·삭제·undo와 전달 PNG를 확인했다. 마우스로 직접 드래그해 세로33px 이동하는 것을 보고 실제 실행 취소 버튼으로 되돌렸다. 원래 앱의 컨트롤은 계속 동작했다. AI는 기존 공통 경로를 사용하며 이번 자기 복제본에서 추가 유료 추론을 실행한 것은 아니다.

정상 종료 후 저장소 사본 감사에서 기존8문서의 캡처/전체 session·편집·주석·추가 설명·전체 스냅샷/부모/휴지통·메타데이터 지문이 전부 같았다. 기존18스냅샷·현재 주석2개·편집20개와0.40의 실제 ChatGPT3후보/선택 결과를 보존했다. 암호화 계정 파일도 같다. 새 자기 편집 문서에서만2스냅샷·이동/주석이 생겨 전체는9문서·20스냅샷이다.

설치 앱을 다시 실행해801요소와 주석1·선택 버전 v2·이동한 버튼을 확인했다. SDK에서 새 문서와 스냅샷 ID/부모·주석 수가 같았고, 추가 키체인 승인 창 없이 설치 앱1개만 실행 중이다. 복구 백업을 둔 직접 앱 교체이며 업데이트 버튼 자기 교체·Developer ID/공증 검증은 이번 범위가 아니다.
