# Console Canvas 사용자 액션 검토

기준 버전 0.26.1 · 기준 커밋 dbe341f · 검토일 2026-10-30

후속 구현·검증은 [0.27.0 구현 기록](action-ux-0.27.md)을 따른다. 기준/설계 기록을 소급하여 실측 결과로 바꾸지 않는다.

기본 이동·삭제·스냅샷 저장은 이미 짧다. 가장 큰 절감 지점은 새 대상에 반복 주석을 작성하는 과정과 구현 결과를 다시 가져와 요청별로 판정하는 과정이다. 기존 연속 주석 검토·자동 저장·자동 보관·복구 버튼처럼 이미 액션을 줄인 경로를 우선 활용해야 한다.

최신 개선 판정은 [시나리오별 액션 절감과 UX 보호 검토](user-action-reduction-review-0.26.1.md)를 따른다. 이 문서는 현재 횟수의 기준과 시작 상태를 보존한다. 초기에 제안한 자동 이동/주석창 자동 추종/자동 다운로드 수치는 안전성 검토로 수정했으며 구현 완료가 아니다.

## 범위와 계산 기준

현재 제공 경로를 13개 영역, **121개 목표 시나리오**와 **7개 복합 작업의 조건부 기준 동선**으로 정리했다. PRD FR-01~18·FR-20~31을 대조한다. FR-19의 Chrome 확장/WebMCP는 지원 종료 경로로 제외하고 FR-20의 기존 자료 이동·런타임 준비는 유지한다. 설치·로그인·외부 개발·미지원 인증·모든 오류 조합을 고정 횟수로 완료 가능하다고 간주하지 않는다.

- 클릭, 키보드 명령, 드래그는 각각 1회다. 수정키+클릭과 키 조합은 한 제스처다.
- 한 필드의 완성된 값 입력/교체는 1회다. 글자 수·조합 입력·선택 후 교체의 세부 타건은 세지 않는다. 입력 초점 클릭은 별도 1회이며 자동 초점은 0회다. 이는 원시 클릭/키 로그가 아닌 사용자 조작 모델이다.
- 네이티브 드롭다운 열기+옵션 선택은 2회다. 자동 도구의 selectOption 한 번을 사용자 1회로 세지 않는다.
- 링크로 화면 이동, 탭/문서 전환, 메뉴·하위 메뉴·접힌 영역 펼치기, 뒤로 가기, 검색·필터·페이지 이동, 스크롤, 모달 열기·닫기는 모두 실제 수행 횟수만큼 센다. 스크롤/탐색/재시도는 필요한 추가 제스처 수 q를 붙이며 미측정 q를0으로 간주하지 않는다. 상태 읽기·시각적 비교·의사결정·로딩·AI 추론은 클릭 0회여도 시간 비용이 있으므로 제거된 작업으로 해석하지 않는다.
- 앱 내 횟수와 OS·외부 대화 액션을 분리한다. OS 기본 저장은 확인 1회, 보이는 파일 선택·열기는 2회로 가정한다. 대화 전달은 전환·초점·붙여넣기·보내기 4회다. 실제 환경에서는 달라진다.
- 목표별 표는 명시된 시작 상태에서 필요한 기준 동선을 센다. 실제 사용에서는 해당 시작 상태에 도달하는 조작도 전부 더한다. 최단 가능 경로와 사용자가 실제로 거친 경로는 별도로 기록한다. 모달에서 계속 편집해야 하는 경우 닫기까지 포함한다. 선택만으로 완료되는 미리보기와 실제 버전 적용을 같은 목표로 섞지 않는다.
- 서로 다른 목표의 횟수를 모두 합쳐 제품의 총 액션 수로 만들지 않는다. 여러 목표가 선행 선택·열린 창·자동 초점을 공유하므로 복합 작업은 U01~U07처럼 별도로 합성하고, 아직 확인하지 않은 진입·탐색 조작은 N으로 남겨 전체 횟수를 미확정으로 표시한다.

## 진입과 탐색까지 포함하는 전체 집계

**전체 액션 = 진입·준비 + 화면 탐색·메뉴 펼침 + 입력·편집 + 확인·복귀 + OS·외부 전달**이다. 화면 이동을 만드는 클릭은 링크든 버튼이든1회이고, 메뉴를 열고 하위 메뉴를 열고 항목을 고르면 각각1회다. 필요한 확인/닫기/복귀도 제외하지 않는다. 자동 저장·자동 초점·자동 복귀처럼 시스템이 수행하는 동작만 사용자 액션0회다.

앞서 제시한21회·44회 등은 원본 상태/대상이 준비되었다는 조건의 **부분합**이다. 링크 이동·메뉴 펼침 등 진입·탐색이 남아 있는 실제 전체 횟수로 확정하지 않는다. 시작 상태를 정하고 실제 순서를 기록하기 전에는 `부분합 + 미측정 진입·탐색`이라고 표시한다. 외부 사이트에 필요한 조작도 제품 조작과 구분해 표시하되 전체 사용자 비용에서는 빼지 않는다.

| 실제 사용한 동선 예 | 분해 | 횟수 |
| --- | --- | ---: |
| 문서 메뉴를 통해 원본 주소 열기 | 문서 메뉴1 → 원본 정보 펼치기1 → 원본 주소 링크 클릭1 | 3 |
| 저장 문서 검색 후 전환 | 문서 메뉴1 → 저장된 화면 전환1 → 자동 초점된 검색란 입력1 → 문서 선택1 | 4 |
| 스냅샷 검색 후 실제 버전으로 이동 | 스냅샷 목록1 → 검색란 초점1 → 검색어 입력1 → 결과 선택1 → 이 버전으로 이동1 | 5 |
| 앱 제공 스킬 설치 | 앱 설정1 → 에이전트 연결 열기1 → 스킬 설치1 | 3 |

예를 들어 저장 문서 목록을 찾으려고 메뉴를 한번 잘못 열었다 닫고 올바른 메뉴를 열었다면, 잘못된 열기·닫기도 실제 경로에 더한다. 원본 화면에서 메뉴 펼침1·링크 이동2·필터 드롭다운 선택2회가 필요했다면 총5회를 추가한다. 이5회는 계산 예시이며 특정 사이트에서 실제 측정한 결과가 아니다. 반대로 원본이 이미 원하는 상태라 웹사이트 탭1회로 충분했다면 불필요하게 원본 정보3회를 강제하지 않는다.

각 시나리오에서는 다음 세 수치를 함께 남긴다.

- **기능 동선:** 시작 조건을 갖춘 상태에서 목적을 달성하는 기준 횟수. 아래121개 목표 표가 이에 해당한다.
- **실제 전체 동선:** 시작 화면부터 진입·링크·메뉴·스크롤·편집·복귀까지 수행한 모든 횟수. 모르면 미측정으로 남긴다.
- **우회 비용:** 같은 시작/완료 상태에서 실제 전체 동선과 검증된 최단 동선의 차이. 탐색 실패를 최단 경로에 섞거나, 미리 준비된 화면을 실제 전체 동선으로 보고하지 않는다.

## 크게 줄일 대상의 판단 기준

일반 편집은 목표당1~2회, 메뉴를 통한 비반복 작업은3~4회를 기준으로 본다. 반복 작업은 항목당3회 이상, 다른 문서로 갔다 돌아오는 왕복, 같은 정보를 다시 입력하는 경우를 우선 검토한다. 이 숫자는 이번 검토의 설계 기준이며 보편적인 UX 합격 기준이 아니다. 이름·주석·원하는 시안·반영 여부처럼 사용자가 결정해야 할 정보는 줄이기 위한 생략 대상으로 삼지 않는다.

## 확인 방법

PRD와 현재 UI/명령 코드를 기준으로 한 동선 분석이다. 설치 앱에서 문서 메뉴·문서 목록 자동 초점·스냅샷 목록·전달 화면·전달 중 주석 왕복·AI 작성 화면·설정/업데이트 진입을 읽기 위주로 직접 확인했다. 스냅샷 목록을 별도로 닫지 않고 상단 전달 버튼을 누를 수 있는 것도 확인해 불필요한 닫기를 합산하지 않았다.

모든 목표를 실제로 완료한 사용성 실험이나 시간 측정 결과는 아니다. 사용자 문서 편집·주석 입력·스냅샷 저장/복원·삭제·유료 AI 호출·업데이트 설치는 이번 조사에서 실행하지 않았다. 기존 연결 MCP 조회는 401을 반환해 연결 도구로 검증했다고 표시하지 않는다. 사용자 자료를 바꾸는 완료 동작과 OS/외부 경로는 코드로 산정했다.

## 복합 작업의 조건부 기준 동선과 실제 전체

아래 기준 부분합에는 외부 대화/기본 OS 확인을 포함한다. 전체는 현재에 N, 개선에 N′를 더한다. N은 기준 밖의 문서 진입·원본 링크/메뉴·로그인/필터·요소/그래프 탐색·스크롤·외부 대화 찾기·OS 폴더 탐색이다. 기존 표에 포함된 메뉴 클릭을 중복 합산하지 않으며 미측정 N을0으로 두지 않는다.

기본 개선과 선택적 빠른 경로를 구분한다. 옵션 설정/단축키 발견/대상 지정이 필요하면 전부 센다. 수정 이유·보호 조건·행별 확인은 [최신 검토](user-action-reduction-review-0.26.1.md)를 따른다.

## 목표별 액션 목록

표의 현재 횟수는 명시한 시작 조건 아래의 기능 동선이다. 진입·탐색·복귀가 표 밖에 남으면 이를 더하기 전까지 실제 전체 횟수는 미확정이다. 개선 목표는 제안이며 구현 상태가 아니다. `유지`는 현재 동선의 액션 수를 유지한다는 의미다. `화면+코드`는 실제 화면에서 진입/초점/복귀를 확인했다는 뜻이며 쓰기 완료 테스트를 의미하지 않는다.

| ChatGPT 구독 로그인/OAuth | 지원·제품 자격·실제 추론 검증이 남은 경로다. 미지원 상태를 1회 클릭 완료로 세지 않는다. |
| 캔버스가 연결된 외부 에이전트를 즉시 실행 | 현재 수동 요청 복사·대화 전달이 필요하다. MCP 연결만으로 앱이 새 대화를 시작하거나 자동 실행하는 기능으로 계산하지 않는다. |
| API 실패 자동 재시도 | 현재 키·모델·한도를 확인하고 새 요청을 작성하는 안내다. 같은 기준 재시도 구현 없이 버튼 한 번 성공으로 세지 않는다. 향후 같은 기준·프롬프트를 보존한 재시도를 설계할 수 있다. |
| 자동 저장 오류·인증 오류·접근 불가 | 원인과 권한에 따라 해결이 달라진다. 오류 표시까지의 액션과 성공까지의 액션을 분리한다. 보존·파일 백업·재연결 안내를 단축하되 성공을 보장하지 않는다. |
| 전체 앱 자료 일괄 백업 | 문서별 편집 파일 저장은 제공하지만 전체 문서/휴지통/환경/로그인 세션 일괄 내보내기 UI는 동일 기능이 아니다. G07을 전체 백업 완료로 합산하지 않는다. |

## 절감 우선순위

초기 단축안은 [최신 시나리오별 검토](user-action-reduction-review-0.26.1.md)의 기본/선택 경로와 UX 보호 조건으로 대체했다. 신뢰 상태 정리 → 복구/결과 연결의 왕복 제거 → 판정/명시적 주석 대기열 → 문서/원본 탐색 → 실행 메뉴/설정 → 숙련자 명령 순서를 권장한다. 모든 시나리오를 반드시 더 적은 숫자로 만들지는 않는다.

## 액션을 줄여도 유지할 확인

- 스냅샷 이름 입력과 저장 후 그래프 펼침은 확정 요구다. E01의3회는 유지한다. 목록을 닫고 다시 여는 불필요한 왕복만 피한다.
- 스냅샷 미리보기와 실제 이동, AI 후보 미리보기와 적용은 각각 분리한다. 과거/미저장 작업 자동 보관은0회로 유지한다.
- 자산 복구 미리보기와 적용은 유지한다. 여러 번 실패한 결과를 다시 확인하지 않아도 되게 상태를 누적한다.
- 주석 작성만으로 원본이나 복제본 HTML을 자동 수정하지 않는다. 원본 사이트 업무 이벤트를 실행해 액션을 줄이지 않는다.
- PNG 저장의 OS 확인·외부 AI 전송·과금 실행·업데이트 재시작을 사용자 모르게 실행하는 방식으로 단축하지 않는다.
- 이전 검토에서 발견한 기존 편집2건/이력0건 불일치, 복구 완료/원본 경고 구분, MCP 건강 상태는 클릭 수와 별개로 우선 해결할 신뢰 문제다.

## 후속 검증 기준

개선할 때 이 목록의 시작 상태·완료 상태를 그대로 사용해 변경 전후를 비교한다. 별도 가상 문서에서 U01~U07을 실제 완료하고 앱/OS/외부 액션을 각각 기록한다. 클릭 수 외에 완료 시간·재시도·뒤로 가기·잘못된 대상/버전 선택·저장 상태 이해·이미지 재질문 횟수를 함께 비교한다. 목표 수치는 설계 목표이며 구현/측정 후 갱신한다. 매번 자동 초점/자동 저장만0회인지 확인하고, 링크·메뉴 펼침·하위 메뉴·탭 전환·검색 초점·스크롤·닫기·복귀까지 실제 순서대로 번호를 붙여 N과q를 실측값으로 대체한다. 이번 검토만으로 PRD의 확정 동작이나 완료 티켓을 변경하지 않는다.
