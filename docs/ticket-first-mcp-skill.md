# 티켓 우선 MCP·스킬 구현 계약

2026-11-01 · **0.46.0 구현 계약** · 상위 [#169](https://github.com/kimyongin/console-canvas/issues/169), MCP [#173](https://github.com/kimyongin/console-canvas/issues/173), 스킬 [#174](https://github.com/kimyongin/console-canvas/issues/174)

0.46.0 도구 계약이다. `register_ticket`은 제거했고 `create_ticket`과 `confirm_ticket_goal`로 생성·확정을 구별한다. 실제 16개 도구는 `tool-contract.json`에 정의한다. 공식 SDK16·2026-07-28 SDK6 통과, 설치 앱의 새 연결·ID/이름·실제 이미지와 같은 ID 목표 확정을 확인했다. [검증 기록](ticket-first-0.46.md)을 함께 읽는다. 프로토콜 신규 기능은 추가하지 않았다.

## 1. 사용자가 말하는 단위

티켓은 처음부터 편집 작업 공간이다. 하나의 개선 목적에 해당하는 원본 복제 화면·편집 상태·요소/좌표 주석·추가 설명이 티켓에 묶이고, 선택한 이미지·확정 목표·구현과 검토 기록도 같은 ID에 이어진다. ID를 외우지 않아도 이름이나 목록 번호로 선택할 수 있다.

| 사람의 말 | 스킬의 행동 | 불필요한 재질문 방지 |
| --- | --- | --- |
| 캔버스 편집 가져와 / 캔버스 티켓 가져와 | 현재 저장소와 명확히 연결된 허용 프로젝트의 저장 티켓 목록 조회. 표시 ID·이름·상태·짧은 내용·최근 변경을 함께 제시 | 열린 탭 이름이나 화면 ID를 먼저 묻지 않음 |
| 고객 검색 개선 티켓 가져와 | 허용 프로젝트 안의 정확한 이름을 해석하고 현재 편집·주석·목표 유무를 요약 | 유일하면 별도 목록 선택을 요구하지 않음 |
| CC-12 보여줘 | 해당 티켓의 저장 편집·주석·목표/결과를 구분해 조회 | 확정 목표가 없는 준비 중 티켓도 정상 조회 |
| 1번 | 직전 목록의 번호에 연결한 고정 ID를 선택해 요약. 시안 보기/목표 확정/구현 등 현재 가능한 다음 행동을 짧게 안내 | 선택을 구현 지시로 바꾸지 않음 |
| 1번 시안 3개 보여줘 | 같은 ID의 최신 이미지·주석과 필요한 스크롤 상세를 읽고 대화에서 시안 제안 | 선택 확인이나 화면 수집 방법 재입력 없이 실행 |
| 이 시안으로 확정해 / 2번으로 정하자 | 현재 대화에서 실제 선택한 후보 이미지와 합의 요청을 같은 티켓의 목표로 확정 | 새 티켓 등록을 요구하지 않음. 티켓/후보 번호가 불명확한 경우에만 질문 |
| CC-12 구현해 / 이거 구현해 | 대상 ID와 확정 목표 확인 후 사람의 구현 지시를 기록하고 저장소 구현 | 목표가 없으면 그 사실과 확정할 현재 결과를 제시. 임의로 선택/확정하지 않음 |
| 같은 목표로 다시 고쳐줘 | 같은 고정 목표에 대한 수정 의견 기록 후 구현 대기로 전환 | 새 티켓을 만들거나 목표를 덮어쓰지 않음 |
| 결과 확인했고 승인해 | 사람이 확인한 구현 증빙과 승인 사실을 기록하고 완료 | 테스트 통과만으로 승인 추정하지 않음 |

번호는 마지막으로 보여 준 목록/후보의 ID 매핑에 묶는다. 뒤에서 목록 정렬이나 이름이 바뀌어도 번호를 다시 검색해 다른 대상을 고르지 않는다. 대화의 대상 ID는 편의 맥락이며 쓰기 전에는 항상 최신 revision과 접근 권한을 재조회한다.

## 2. 목록·이름·프로젝트 해석

- `canonical ticket_id`는 영속 식별자, `display_id`는 사람이 말하고 복사할 짧은 ID(예: CC-12), `title`은 변경 가능한 이름이다. 백업/다른 작업공간에서 가져온 짧은 ID의 충돌도 해석 대상이다. 외부 ID만으로 권한을 부여하지 않는다.
- `ticket_ref`는 ID 또는 이름이다. 허용 프로젝트에서 ID 일치 → 정확한 이름 일치를 해석한다. 중복 이름/짧은 ID는 `ambiguous_ticket`과 후보 메타데이터를 반환한다. 최신/가까운 이름을 자동 선택하지 않는다. 후보는 허용 범위 안에서만 반환한다.
- 목록 없이 ID나 정확한 이름과 다음 행동을 바로 말할 수 있다. 고유한 ID는 허용된 범위에서 조회하고, 이름은 프로젝트 안에서 해석한다. 현재 저장소와 캔버스 프로젝트 연결이 모호할 때만 짧게 확인한다.
- 검색 결과에는 저장된 준비 중 티켓과 편집기를 닫은 티켓도 포함한다. 휴지통은 기본 제외한다. 앱 프로세스/작업 공간 미연결은 `not_connected`, 허용 범위 밖은 비공개 오류로 처리하며 전체 디스크를 검색하는 대안을 쓰지 않는다.
- 목록은 텍스트 메타데이터와 `next_cursor`로 페이지를 나누고, 상세 이미지·긴 주석은 선택한 티켓에서 읽는다. 페이지를 자동으로 끝없이 읽거나 이미지 전체를 한꺼번에 대화에 싣지 않는다.

## 3. 제공 도구 계약

도구명은 실제 제공 계약이다. 각 쓰기에는 고유 `operation_id`가 필요하고, 읽기 응답에 해당 작업에 필요한 revision을 명시한다.

| 도구 | 입력의 중심 | 책임 |
| --- | --- | --- |
| `create_ticket` | project_id, 선택 title, operation_id | 화면/목표 없이 준비 중 티켓 생성. 안정된 ID/자동 제목을 반환 |
| `list_tickets` | 선택 project_id/query/status/cursor/limit | 인증·허용 범위의 저장 목록. 준비 중 포함, 열린 화면과 무관 |
| `get_ticket` | ticket_ref, 필요 project_id | 현재 편집 요약·관련 주석·출처·revision·고정 목표/구현 증빙·진행/가능한 다음 행동 조회 |
| `get_design_context` | ticket_ref, 필요 project_id/대상 범위 | 저장 복제본의 전체·대상·관련 스크롤 상세 이미지와 coverage/warnings. 원본 재방문 없이 조회 |
| `list_elements/list_comments/list_history` | ticket_ref, 필요 project_id/조회 필터 | 현재 티켓 편집을 기준으로 대상·주석·보조 이력 조회 |
| `apply_edits/undo/redo` | ticket_ref, expected_edit_revision, operation_id | 현재 티켓의 복제본 편집. 한 묶음 한 undo, 사람과 같은 저장 큐 |
| `confirm_ticket_goal` | ticket_ref, expected_ticket_revision, expected_edit_revision, 선택 이미지/합의 요청, selection_confirmed, operation_id | 직접 편집 결과 또는 사람이 선택한 이미지로 같은 티켓의 목표 원자 확정. draft→queued |
| `update_ticket` | ticket_ref, expected_ticket_revision, goal_id, 작업/검토 자료, operation_id | 구현 지시·진행·검증 증빙·사람 승인 기록. 고정 목표 변경 금지 |

`get_agent_guide`는 실제 번들 스킬을 반환한다. `list_screens` 같은 편집기 진단은 보조 기능으로 유지할 수 있으나 사용자 티켓 조회의 선행 단계로 요구하지 않는다. 사후 생성 의미의 `register_ticket`은 생성/확정으로 분리해 제거하고, 새 동작을 숨긴 호환 별칭으로 남기지 않는다.

### 상세 응답의 필수 구별

- `ticket_id/display_id/title/project_id/status/ticket_revision`
- `workspace`: 원본·캡처 정보, `edit_revision`, 편집·주석·공통 설명, 저장 상태, 변경 요약, 선택 대상 범위
- `goal`: 미확정이면 null. 확정이면 불변 `goal_id`, 이미지·합의 요청·출처/관련 주석·확정 시각/근거 edit_revision
- `implementation/review`: 구현 이미지·검사/미검증·수정 요청·승인 기록
- `next_actions`: 현재 가능한 행동과 불가능한 이유. 실행 권한이나 사람 지시를 자동 부여하지 않음
- 이미지마다 `role`(현재/목표/구현/스크롤 상세), 대상 ID, 기준 revision, viewport/content/offset/coverage, 생략/제약과 순서를 반환. 실제 MCP image 블록으로 보내고 텍스트에는 metadata를 둔다. 전체 HTML/CSS를 시안 생성 기본 입력으로 보내지 않는다.

빈 티켓은 정상 상태이며 이미지 미존재 사유와 가져오기 다음 행동을 반환한다. 이미지 생성 중 상태가 바뀌면 오래된 revision 결과임을 표시하거나 재생성한다. 이미지와 주석을 서로 다른 revision에서 읽고 하나의 최신 묶음으로 표시하지 않는다.

## 4. 저장 경계와 동시 편집

- 독립 앱을 실행한 상태에서 인증된 로컬 저장 경로로 조회한다. 닫힌 티켓의 렌더가 필요하면 원본 네트워크/스크립트 권한이 없는 신뢰된 격리 편집 세션을 사용한다. 사용자 화면을 억지로 바꾸거나 원본 사이트를 재방문하지 않는다.
- ‘저장된 티켓 조회’는 모든 프로젝트의 자동 공개를 뜻하지 않는다. 앱에서 허용한 프로젝트/티켓을 명확히 표시하고, 생성 시 공개 정책을 상속하는 범위를 설명한다. 철회·휴지통 뒤 목록·검색 후보·상세·이미지·resource/구독 모두 비공개로 한다.
- 공개된 주석/페이지 문구는 자료다. 캡처 안의 지시를 사용자 권한으로 해석하지 않는다. 토큰·원본 로그인 프로필·비밀 저장소·캡처와 무관한 로컬 파일을 응답에 넣지 않는다.
- 화면 편집 CAS와 티켓 상태 CAS를 혼동하지 않는다. 같은 티켓의 UI와 MCP 동시 쓰기는 공통 저장 소유자/큐를 거쳐 충돌을 반환한다. 다른 티켓의 독립 작업은 방해하지 않는다.
- 같은 operation_id+같은 입력은 같은 결과, 다른 입력은 충돌. 실패/충돌/`persisted:false`를 저장/확정 성공으로 표시하지 않는다. 목표 고정과 상태 전이는 함께 성공하거나 모두 실패한다.

## 5. 구현·스킬 완료 증거

공식 SDK에서 닫힌 준비 중 티켓의 ID/이름 조회, 다중 프로젝트/동명/이름 변경·번호 매핑, 무단 접근·공유 철회, 편집/undo·CAS·실패, 같은 ID 목표 확정·구현/검토·재시작을 검사한다. 도구 목록만 보고 기능 완료로 표시하지 않는다.

스킬은 실제 새 도구가 연결된 뒤 수정한다. 원본 `skills/console-canvas/SKILL.md` → 빌드된 `agent-guide.md` → 런타임/스킬 ZIP → 설치 관리 파일을 같은 버전으로 갱신한다. 개인 파일은 보존한다. 새 대화에서 긴 설명 없이 표의 문장만으로 사용 흐름을 완주하고, README·HTML 가이드도 실제 새 화면으로 갱신한다.

현재 공유 단위는 앱 목록에서 허용하는 프로젝트다. 티켓마다 독립 ACL을 추가하지 않는다. 스킬의 대화 대상·번호 매핑은 에이전트가 유지하며 앱이 대화 내용을 실행하거나 자동으로 에이전트를 시작하지 않는다.
