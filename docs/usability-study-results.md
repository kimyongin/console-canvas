## 준비

샘플: [5개 독립 프로젝트](../samples/ux-study/README.md). 대시보드 검색/보고서 저장, 쇼핑 검색/상품 폼, 칸반 상세/저장, 예약 날짜 선택/예약 입력, CMS 제목/미리보기/저장을 브라우저에서 직접 사용했다. 모두390px에서 문서 가로 넘침이 없음을 확인했다. 이 사실을 Console Canvas 복제 품질 통과로 사용하지 않는다. 초기 소스 커밋과 이후 회차 결과는 아래에 누적한다.

사용자 Mac의 AX 조회는 가능하지만 네이티브 포인터는 noWindowsAvailable이다. 사용자에게 잠금 해제를 요청하지 않고 수집 경계(격리 Electron의 실제 DOM/실제 픽셀)와 공통 UI 직접 사용(실제 수집 파일의 일반 파일 가져오기 경로)을 분리한다. native 앱의 직접 수집 버튼을 클릭한 것으로 표시하지 않는다. UI 생성 티켓은 브라우저 별도 저장소에 두고 사용자 앱의 기존 자료는 변경하지 않는다.

## I1 · 분석 대시보드 · 시작 질문

- 실제 개발자가 여러 개선 작업을 모으는 데 ‘편집 화면’과 ‘목표 티켓 목록’을 오가는 구조가 필요한가?
- 현재 티켓을 식별하는 정보가 몇 번 반복되고, 작업을 이어갈 다음 행동이 명확한가?
- 프로젝트와 티켓 이름을 설정하려는 사람이 ‘원본 정보’를 열어야 한다는 것을 알 수 있는가?
- 주석은 빠른 입력 도구인가, 별도 검토/탐색 화면인가? 현재 기능이 꼭 그 자리에 있어야 하는가?

위 질문은 검증할 가설이며 아직 개선을 채택한 결론이 아니다. 첫 회차의 UI/편집5티켓·MCP 구현·검증·설치가 끝나기 전에 I2를 시작하지 않는다.

### I1 결과 · 0.47.0

CC-3~CC-7을 실제 UI로 만들고 배치·중복 제거·입력·모바일·스크롤 목표를 각각 확정했다. SDK로 origin59030 프로젝트를 2개씩 페이지 조회하고 ID/goal_id를 고정해 실제 dashboard 소스를 수정했다. 5개 모두 구현 이미지·검사 결과와 함께 review로 기록했다. 사람 승인/done은 만들지 않았다.

중복 최근 목록/검색과 별도 티켓 이름 모달을 제거했다. 이름·프로젝트는 메뉴의 명시적 저장 폼으로 통합하고 원본 정보 안의 프로젝트 설정과 blur 자동 저장을 없앴다. 반복 제목·PROTOTYPE 배지·중복 주석 카운터를 제거했다. 단일 주석은 탐색 바 없이 입력하고, 목표 확정은 목록 상세를 열지 않고 캔버스로 돌아온다. MCP 범위 설명과 스킬의 묶음 구현 절차를 갱신했다.

각 티켓을 UI로 복제해 이름·기존 주석 수정·목표 확정·캔버스 복귀를 재실행하고 사본은 휴지통으로 보냈다. 새 사본이 원래 구현 묶음에 합류하지 않음을 확인했다. 동일 조건의 이름 변경은4→3동작, 목표 확정 후 복귀는3→2동작이다. raw 기준선109회(성공106), 재실행65회+정리10회는 준비·편집 재사용 조건이 달라 전체 감소율로 비교하지 않는다. 이전 blur 프로젝트 설정은 실제 저장되지 않아 성공으로 세지 않았고 새 명시적 저장은 재열기로 확인했다.

실제 샘플에서 Enter 검색/초기화, 배너 DOM 제거, 390px 지표·액션 줄바꿈, 내부 표 스크롤·sticky 헤더를 확인했다. 수정 후 실제 수집 RGB16 일치99.949%, RGB8 99.937%, 완전 일치99.923%. npm run check와 Electron offscreen 통합(공식 SDK16/최신 SDK6·저장 후 정상 종료/재실행)을 통과했다. 앱/프로필/스킬 백업 후 같은 Apple Development 서명으로 업데이트한다. 네이티브 본문 포인터 검증 제한은 공통 UI 성공으로 대신 주장하지 않는다.

증빙은 ignored local/ux-study/I1의 전후 액션·CC-ID 매핑·SDK inspect/start/review·실제 사진·검사 로그에 있다. 원본 준비 커밋8c30475와 실제 구현 diff를 구별한다.

### 진입에서 발견한 원본 파일 오류

실제 수집1280×1377, RGB16 일치99.938%·RGB8 일치99.923%·완전 일치99.905%, 원본 DOM 무변경을 확인했다. 최초 비교 스크립트는 viewport 사진900px만 참조해 clone1377px와 높이가 달랐다. 전체 사진 타일의 전 픽셀 coverage를 확인해 비교하도록 검사 측을 수정했다. 제품 재현 오류와 구별한다.

IAB의 일반 파일 선택으로 수집된.uiclone을 열자 ‘지원하지 않는 편집 파일’이 됐다. format이 있는 snapshot을 백업으로 처리하는 제품 분기가 원인이다. collector snapshot은 snapshot 경로, backup/알 수 없는 format은 기존 backup 검증 경로로 나눠 회귀를 추가했다. DB 주입/format 삭제로 우회하지 않았다. 파일 선택 도구 호출에 긴 벽시계 경과가 있어 일반 조작 시간의 개선 수치로 사용하지 않는다.

I1 배포: 0.47.0, 가이드 소스 f0aece6bc332bab91e454593ddc66b52421e1e37를 기존 비공개 URL로 발행했다. 새 캡처4장, 390px 넘침 없음·확대/닫기·문장 복사를 직접 확인했다. 설치 앱은 정상 종료/백업/동일 Apple Development 서명 후 재실행했고 실제 AX에서 새 원본 캡션을 확인했다. 남은 I2~I5는 미착수다.

## I2 · 쇼핑 운영 · 0.48.0

근본 질문: 프로젝트를 고른 목록이 왜 다른 프로젝트를 보여주는가? 작은 주석 입력에 반복 설명이 필요한가? 실제 CC-14~18의5유형 목표/주석을 UI로 만들었다. 기준선은 공개 프로젝트가59031인데 타 프로젝트도 섞였다. 프로젝트 선택을 실제 목록 필터로 전환하고 기본을 현재 프로젝트로 좁혔다. 모든 프로젝트는 선택 가능하되 공유 체크박스가 없어 대상을 오해하지 않는다. 조회 필터 변경은 권한 변경이 아니다. 주석 미리보기의 상시 설명과 요청 패널 바닥 사용법 문장을 제거하고 삭제 전 참고만 유지했다.

동일한 목록→티켓→기존 주석→완료 경로를5개 재실행했다. 각4동작, 총20회이며 기준선의 일부 로그는 도구30초 시간 제한으로 소실되어 전체 전후 감소율은 산출하지 않는다. 이후 액션마다 파일로 기록하도록 검사 도구를 보강했다. 프로젝트5행/타 프로젝트5행/모든 프로젝트12행과 공개 범위를 직접 확인했다. 필터·검색으로 대상을 줄일 수 있고 같은 프로젝트에서 티켓마다 검색 재입력을 강제하지 않는다.

실제 shop 소스에서 카드 기준선·이미지 밀도·중복 공개 버튼/안내 제거·Enter 검색/빈 결과·모바일 액션을 구현했다. 390px 문서 너비390/카드1열·등록 폼 저장을 확인했다. SDK pagination과 고정한5ID/goal별 구현 결과를 review로 기록했다. 사람 승인하지 않았다. 브라우저 재연결 비용은 초기 준비로 분리하고 테스트 헬퍼의 checks 배열→문자열 오류를 제품 오류로 세지 않았다. I1 핵심 티켓/주석은 같은 SDK와 목록 전환으로 유지 확인한다.
