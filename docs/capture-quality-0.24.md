# 가져오기 품질 · 0.24.0

2026-10-29 · #62~#66 · FR-01/03/10/11 · AC-61~65

## 구현

- 기본 가져오기에서 각 iframe의 컨텍스트에 수집기를 실행한다. 내장 Chromium은 프레임 트리·OOPIF 세션·실제 소유 요소를 사용하므로 다른 출처·중첩·중복 URL도 구별한다. Chrome은 허용된 프레임 전체를 시도하고 중첩 결과를 합친다. 출처 권한이나 프레임 신원을 확인하지 못하면 원인을 남기고 해당 프레임을 이미지로 보존한다. 추가 사이트 권한을 자동 승인하지 않는다.
- 원본 selector/ID와 `locator.frames`를 유지하고 렌더 ID·SVG 로컬 참조를 이름 공간으로 분리한다. Shadow DOM의 호스트 경로는 `locator.shadows`에 남긴다. 내장 앱은 Inspector로 읽을 수 있는 닫힌 Shadow DOM도 수집한다. 확장이 모든 닫힌 Shadow DOM에 접근한다는 뜻은 아니다.
- 수집 중 프레임 HTML·이미지 로드·폰트·표시 위치/스타일이 바뀌면 오래된 DOM과 다른 시점의 화면을 섞지 않고 그 프레임만 실제 촬영 픽셀로 보존한다. 이 경우 `frame.failure.code`는 `frame_changed_during_capture`다.
- 이미지와 폰트는 내장 데이터로 보존한다. 내장 앱은 캐시와 이미 관찰한 리소스의 Inspector 로더를 사용한다. 확장은 페이지 안의 읽기와 공개 CORS 요청을 사용하며 요청에 쿠키를 추가하지 않는다. 읽지 못한 IMG는 문서에 포함한 스크린샷에서 보완한다. GIF·애니메이션 WebP의 픽셀 폴백은 해당 시점의 PNG로 고정한다. 정적 WebP는 원본 바이트로 내장한다. 구분은 [Google WebP 컨테이너 규격](https://developers.google.com/speed/webp/docs/riff_container)의 애니메이션 플래그를 따른다.
- CSS 배경·스프라이트·마스크를 수집하고 큰 반복 이미지는 CSS 변수로 공유한다. 편집기에서 변수 정의를 복제 문서 루트에 보존하므로 요소 이동·복사 뒤에도 유지한다. 배경 위 문구와 버튼은 독립 DOM으로 남는다. 읽을 수 없는 장식용 빈 요소·의사 요소의 배경/마스크는 해당 요소의 실제 픽셀로 보완하며 문구나 자식을 가진 전체 영역은 평탄화하지 않는다. 외부 image/use 참조 및 마스크·필터·방사형 그라디언트가 있는 SVG는 원래 SVG 식별 정보를 가진 이미지 한 레이어다. 단순 경로·선형 그라디언트는 SVG로 유지한다.
- 긴 프레임은 문서 표면 촬영과 실제 뷰포트 촬영으로 보완한다. 화면 밖 OOPIF는 실제로 스크롤해 그 프레임 영역의 픽셀만 합친다. 큰 페이드가 시작되면 뷰포트 방식으로 다시 촬영하고 겹침으로 고정 헤더 중복을 줄인다. 지연 로딩으로 문서가 늘면 높이를 다시 읽고 필요한 경우 재촬영한다.
- 가져오기 전후의 스크롤을 복원한다. 주소가 바뀌면 새 페이지에 이전 스크롤을 적용하지 않는다. 수집기는 원본 DOM을 쓰지 않으며 업무 버튼을 실행하지 않는다. 코디네이터의 스크롤에 따라 원래 페이지의 지연 로딩은 발생할 수 있다.
- 캔버스 크기는 실제 문서의 크기다. iframe/스크롤 영역에 잘린 자식의 좌표를 문서 크기에 더하지 않는다. DOM 식별 정보는 그대로 보존한다.
- 같은 가져오기 안에서 읽은 리소스는 문서별 메모리 캐시에 재사용한다. Chrome은 최종 DOM을 네트워크 대기 없이 다시 읽고 촬영해 슬라이드/지연 이미지와의 시점 차이를 줄인다. 새 수집기를 주입하면 캐시를 새로 만든다.
- 스크롤 때 배너/헤더 높이가 바뀌면 원본의 안정된 이미지·제목·프레임 위치를 기준으로 타일을 최종 DOM 좌표에 맞춘다. 사진 픽셀은 바꾸지 않으며 `sourceRect`/`layoutShift`로 촬영 위치와 보정을 남긴다. 숨은 메뉴는 고정 헤더로 간주하지 않는다.
- 선택한 부모 안을 클릭하면 내부 요소를 선택한다. 실제 드래그는 기존 부모/묶음 이동을 유지한다. 선택 클릭은 편집·undo를 만들지 않는다.

## 한도와 미지원 조건

프레임 중첩 5단계·32개, 수집 요소/파일 크기와 이미지 예산을 적용한다. 스크린샷은 최대 32개 타일·약 4천만 CSS 픽셀을 기준으로 한다. 준비 스크롤과 Chrome 캡처는 최대 24,000px이며 내장 앱의 문서 표면에는 별도 크기 한도가 있다. 원본에 아직 없는 가상 행·닫힌 다른 페이지의 내용을 생성하지 않는다.

이미지 영역은 가져온 문서/프레임에서 보이는 범위를 기준으로 `full`/`partial`/`unavailable`로 구별한다. `full`은 화면 밖 원본 자산 전체를 확보했다는 뜻이 아니다. 데이터가 없는 픽셀을 확대하거나 회색으로 채워 원본처럼 판정하지 않는다. CORS·인증·CSP·리소스/시간 한도로 읽지 못한 CSS 리소스는 경고에 URL을 남긴다. 이를 오프라인 보존 완료로 안내하지 않는다. 임의 사이트 전체의 완벽한 복제를 보장하는 문서는 아니다.

## 95% 검증 기준

사용자가 지정한 기준은 **원본과 복제 이미지의 일치율 95% 이상**이다. 같은 뷰포트·스크롤·CSS 픽셀 크기를 사용하고 픽셀의 최대 RGB 채널 차이가 16/255 이하인 비율을 계산한다. 기준과 허용 차이는 사이트별로 바꾸지 않으며 원본 이미지·복제 DOM 렌더·차이 PNG·평균 차이를 보존한다. 영역을 가리는 마스크를 사용하지 않는다.

초기 뷰포트와 문서 비교 영역을 각각 검사한다. Chrome은 별도로 촬영한 원본 전체 페이지 PNG가 비교 영역을 포함하면 이를 문서 기준 이미지로 사용한다. 별도 전체 촬영이 불가능하면 원본 타일과 같은 뷰포트에서 복제본을 스크롤해 비교하고 구간별 원본/복제/차이 PNG와 문서 합성본을 남긴다. 동적으로 따로 움직이는 열을 서로 다른 시점의 타일로 합친 결과는 독립 전체 원본과 구별한다. 뷰포트와 문서 합성 영역의 일치율은 각각 95% 이상이어야 하며 세부 구간 수치는 진단으로 기록한다. 자동 비교 영역은 최대 12,000px이며 실제 비교 높이와 전체 문서 높이를 결과에 함께 기록한다. 미촬영 영역·빈 화면·봇 확인/접속 제한 화면을 성공으로 세지 않는다. 수치와 별개로 보이는 IMG/프레임 누락·불완전 캡처도 실패 처리한다. 복제 렌더러의 외부 요청을 차단해 원래 링크 없이 재현되는지도 검사한다.

`node_modules/.bin/electron scripts/verify-capture-quality.cjs`는 실제 제품 수집과 `CanvasScene` 렌더를 사용한다. `CAPTURE_QA_CASES`로 이름/URL 목록, `CAPTURE_QA_OUTPUT`으로 로컬 증빙 폴더를 지정한다. `CAPTURE_QA_REPLAY`는 실제 확장으로 저장한 자료를 재현한다. `experiments/webmcp/run.mjs --product --capture-quality`는 별도 Chrome 프로필·공식 DevTools MCP로 확장 버튼을 실제 실행한다. 캡처·로그인 프로필·사용자 백업은 Git에 넣지 않는다.

## 통합·설치 배포 확인

- 정확한 배포 앱 런타임을 별도 임시 프로필로 검사했다. 공식 MCP SDK 22개·최신 클라이언트 17개(협상 프로토콜 `2026-07-28`), 실제 DOM 수집·sandbox·원본 무변경·정상 종료/재실행·주석/분기/휴지통 보존을 통과했다. `local/final-packaged-sdk-024.log`.
- 별도 Chrome 프로필에서 실제 확장 버튼과 공식 DevTools MCP로 62개 제품 통합 검사를 통과했다. `local/chrome-final-product-024/`.
- 사용자 앱을 저장 확인 후 정상 종료하고 앱·전체 프로필·편집 파일·스킬을 백업했다. 설치 앱을 0.16.1→0.24.0으로 교체·재실행하고 실제 UI의 버전, 기존 364개 요소·편집·스냅샷 3개와 주석이 있는 버전 미리보기를 확인했다. 원본/재실행 후 편집 파일에서 기존 HTML·요소·편집·요소/좌표 주석·추가 설명·이력·스냅샷 ID/부모/상태가 같았다. 새 기능의 빈 기본값과 갱신 시각만 추가/변경됐다. 사용자 문서에는 시험 편집을 적용하지 않았다.
- 앱 시작으로 설치 스킬 4개 관리 파일이 배포 ZIP과 바이트 단위로 같아졌으며 기존 추가 파일은 보존한다. 실제 사용자 설치에는 추가 파일이 없었고 보존 동작은 회귀 검사도 통과했다. 새 공식 SDK 클라이언트로 설치 스킬→실제 앱의 guide 0.24.0·연결 화면·요소·주석·스냅샷 조회를 읽기 전용으로 검증했다. 업데이트 전부터 열린 MCP 세션은 인증 정보가 오래돼 재연결이 필요했다.
- 일반 Chrome의 기존 고정 ID/설치 경로를 유지해 0.23.0→0.24.0을 새로고침했다. 설치 관리자에서 버전 0.24.0을 확인했다. 확장 저장소를 백업하고 삭제/초기화하지 않았다. 사용자 확장 편집 탭 직접 열람은 브라우저 URL 정책이 차단해 우회하지 않았다. 해당 사용자 문서의 재열기 직접 확인은 미검증이며, 별도 프로필의 저장/재열기 검증과 구별한다.
- 공식 Electron 45.0.0 SHA-256 확인·앱 서명·DMG 체크섬 검증을 통과했다. 배포 앱 런타임/스킬은 각각 생성 ZIP과 바이트 단위로 같다. 이번 설치는 백업을 동반한 직접 교체이며 업데이트 버튼의 다운로드/자기 교체 흐름을 새로 검증했다는 뜻은 아니다.

비공개 보존 증빙은 `local/deployment-024-backup/`에 있다. QA 실행기를 잘못 지정한 한 번의 시도에서 최근 문서 포인터가 비워져 백업의 포인터만 복원했다. 당시 원본 IndexedDB 모든 파일의 해시와 존재 여부가 백업과 같음을 확인했고, 올바른 격리 실행기로 SDK 검사를 다시 통과했다. 이후 실제 앱 내보내기 대조로 기존 내용 보존도 확인했다. 이 실패를 성공한 통합 실행으로 세지 않는다.
