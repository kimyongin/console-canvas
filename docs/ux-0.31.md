## 직접 사용

별도 localhost54236·가상 NORTH만 사용했다. 실제 사용자 문서/프로필에는 편집하지 않았다.

- 버튼 주석을 작성하고 전달의 추가 설명을 수정한 직후 ‘구현 결과 확인’을 한 번 클릭해 같은 최신 설명의 검토로 이동했다. 모달은 하나다.
- 큰 목록에 자유 주석을 입력한 채 펼치기→100%를 선택했다. 행/열을 읽을 수 있는 크기로 표시하며 초안과 완료 버튼을 유지했다.
- ‘시안’을 두 번 저장해 v2/v3와 시각으로 구별했다. 전달에서 v2의 목록 요청을 눌러 과거 주석을 직접 열고 수정한 뒤 ‘분기 D’를 저장했다.
- 문서를 최신 번들로 다시 열어 그래프 DOM의 v3와 v4 부모가 모두 v2임을 확인했다. 실제 클릭으로 미래 v3를 적용한 뒤 v4로 돌아왔다. 원래 미래와 새 가지가 남았다.

화면 증빙은 Git 제외 `local/ux-031/comment-preview-100.png`, `branch-D-final.png`다. 자동 검사와 직접 사용의 범위는 구분한다.

## 검증 기록

최종 `npm run check` 종료 코드0: 타입·포맷·번들/스킬 패키징, Python45·Node52·Chromium716+smoke2. 신규58개와 기존658개가 모두 통과했다. 스킬 quick_validate와 PRD의 FR/AC ID 중복·관련 문서 링크도 확인했다. 로그는 Git 제외 `local/ux-031/check-final.log`다. 새 `tests/ux-followup-031`은3/10/30개 혼합 상태, 결과 재선택/실제 변경, 이름 초안의 필터/탭/닫기,12개 동명·긴 동명 버전, 양쪽 비교, 과거 이어 편집/dirty 자동 보관/A→D/미래 이동, 실제 IndexedDB 쓰기 실패·롤백/재시도,720×600 미리보기, 최신 설명 첫 동작/취소/복사 대체/오래된 응답, 편집 파일·IndexedDB 재열기를 검사한다.

기존 developer-workflow의 ‘다른 결과’ 검사는 실제 다른 편집 상태를 저장한 뒤 선택하도록 바꿨다. usability의 저장 버전 검사는 조회 상태 무변경과 명시적 이어 편집 경로를 확인한다. 이름 판독은 새 vN와 실제 이름을 함께 확인한다. 원래 데이터 보존 조건을 제거하지 않았다.

새 검사는 공유된 가상 DB를 사용하는 기존 빈 목록 시나리오 뒤에 실행한다. 격리 Chromium의 파일 저장/클립보드 응답은 mock이며 실제 OS 대화상자/클립보드 사용자 제스처/IME/스크린리더를 검증했다고 보고하지 않는다. 네이티브/설치 잔여는 #7/#27에 유지한다. 화면 필터에서 ‘다음 미검토’는 한 번의 클릭이고 과거 요청의 이어 편집도 요청 버튼 한 번이다. 전체 작업 시간이나 모든 사용자 시나리오의 액션 절감률을 실측했다고 주장하지 않는다.
