# 설치 앱·보호 저장소 검증 · 0.38.3

2026-10-31 · #27/#152/#153. 아래 이전 버전 기록은 당시 결과이며 현재 서명 결론은 이 절을 따른다.

## 반복 승인 원인 정정

0.38.0/0.38.1/0.38.2를 같은 자체 개발 인증서로 서명했다. 서로 다른 CDHash와 같은 certificate-bound designated requirement, 새 빌드의 이전 요구사항 만족을 실제 확인했다. 빌드0.38.2는 OS 승인 대기 없이 완료됐다. 하지만 앱 실행에서 사용자가 ‘Console Canvas Safe Storage’ 접근 창을 다시 확인했다. 사용자는 두 번째 항목은 ‘항상 허용’ 뒤 다시 뜨지 않았다고 별도로 보고했다. 두 번째 항목의 이름은 확인되지 않았으므로 같은 원인/해결로 합치지 않는다.

비밀 값 없이 해당 Safe Storage 한 항목의 접근 정보만 조회했다. partition 목록에는 이전 두 빌드의 cdhash가 있었으며 일반 trusted application은 기존 Electron 개발 실행 경로였다. Apple securityd의 자체 서명→cdhash 분류와 일치한다. 코드 서명 인증서의 사용자 신뢰 검증도 성공했으므로 ‘같은 인증서면 해결’ 판단은 불충분했다. [원인·Apple 근거·정식 서명 후속](development-signing.md). 기존 항목/ACL·비밀을 수정하거나 평문 저장으로 우회하지 않았다.

## 수정과 남은 조건

- 기본 빌드는 준비한 같은 개발 신원을 재사용하며 손상/부재·서명 실패에 자동 ad-hoc 전환하지 않는다. 개인 키/복구 P12/암호는 사용자 전용 비공개 디렉터리에만 유지한다.
- 앱 시작에서 ChatGPT 암호화 probe와 계정 복호화를 지연한다. 일반 편집/MCP는 먼저 시작한다. 계정 확인 시 대기 안내·AI 실행 차단, 실패 뒤 같은 창의 재시도를 제공한다. 거절된 원래 암호화 로그인 파일을 보존한다.
- Apple 개발/Developer ID 인증서가 없는 현재 환경의 자체 서명은 업데이트마다 Safe Storage 승인이 다시 필요할 수 있다. 이 문제가 해결됐다고 보고하거나 #153을 닫지 않는다. 인증서 등록/결제는 자동 진행하지 않는다.
- 실제 계정 로그인·허용 모델과 수정 소스의 실제 완료 후보1개는 확인했다. 설치 UI의 시안3개 생성·비교·적용·그 결과 재실행은 미검증이다. 0.38.2에서 native AX/화면은 시안 창 클릭 뒤 이전 화면을 반환하고 좌표 클릭은 noWindowsAvailable이었다. MCP busy 상태와 달라 성공 증거로 쓰지 않는다.

## 자료 보존

0.38.2 설치 직후 프로필227개 파일이 교체 전과 같았다. 정상 종료 후0.38.3 교체 전 프로필226개 파일·앱을 추가 백업했다. 저장소 사본 감사에서 최초 설치 전의7문서·13스냅샷·현재 주석2개·편집 대상20개 전체 지문이 여전히 동일하다. 새 가상 NORTH QA 문서만 추가됐고 사용자 문서를 테스트 편집하지 않았다.

공식 Electron45 SHA·같은 개발 인증서·strict/deep·DMG 무결성을 확인한0.38.3을 설치했다. 교체 전후 프로필226개 파일이 같고 런타임128개 해시가 일치했다. 새 승인 창 없이 편집기·자동 저장 완료·스냅샷 목록·통합 변경 이력과 연결 상태가 나타났다. 실제 SDK는0.38.3 가이드/서버·QA 문서/스냅샷/요청을 읽었고 busy:false였다. SecurityAgent 프로세스는 없었다. 이는 계정 저장소를 접근하지 않은 일반 시작의 검증이며 ChatGPT 사용 시 무재승인 검증이 아니다.

설치 스킬 자동 동기화0.38.3·관리 파일4개 번들 일치·오류0, 암호화 로그인 파일의 이전 해시 일치를 확인했다. 정상 종료 후 사본 감사에서 기존7문서/13스냅샷/주석2개/편집20개 전체 지문이 같고, QA까지8문서도 교체 전후 같다. 두 번째 정상 실행에서도 새 승인 대기 없이 같은 QA 문서/버전을 복원하고 SDK0.38.3 조회를 통과했다. 설치 앱은1개만 실행 중이다.

완성 앱의 직접 교체이며 업데이트 버튼의 자기 교체 시험은 아니다. 개인 프로필·접근 메타데이터·로그는 Git 제외 local/deployment-037에 보존한다.

# OS 암호화·실제 ChatGPT 호출 수정·설치 앱 갱신 · 0.37.4

2026-10-31 · 설치 전0.34.0 → 설치 후0.37.3 · #27 / #152 · FR-41·AC-138.

## 암호화 실패 원인과 수정

0.36 통합 검사기는 임시 프로필뿐 아니라 `HOME`과 `CODEX_HOME`도 바꾸었다. 이 환경에서 macOS 저장소는 available=true 이후 실제 암호화가 실패했다. 일반 OS 사용자 환경에서 같은 Electron45의 비동기 암호화/복호화는 즉시 및2초 뒤 모두 성공했다. OS 사용자 홈을 유지하고 앱 프로필·브리지·스킬만 분리한 통합 검사도 실제 암호화를 통과했다. 격리 실패를 설치 앱/계정의 실패로 단정하지 않는다.

검사기에서 OS 홈 덮어쓰기를 제거했다. `CONSOLE_CANVAS_SKILL_DIR`가 있으면 해당 경로만 조회/갱신하고 실제 사용자 스킬 루트를 검색하지 않는다. 회귀 검사는 사용자 홈 조회를 실패시키고 다른 설치본이 그대로임을 확인한다. macOS 통합 검사는 실제 보호 저장소 roundtrip 성공을 요구한다. 평문 저장·보안 설정 변경·다른 앱의 토큰 차용은 추가하지 않았다.

0.37.1부터 시작 시 Electron 접근성 지원을 활성화한다. 설치 앱의 WebContentsView 안 편집 도구와 ChatGPT 설정이 네이티브 접근성 트리에 나타남을 확인했고 통합 회귀 검사를 추가했다.

## 실제 호출 결함과 수정

실제 로그인/모델 조회 뒤 첫 생성이 connection_failed로 끝났다. 공통 API 어댑터가 OAuth bearer에도 API 키용1000자 제한을 적용한 결함을 가상3000자 토큰으로 재현했다. OAuth 인증의 토큰 한도를 별도로 분리하고 기본 API 키 제한·개행 거절·비밀 비노출을 유지했다. 실제 서비스→Responses 경로와 API/OAuth 경계 회귀2개를 추가했다. 입력 초과/잘못된 인증은 원인을 구별하는 안전한 오류 코드로 반환한다.

## 실제 계정 검증 상태

설치 앱에서 새 문서→AI 시안→AI API 연결→ChatGPT 로그인·요금제 인증과 로그인 버튼을 확인했다. 자동 조작 도구는 `elementHasNoFrame`/`noWindowsAvailable`을 반환해 로그인 클릭을 완료하지 못했다. OS 잠금으로 단정하지 않으며 사용자에게 로그인·연결 동의를 직접 완료하도록 요청했고 사용자가 완료했다. 설치 앱에서 로그인 완료 계정과 실제 허용 모델 GPT-6.1-Sol을 확인했다. 실제 계정 파일은 OS 암호화 컨테이너이며 파일 권한0600임을 비밀 값을 출력하지 않고 확인했다. 실행 방식 드롭다운은 자동 조작이 반응하지 않아 사용자에게 AI 직접 호출 선택을 요청했다.

0.37.2에서 같은 기준의 요청은 generation_failed로 끝났다. 비밀 비노출 실제 진단은 HTTP200·response.completed를 확인했지만 완료 객체의 output이 비어 있었다. 실제 본문은 output_text.delta/done에 있었다. 0.37.3은 순서별 본문을 모으고 done으로 중복을 제거하되 completed 확인 후에만 후보를 등록한다. 같은 스트림의 수정 전 실패와 수정 후 성공·중단 응답 무등록을 회귀 검사했다. 수정 소스의 실제 ChatGPT 가상 버튼 진단은 입력452/출력139토큰·후보1개·실패0으로 성공했다. 이는 설치 UI의3개 비교/적용 검증과 별도다.

최종0.37.3 앱 시작은 macOS SecurityAgent의 기존 키체인 접근 허용을 기다렸다. 배포는 ad-hoc 서명이며 업데이트로 실행 파일의 서명이 바뀐 상태다. 조작 도구는 SecurityAgent 접근을 안전 정책으로 차단해 사용자에게 OS 보안 창 처리를 요청했다. 키체인 설정/ACL을 우회하거나 보안을 낮추지 않았다. 배포용 안정된 서명과 첫 접근 안내는 공개 배포 조건에서 별도로 확인한다.

**실제 로그인·동의·모델 목록과 수정 소스의 response.completed/후보1개는 확인했다. 설치 UI의 후보3개 비교/선택 적용은 아직 미검증이다.** #152/AC-138은 열어 두며 공개 배포/라이선스 자격도 별도다. 기존 토큰을 읽거나 API 키 과금으로 전환하지 않는다.

원본 프로필·감사 사본·지문·SDK 결과·암호화 probe·실패/성공 검사·빌드/설치 로그는 Git 제외 `local/deployment-037/`에 보관한다. 실제 캡처·개인 정보·토큰은 커밋하지 않는다.

## 0.37.4 실제 모델 CSS 등록 후속

사용자가0.37.3 키체인 허용을 완료한 뒤 설치 앱 About0.37.3·테스트 문서 복원을 확인했다. 같은 실제 요청은 모델 응답 뒤 로컬 후보 등록에서 실패했다. 고정 가상 NORTH 입력(HTML613661자/364요소)을 같은 인증 서비스에 전달한 실제 응답은 HTTP200/response.completed·후보1개·입력214174/출력235토큰이다. 실제 패치의 -webkit-text-fill-color가 기존 속성 이름 검증에 거절되는 것을 격리 DOM으로 재현했다. 같은 캡처의 AI 입력 이미지 생성도 성공했다.

0.37.4는 유효한 vendor CSS 속성을 허용하면서 -moz-binding/behavior·외부 URL/실행 CSS 거절을 유지한다. 실제 패치의 수정 전 거절/수정 후 정상 검증과 Chromium의 안전한 속성/실행 속성 차단을 확인했다. ChatGPT broker는 로컬 후보 등록 실패에도 이미 소비한 사용량·모델·안전한 원인을 유지하고 중복 추론하지 않는다. 전체 check:all은 Python53·Node79·Chromium919+smoke2·SDK25+17·nativeScopes5·실제 OS 보호 저장·정상 재실행을 통과했다. 설치 UI의3개 비교/적용 검증은 계속 진행한다.

키체인 반복 원인은 실제 설치 서명의 designated requirement가 빌드별 cdhash만 포함하는 점과 일치한다. 현재 기기에 유효 코드 서명 인증서는0개다. [Electron 공식 설명](https://github.com/electron/electron/blob/main/docs/api/safe-storage.md)·[Apple DR/Keychain](https://developer.apple.com/library/archive/technotes/tn2206/)을 확인했고, 고정 개발/배포 서명과 대기 UI는 [#153](https://github.com/kimyongin/console-canvas/issues/153)에 계획으로 분리했다. 인증서/개인 키·신뢰/ACL을 임의 생성하거나 변경하지 않았다.
