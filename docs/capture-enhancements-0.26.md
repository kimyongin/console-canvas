# 가져오기 검토·범위·복구 · 0.26.1

0.26.0의 다섯 개선을 유지하고, #79의 선택 영역 확장 후 삭제 전 참고 카드 원점 오류를0.26.1에서 수정했다.0.26.0 게시 자산은 교체하지 않는다. FR-10/31·AC-10/75에 연결한다. 원점100의400×200 영역을 왼쪽으로 넓힌 뒤 삭제한 빨간 요소가 전달 카드에서 사라지는 것을 픽셀로 재현했고, 두 비트맵을 같은 전역 범위로 잘라 실제 빨간 대상이 카드에 남는 회귀를 통과했다. 원본/현재 편집은 변경하지 않는다. 최신 공통 검사 Chromium532개(새 기능24개), Python45·Node44, 패키지 공식 SDK25·최신 SDK17·네이티브5개를 통과했다.


#74~#78은 FR-31·AC-72~76에 연결한다. 기존 #73(IKEA 영상), #68(미시험 페이지 일반화)의 미달을 이번 콘솔 회귀 통과로 종료하지 않는다.

## 제공하는 흐름

1. 웹사이트 헤더에서 현재 보이는 화면(기본), 전체 페이지, 영역 선택을 고른다. 영역 선택은 현재 원본 사진 위에서 드래그·확인/취소한다. 보이는 화면/영역은 전체 문서로 스크롤하지 않는다. 전체 페이지는 기존 준비·타일 촬영 뒤 원위치로 복귀한다.
2. 가져오기 정보에서 누락·부분 수집, 개별 편집 제약, 참고를 따로 읽는다. 원본 사진과 비교는 실제 촬영 타일과 편집 전 복제본/현재 작업의 독립 비교다. 좌우/겹치기·농도·배율·동기 스크롤을 제공한다. 버전 비교의 이전 이름 ‘가져온 원본’은 ‘편집 전 복제본’으로 바꿨다.
3. 원본 사진의 빗금은 미촬영, 촬영 면적은 중복 타일을 제외한 사진 범위다. 여러 타일은 같은 시점이 아닐 수 있다. 사진 없는 문서는 비활성 이유를 보인다. 자동 시각 일치율이나95% 배지를 만들지 않는다.
4. 이미지·폰트 다시 읽기로 관측된 공개 자산을 선택한다. 성공/실패 목록과 독립 미리보기를 확인하고 적용한다. 원본 캡처/사진과 과거 버전은 보존하며 복구가 실행 취소·이력·새 스냅샷·편집 파일에 포함된다.

## 범위·한도

영역은 원본 전역 좌표를 유지한다. 레이아웃 보존을 위한 주변 HTML도 파일에 들어갈 수 있으므로 민감 정보 삭제/보안 분리 기능이 아니다. 범위 밖 요소를 숨기고 캔버스·버전/비교 미리보기·전달 이미지를 자른다. 가져온 요소를 범위 밖으로 이동하면 작업 표시 범위가 확장된다. 원본에 아직 없는 가상 행을 합성하지 않는다. 내장 PNG는 선택 출력8192×16000px·48MP 한도를 적용하며, 긴 원본 문서의 작은 영역은 문서 전체 높이 한도에 잘못 막히지 않도록 분리했다.22,000px 문서의19,000px 위치에서400×200px 영역을 출력해 실제 색상까지 확인했다.

복구는 HTTP(S), 쿠키/인증 없이 최대16개·각900KB·합계1.25MB·각2.5초를 적용한다. PNG/JPEG/GIF/WebP/AVIF·WOFF/WOFF2/TTF/OTF만 바이너리 판독한다. SVG·로그인 자산·수집되지 않은 선언은 복구하지 않는다. 누적 코드 패치2MB 한도도 적용한다. 닫기/문서 교체·리비전 변경 후 늦은 응답은 적용하지 않는다. 저장 오류는 기존 저장 큐·오류 표시·백업 계약을 공유한다. 원본 수집 경고는 역사적 근거로 유지한다.

MCP19개 도구를 유지하고 get_screen의 capture_reference/capture_scope/resource_repairs, capture_status.counts·severity를 추가했다. apply_code_patches의 resource는 관측 참조의 제한된 data URI만 적용하며 네트워크를 호출하지 않는다. revision/operation_id·한 undo 단계·persisted 계약은 유지한다.

## 검증 기록

콘솔 가상 페이지는 열린 필터·편집 창·툴팁, 내부 스크롤·고정 표 머리/열, 전체1000개 중 렌더된20개 가상 행을 포함한다. 사전 지정 구역을 전체 화면 지표와 함께 비교하며 RGB16 기준95%를 적용한다. RGB8/완전 동일과 원본/복제/차이 PNG도 보존한다. 좌표는 이 가상 검사의 진단 구역이며 제품 수집기에 사이트 분기나 제외 마스크를 추가하지 않는다.

| 구역 | RGB16 일치율 |
| --- | ---: |
| 초기 화면 | 99.951875% |
| 문서1800px | 99.973264% |
| 열린 필터 | 99.454470% |
| 고정 표 | 100% |
| 가상 목록 | 100% |
| 열린 편집 창 | 100% |
| 툴팁 | 99.775758% |

원본 HTML·스크롤·업무 클릭 횟수가 수집 전후 같음을 확인했다. 다른 시점/사이트의 완전한 재현을 의미하지 않는다.

별도 네이티브 범위 검사는1100×850 원본에서 scrollY=500 상태의 현재 화면·500×300 영역·전체 문서를 수집한다. PNG가 선택 범위 크기와 같고 원본/중첩 스크롤·HTML·클릭 횟수가 보존되며 오래된 영역 요청은 거절된다. 현재 화면 RGB16=99.687166%, 영역=100%다. 최초 영역94.256667%는 직렬화에서 내부 스크롤 위치가 사라진 오류였다. 비교 iframe과 네이티브 PNG에 스크롤을 복원해 수정했으며 최초 실패 수치와 수정 전 직렬화 방식의 재현 PNG도 로컬 기록에 남겼다.

## 최종 공통·통합 검증

- `npm run check`: 타입/포맷/번들·스킬 패키징, Python45개·Node44개·Chromium532개와 standalone/네이티브 영역 드래그 통과. 새 기능 사용 흐름24개는 실제 편집기 UI에서 사진/겹치기·경고 분류·영역/이미지 크기·원본 비파괴·자산 적용/undo/redo·저장·과거/미래 스냅샷·편집 파일 왕복을 확인한다.
- 공식 Electron45 SHA-256·앱 서명·DMG 무결성 검증 후 배포 앱을 만들었다. **그 번들 안의 runtime**을 `CONSOLE_CANVAS_TEST_APP_ROOT`로 지정해 공식 MCP SDK25개·최신 SDK17개(protocol2026-07-28), 정상 종료/재실행·주석/분기·휴지통/패널/저장 복원을 검증했다. 별도 네이티브 범위/PNG5개도 같은 패키지에 수행했다. 이 자동 통합의 기본 화면은 offscreen 가상 자료이며 아래 실제 사용과 구분한다.
- 기존10개 내장 캡처를 오프라인 재생해 초기 화면/문서 각각95% 이상을 유지했다. 이번에 사이트10개를 새로 방문한 시험이 아니다. 기존 #73의 IKEA 영상 미달과 #68의 신규 페이지 일반화는 열림 유지한다.

## 직접 사용·설치·보존

설치 앱의 별도 테스트 프로필/포트8959에서 가상 콘솔을 열어 현재 화면 가져오기, 실제 원본 사진 좌우/겹치기·농도 증가, 공개 이미지 재읽기·미리보기·명시 적용·실행 취소/다시 실행·이력/자동 저장, ‘자산 복구 A’ 스냅샷 저장·과거/미래 이동을 직접 조작했다. 원본 사진 위 드래그로928×341 구역을 선택해 캔버스로 가져오는 것도 확인했다. 실제 설치 앱의 이 QA 문서에서 공식 SDK로 관측 자산 resource를 적용·undo하고 범위·리비전·resource_repairs를 검증했다. 실제 사용자 문서에는 시험 편집을 적용하지 않았다.

직접 비교 중 원본에서 실패한 IMG의 alt 렌더링을 정상 이미지 상자로 바꾸면 기준선/후속 배치가 달라지는 경우를 발견했다. 원본의 `source_broken` 상태는 외부 주소를 요청하지 않는 inert 오류 이미지로 유지하고 명시 복구 때만 바꾼다. 이를 콘솔 가상 회귀와 네이티브 범위 검증에 포함했다. 원본 사이트/selector별 분기를 추가하지 않았다.

기존 앱을 정상 저장 종료한 뒤 앱0.25.0·전체 사용자 데이터·브리지 상태·기존 스킬과 현재 편집 파일을 백업했다. 최종0.26.1 설치·일반 프로필 재실행에서 기존 문서(b1f345e4…)의364개 요소·3개 스냅샷·기존 편집/스냅샷 대비 변경2건·주석/전체 분기를 복원했다. 전후 편집 파일 전체 비교는 `/createdAt`, `/snapshot/updatedAt`만 다르고 콘텐츠는 같다. 런타임121개 체크섬과 설치된 스킬 관리4개 파일이 배포 자산과 같다. 설치된 스킬 경유 SDK도 서버/가이드0.26.1·문서 연결·새 메타데이터를 읽기 전용으로 확인했다.

최종 앱의 기존 문서에서 새 가져오기 정보·원본 사진 비교를 직접 열었다. 오래된 원본 사진의 촬영 면적77.6%를 빗금과 함께 표시해 사진이 없는 하단을 성공으로 덮지 않았다. 이77.6%는 시각적 일치율이 아니다. 확인 후 기존 편집 화면으로 돌아갔다.

로컬 증빙은 `local/capture-enhancements-026/`, 전체 복구 백업·전후 파일/보존 지문은 `local/deployment-026-backup/`에 둔다. 실제 사용자 데이터·사이트 캡처·로그인 프로필·인증 토큰은 GitHub에 커밋하지 않는다.
