# 0.19.1 디자인 보정

2026-10-25. [#26](https://github.com/kimyongin/console-canvas/issues/26). 드롭다운 화살표 여백 수정 중 실제 화면의 공통 디자인을 함께 점검했다. 사용자 자료의 저장 형식·캡처 DOM·편집 동작은 바꾸지 않는다.

## 반영

- 공통 드롭다운: 네이티브 화살표 대신 같은 12px 아이콘을 오른쪽 10px 안쪽에 둔다. 텍스트 끝 공간 30px로 겹침을 방지하고 네이티브 선택/키보드는 유지한다.
- 폼: 범위/종류·검색/일반 입력을 32px 높이, 7px 모서리·중립 테두리·12px 글자로 맞췄다. 하단 배율은 27px 높이와 72px 너비를 사용한다. 비교/주석/버전 선택도 같은 공통 스타일을 따른다.
- 체크박스: `Input`에서 텍스트 입력용 클래스와 분리했다. 14px 크기·패딩/그림자 없음·보라색 선택 표시. 기존 input/label·키보드·checked/disabled 의미는 유지한다.
- 메뉴/닫기: 문서 메뉴와 기타 작업의 개별 그림자를 없애고 항목 간격·배경 피드백을 정리했다. 삭제 색상과 접근성 이름은 유지하며 닫기 버튼은 28px로 통일했다.
- 변경 이력: 본문과 시각/기준 정보의 대비, 제목·본문 간격과 글줄을 정리했다. 작은 카드 테두리로 대상을 구분하고 타임라인/접힘/필터 구조는 유지한다.
- 하단: 연결·변경 건수·화면 크기는 한 줄로 읽히게 하고 안내 문구가 남는 공간을 사용한다. 좁은 공간에서 필요한 경우 가로 스크롤로 기존 조작을 유지한다.
- 키보드 포커스: 입력·선택의 겹친 두꺼운 강조를 정리하면서 눈에 보이는 포커스를 유지했다. 캡처 iframe 내부의 원본 UI에는 이 스타일을 적용하지 않는다.

## 검증과 배포

CUA 브라우저의 별도 가상 문서에서 범위/종류·배율 선택, 선택 요소만·비교 동기 스크롤 체크, 메뉴/비교 열기와 Esc 닫기, 공통 높이/패딩 계산 스타일을 확인했다. 32px 폼·14px 체크박스·10px 화살표 여백을 실제 렌더에서 확인했다. 낮은 영향의 스타일 변경이므로 구현을 그대로 되풀이하는 CSS 단위 검사는 추가하지 않고 기존 동작 회귀와 실제 화면을 사용한다.

MCP 13개 도구와 스킬 사용법은 유지한다. 새 버전 런타임·가이드·스킬 ZIP·앱/DMG/ZIP을 생성해 확인한다. 자동 검사와 격리 앱 결과는 아래 최종 확인에 기록한다.

최종 확인: 타입·포맷·빌드, Python 39개·Node 27개·실제 Chromium 321개가 통과했다. 최종 앱 번들의 Chromium도 321개 통과했고, 격리 앱의 공식 MCP SDK 22개·네이티브 PNG·스킬 설치/ZIP·정상 종료/재실행과 편집/주석·스냅샷/휴지통·패널 보존을 확인했다. 소스/앱 런타임과 스킬 ZIP 지문이 일치하고 앱 서명/DMG 검증을 통과했다. 표준 `npm run check`는 마지막 네이티브 수집의 `Current display surface not available for capture`로 실패했다. offscreen의 실제 DOM/가상 캡처 성공을 잠긴 사용자 설치 앱의 직접 사용 완료로 바꾸지 않는다.

사용자 설치 앱은 Mac 잠금 때문에 정상 저장·종료를 확인할 수 없어 교체하지 않았다. [AGENTS.md](../AGENTS.md)의 “설치 앱을 교체하기 전 주석 초안·추가 설명까지 저장하고 복구 가능한 백업을 확보한다” 및 “종료·업데이트는 `desktop/lifecycle.cjs`의 같은 저장 응답을 기다린다”를 따른다. 설치 앱 갱신/재실행·설치 스킬 동기화는 미완료이며 실제 사용자 문서에 테스트 편집을 하지 않았다.
