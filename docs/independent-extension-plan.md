# Page Canvas · 앱과 Chrome 확장 독립 실행 계획

2026-11-02 · **승인한 수용 기준과0.57 구현 추적.** 실제 코드·검사·결함 수정·설치 범위는 [검증 기록](extension-0.57.md)을 따른다. 아래 체크리스트는 원래 완료 조건이며 실제 사용자 프로필 설치/승인까지 자동 완료로 간주하지 않는다. [PRD](PRD.md)의 현행 동작을 유지하면서 이 문서의 순서로 확장 지원을 추가한다. 아래 PCX 번호는 개발 항목 키이며 캔버스 사용자가 만드는 CC 티켓과 다르다.

## 목표와 범위

사용자는 **데스크톱 앱 또는 Chrome 확장 하나만** 선택해 같은 가져오기→자동 티켓→편집·주석→확정→로컬 에이전트 작업 흐름을 사용한다. 확장이 Page Canvas 데스크톱 앱을 실행하거나 연결하지 않는다. 앱↔확장 통신·동기화·Native Messaging·전용 로컬 수집 서버를 만들지 않는다.

복제·정제·편집·티켓/목표·저장 트랜잭션·도구 스키마와 검증은 공통 소스다. Electron/CDP, chrome.debugger, 파일·바이너리·렌더·에이전트 연결 같은 환경 경계만 어댑터로 분리한다. **Chrome용 복제 엔진을 따로 만들거나 archive 수집 코드를 복사하지 않는다.** 앱만 고치는 사이트별 수집 분기를 확장에 새로 작성하지 않는다.

```text
내장 Chromium ─ Electron 연결부 ─┐
                               ├─ 공통 복제 엔진 → 공통 편집기·티켓 서비스
Chrome 탭 ───── 확장 연결부 ────┘                     │
                                      실행 환경별 독립 저장·에이전트 연결
```

같은 소스/규칙이라는 뜻이지 두 실행의 데이터베이스나 생성된 번들 전체가 같다는 뜻은 아니다. 양쪽은 서로를 설치·실행·검색하지 않아야 한다. 개발 중 비교 시험용 Node/Electron 사용과 확장 제품의 런타임 의존성을 구별한다.

## 실제 사용 흐름

1. Chrome에서 로그인·검색·스크롤·메뉴 상태를 준비한다.
2. 확장 아이콘에서 **현재 화면 가져오기**를 실행한다. 최근 프로젝트를 간결하게 표시하고 변경할 수 있다. 첫 사용에만 이름 하나로 프로젝트를 만들고 이어간다. 기본 현재 화면, 보조 메뉴 전체/영역을 제공한다.
3. 원본 탭을 유지하고 수집 성공·원자 저장 뒤 기존 확장 편집기 탭을 재사용해 해당 티켓을 연다. 확장 팝업이 닫혀도 이미 시작한 수집을 잃지 않는다. 프로젝트를 매번 재선택하게 하지 않는다.
4. 공통 편집기에서 편집·주석·확정한다. 확정 후 자동 이동하지 않는다. 원본 복귀는 한 번이며 원본 탭이 없어지면 사라졌다고 표시한다. 자동 새로고침/로그인 재현을 하지 않는다.
5. 최초 한 번 Chrome/에이전트 연결을 준비하고 같은 대화에서 **캔버스 티켓 가져와**, **CC-12 시안 3개 보여줘**, **확정된 티켓들 구현해**를 사용한다. ID/이름 해석은 선택한 workspace/project 안에서 수행한다.

설정에는 현재 실행 환경에 맞는 연결·가이드·파일 기능만 둔다. 확장에 앱 서버 시작·키체인·앱 업데이트·OS 스킬 자동 설치 메뉴를 남기지 않는다. 원본 웹사이트에 에이전트 명령을 전달하지 않으며, WebMCP 도구는 신뢰한 캔버스 최상위 문서에서만 등록한다. 캡처 복제 iframe은 계속 스크립트 없는 격리 상태다.

### PCX-00 · 독립 Chrome 확장 지원과 공통 소스 전환

현재0.56.0 내장 앱을 유지하면서 Chrome 확장 하나만으로 가져오기·편집·저장·에이전트 작업을 수행한다. 두 제품의 공통 소스와 다른 실행 환경을 구별하고 아래 여덟 작업을 순서대로 완료한다.

완료 조건:

- [ ] PCX-01~08의 수용 조건과 미검증 범위를 집계한다. 조사·계획을 구현 완료로 표시하지 않는다.
- [ ] Page Canvas 앱/호스트/수집 서버가 없는 환경에서 확장 전체 흐름과 재실행·업데이트 유지를 실제 검증한다.
- [ ] 앱과 확장의 엔진·편집·티켓 소유권이 하나이며 빌드/회귀 검사로 소스 분기를 방지한다.
- [ ] 기존 앱 자료·MCP·서명·설치 경로를 보존한다. 이번 계획은 기존 자료 삭제 승인이 아니다.
- [ ] 정식 확장 지원 표시는 선행 연결 검증·품질·배포 검증 완료 뒤 바꾼다.

### PCX-01 · 공통 복제 엔진을 브라우저에서도 직접 실행

선행: 없음. 현행 desktop/capture-cdp.cjs와 capture.js를 공통 모듈로 정리한다. CommonJS/Buffer·바이너리/스트림·수집 코드 로드와 실행 환경 의존만 분리한다. 알고리즘·자산/프레임/폴백 정책은 공통 모듈에 둔다.

완료 조건:

- [ ] 확장 service worker 등 브라우저 실행부가 실제 공통 엔진을 실행한다. 수집에 Node/Electron/Python/HTTP 릴레이를 사용하지 않는다. 시험 제어용 도구와 제품 의존성을 분리한다.
- [ ] 기존6샘플을 앱/확장 양쪽에서 수집해 요소·프레임·범위·제약과 실제 원본/복제 PNG를 비교한다. Node로 엔진을 실행했던 앞선 실험을 새 성공 근거로 재사용하지 않는다.
- [ ] 같은 엔진 소스와 입력별 어댑터 import graph를 검사한다. 두 빌드의 공통 소스/규칙 fingerprint를 남기되 플랫폼별 번들 전체 해시 일치를 요구하지 않는다.
- [ ] 바이너리/base64·크기 제한·타임아웃 의미를 보존하고 앱 회귀를 통과한다. 확장 CSP를 완화하거나 확장 페이지의 eval/new Function·원격 코드를 허용해 해결하지 않는다. 기존 공통 엔진의 읽기 전용 isolated-world CDP Runtime.evaluate와 이 제한을 혼동하지 않는다.

### PCX-02 · 일반 Chrome의 WebMCP 외부 에이전트 연결 선행 검증

선행: PCX-01. archive의13개 도구/과거 설정을 재사용 완료로 보지 않고 최신 Chrome/API/공식 Chrome MCP의 실제 배포 버전을 고정해 확인한다. 현재 문서는 document.modelContext와 실험 플래그·카테고리 옵션을 설명하므로 API 존재/등록 성공/외부 호출 성공을 구별한다.

완료 조건:

- [ ] 일반 창의 설치된 Chrome에 확장을 로드하고 실제 로컬 MCP 클라이언트/에이전트 경로로 도구 발견→목록 조회→이미지 수신→편집→undo를 실행한다. headless/전용 pipe 브라우저만의 성공으로 대체하지 않는다.
- [ ] 평소 프로필에 연결하는 공식 경로(예: 지원되는 autoConnect)의 실제 호환·승인·필요 설정과 최소 지원 버전을 기록한다. 개인 프로필 시험은 사용자가 허용한 연결만 사용한다.
